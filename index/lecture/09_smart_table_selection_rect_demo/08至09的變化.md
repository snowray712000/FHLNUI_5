# 08 → 09 的變化

## 一、核心改動：解耦重構

| 面向 | 08 | 09 |
|------|----|----|
| 架構 | 所有邏輯集中於一個 JS 檔 | `TableSelector`（狀態機）＋ 主程式（listeners） |
| 責任邊界 | 模糊，pointer 狀態、UI 更新、copy 混在一起 | 清晰：TableSelector 只繪圖＋消化 pointer 事件 |
| 擴充方式 | 必須修改同一個 JS 檔 | 只需新增 listener，不碰 TableSelector |

---

## 二、TableSelector 發出的事件

| 事件 | 時機 | detail |
|------|------|--------|
| `selectionstart` | pointerdown 命中有效 td | 無 |
| `selectiondrag` | 第一次跨 cell | 無 |
| `selectioncommit` | pointerup 選取確認 | `{ isTouch, x, y, mode, startRow, startCol, endRow, endCol }` |
| `selectioncancel` | pointercancel | 無 |

payload 使用 row/col index，listener 不依賴 DOM ref。

---

## 三、業務規則歸屬

「電腦 single 模式不自動跳選單」移至 listener 端：

```js
// 08（在 pointerup handler 裡）：
if (currentMode && (isTouch || currentMode !== 'single')) {
  showCtxMenuForCopy(e.clientX, e.clientY);
}

// 09（在獨立的 selectioncommit listener 裡）：
sel.addEventListener('selectioncommit', ({ detail }) => {
  if (detail.isTouch || detail.mode !== 'single') {
    showCtxMenu(detail.x, detail.y);
  }
});
```

`TableSelector` 告知事實，不決定後果。

---

## 四、主程式 listeners 一覽

| listener | 職責 |
|----------|------|
| `selectionstart` | 重置狀態面板 |
| `selectiondrag` | 顯示「拖曳中…」提示 |
| `selectioncommit` #1 | 更新 mode badge 與 status detail |
| `selectioncommit` #2 | 判斷是否跳出 context menu（業務規則） |
| `selectioncancel` | 重置狀態面板 |

同一事件可綁多個 listener，各自獨立。

## 五、檔案結構對比

```
08/
  08.html
  08.css
  CtxMenu.js
  08.js          ← 所有責任混在一起

09/
  09.html
  09.css
  CtxMenu.js
  TableSelector.js   ← 新增：選取狀態機
  09.js              ← 薄：只 new TableSelector + bind listeners
```

---

## 六、行為與 08 完全相同

- 電腦拖曳跨 cell → 矩形 / col 選取 → 選單自動跳出
- 電腦 single → 原生選字，不跳選單
- 平板任何選取 → 整格 / 矩形 highlight → 選單自動跳出
- Ctrl+C、複製按鈕皆可用
- 點到 `a / button / [data-action]` 不進入選取流程
