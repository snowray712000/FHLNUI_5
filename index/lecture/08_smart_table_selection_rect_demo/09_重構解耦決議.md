# 09 重構：解耦決議

日期：2026-03-28

---

## 一、問題背景

08 版本的 table 選取邏輯已功能完整，但所有責任集中在單一 JS 檔案中：

- pointer 事件的狀態機（`hasCrossed`, `startCell`, `pointerType`…）
- 選取結果的計算（col / row / single 判定）
- UI 反應（context menu、status badge 更新）
- 複製邏輯（`buildCopyData`, `performCopy`）

這使得「加新功能」只能往同一個檔案塞，責任邊界模糊。

---

## 二、核心想法：事件化解耦

引入 **Observer / EventEmitter 模式**。

Table 的角色只有兩件事：
1. **繪圖**（highlight、cursor、`cross-sel` class）
2. **消化選取狀態機**（pointer 事件的複雜流程）

選取結果確定後，Table 發出一個語意化事件 `selectioncommit`，帶著乾淨的資訊。後面的人只需要知道「選了什麼」，不需要知道「怎麼選到的」。

Table 是一個**訊號轉換器**：
```
原始 DOM pointer events  →  TableSelector  →  selectioncommit 事件
```

---

## 三、事件 payload 設計

`selectioncommit` 攜帶的 `detail`：

| 欄位 | 型別 | 說明 |
|------|------|------|
| `isTouch` | `boolean` | `true` = 平板（touch），`false` = 電腦（mouse） |
| `x` | `number` | `clientX`，供 context menu 定位 |
| `y` | `number` | `clientY`，供 context menu 定位 |
| `mode` | `'single' \| 'col' \| 'row'` | 選取模式 |
| `startRow` | `number` | 選取起始列 index |
| `startCol` | `number` | 選取起始欄 index |
| `endRow` | `number` | 選取結束列 index |
| `endCol` | `number` | 選取結束欄 index |

**payload 用 index 而非 DOM 元素**，讓 listener 不依賴 table DOM 結構。

---

## 四、業務規則的責任歸屬（決議）

08 版本有一條業務規則：
> 電腦 single 模式不自動跳出 context menu；其餘情況（平板 single、任何跨格）才自動跳出。

這條規則**由 listener 端判斷**，不由 `TableSelector` 決定。

```js
sel.addEventListener('selectioncommit', ({ detail }) => {
  if (detail.isTouch || detail.mode !== 'single') {
    showMenu(detail.x, detail.y);
  }
});
```

**理由**：「要不要跳選單」是應用層的 UI 政策，不是選取行為本身的一部分。`TableSelector` 負責告知事實，不負責決定後果。

---

## 五、helper class 方案

瀏覽器原生 `EventTarget` 即可勝任，不需要自己實作 EventEmitter。

```js
class TableSelector extends EventTarget {
  constructor(tableEl) {
    super();
    this._table = tableEl;
    this._bindEvents();
  }

  _bindEvents() {
    this._table.addEventListener('pointerdown', e => this._onDown(e));
    this._table.addEventListener('pointermove', e => this._onMove(e));
    document.addEventListener('pointerup',     e => this._onUp(e));
    document.addEventListener('pointercancel', e => this._onCancel(e));
  }

  _onUp(e) {
    // 消化完複雜狀態後...
    this.dispatchEvent(new CustomEvent('selectioncommit', {
      detail: { isTouch, x, y, mode, startRow, startCol, endRow, endCol }
    }));
  }
}
```

使用端：

```js
const sel = new TableSelector(tableEl);

sel.addEventListener('selectioncommit', ({ detail }) => {
  // copy logic
});

sel.addEventListener('selectioncommit', ({ detail }) => {
  // status display
});

sel.addEventListener('selectioncommit', ({ detail }) => {
  // 未來新功能，不修改 TableSelector
});
```

`TableSelector` 可複用於任何 table，不與特定 UI 綁定。

---

## 六、決議摘要

| 項目 | 決議 |
|------|------|
| 解耦方式 | Observer 模式，`TableSelector extends EventTarget` |
| 事件名稱 | `selectioncommit` |
| payload 格式 | index（非 DOM ref），含 `isTouch`, `x/y`, `mode`, `startRow/Col`, `endRow/Col` |
| 業務規則歸屬 | listener 端，不在 TableSelector 內 |
| EventEmitter 實作 | 直接繼承瀏覽器原生 `EventTarget` |
| 可複用性 | TableSelector 不依賴任何特定 UI，可用於多個 table |

---

## 七、下一步

09 版本按上述決議實作：
1. 抽出 `TableSelector.js`（繼承 `EventTarget`）
2. 主程式改為只 `new TableSelector(tableEl)` 並 bind listeners
3. copy logic、status display、context menu 各自成為獨立的 listener
