# 1. 功能名稱與用語

- 功能：串珠，英文代稱 TSK，程式常用 `tsk` / `tsks`。
- 背景閱讀：`docs/串珠的介紹.md`。其中書籍沿革與內容解說是背景資料，不是前端行為的證據。
- 目前經節：使用者原稱 activate address；這是概念名稱，不保證程式存在同名變數。優先追查 `TPPageState.s` 的 `bookIndex`、`chap`、`sec`。
- 交互參照：指向其他經文的引用；須分開分析顯示文字與點擊時實際使用的參照資料。
- SN：Strong Number；使用者預期可點擊開啟對應字典，實際事件與支援範圍待驗證。
- `book` 有兩種不同語意：`sc.php` 查詢參數 `book=4` 指串珠資料來源，`book=3` 指註釋資料來源；內部經節地址的 `book` / `bookIndex` 則指聖經書卷編號（例如 1 為創世記）。不可混用。

# 2. 我認為這個功能的目的與資料內容

以下為使用者提供的理解，除第 3 節已列出的局部核對外，仍須以程式碼確認。

## 2.1 目的與來源

TSK 原是一部書，電子化後由 API 提供各經節的串珠內容，讓使用者閱讀目前經節的摘要、關鍵字、交互參照與補充說明。

- API 文件線索：https://bible.fhl.net/json/ 中的 `sc.php`。
- 範例：https://bible.fhl.net/json/sc.php?book=4&engs=Gen&chap=1&sec=1&gb=0
- 上述 URL 是參考線索與資料例子，未在整理時驗證線上回應。分析時須區分 API 文件、實際回應與前端實作。

## 2.2 可能出現的內容

1. **章摘要／分段**：以節號和文字列出摘要起點，與後文可能由空行隔開。
2. **關鍵字**：使用者理解是取自 KJV，可以是單字或子句，通常附有交互參照。
3. **說明文字**：可能是關鍵字註解、經節相關描述或類似註腳的補充內容。
4. **交互參照與 SN**：可能出現在上述內容內，需追查如何辨識與產生互動元素。

原稿創 1:1 範例的節錄如下。這是輸入格式線索，不是完整 API 回應，也不是全資料集格式保證；此處 `\n` 表示換行。

```text
\n  1;  God creates heaven and earth;\n  3;  the light;\n  6;  the firmament;\n  9;  separates the dry land;\n 14;  forms the sun, moon, and stars;\n 20;  fishes and fowls;\n 24;  cattle, wild beasts, and creeping things;\n 26;  creates man in his own image, blesses him;\n 29;  grants the fruits of the earth for food.\n\n * beginning.\n # Pr 8:22-24; 16:4; Mr 13:19; Joh 1:1-3; Heb 1:10; 1Jo 1:1|\n\n * God.\n # Ex 20:11; 31:18; 1Ch 16:26; Ne 9:6; Job 26:13; 38:4; Ps 8:3; 33:6,9|\n\n
```

使用者將摘要起點理解為「1–2：God creates heaven and earth」「3–5：the light」「6–8：the firmament」。請確認程式是否實際推算結束節，以及最後一項如何處理，不要把語意解讀直接當成實作規則。背景文件提到摘要只在每章第一節出現，也應區分資料慣例與程式限制。

## 2.3 顯示語言

使用者提到 `TSK顯示模式` 有「中文（縮寫）」「中文（全名）」「英文」；中文全名主要方便不熟悉書卷縮寫的人。

「原始英文轉成中文」不可直接解讀為整篇翻譯。初步只確認交互參照書卷名稱有轉換邏輯；摘要、關鍵字、一般文字是否轉換，留待追查。模式值與預設值也須分開核對狀態初始化、設定 UI、render fallback 與儲存還原。
