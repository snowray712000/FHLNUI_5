# 7.5.12.5：點位置跳轉後，網址 hash 沒變，alt+←/→ 回不去

## 現象

瀏覽器的 alt+← / alt+→ 就是上一個 / 下一個網址 (hash)。從「交互參照」dialog 點某個位置，經文區會跳過去、app 自己的瀏覽記錄 (`ViewHistory`) 也有新增，但網址列的 hash 沒變，所以瀏覽器的上一頁 / 下一頁沒有包含這次跳轉。註釋分頁、右側分頁內點位置的跳轉也一樣。搜尋 dialog 點位置本來就正常。

## 原因

hash 只在 `indexLast.js` 的 `$(document).on('chapchanged')` 裡用 `history.pushState` 更新 (`secchanged` 是 `replaceState`)。這幾個跳轉會改 `ps.bookIndex / chap / sec`、呼叫 `triggerGoEventWhenPageStateAddressChange(ps)` 並重繪，但忘了觸發 `chapchanged`。`ViewHistory` 是另一套 (app 內的歷史清單)，與瀏覽器歷史無關，所以「有歷史記錄但 hash 沒變」。

`pushState` 不會觸發 `hashchange`，所以不需要 `Hash_Changed` 的旗標。

## 修正

在跳轉的最後加上 `$(document).trigger('chapchanged')`：

| 檔案 | 跳轉 |
|------|------|
| `index/queryReferenceAndShowAtDialogAsync.es2023.js` | `show_in_embed()`：交互參照 dialog 的「經文區跳到這裡」、嵌入模式 |
| `index/FhlInfoContent.es2023.js` | 右側分頁內 (串珠等) 點位置 |
| `index/comment_register_events_es2023.js` | 註釋分頁點位置 |
| `index/ViewHistory.es2023.js` | 左側歷史記錄清單點某一筆 (7.5.14.2 補) |

已正常的：`SearchDialog` 的 `#goto`、`FhlLecture` 上下章、`BookSelect`、`BookSelectChapter`、`FhlInfoAudio`。

## 沒動的

`.commentBackground` 的點擊 (`ps.chap = 0`，進入書卷背景)：不是跳到某一節，沒有加進瀏覽器歷史。若之後想加，在該處同樣觸發 `chapchanged`，但要注意 `indexLast.js` 會用 `pageState.chap` 組出 `書名0:sec`。

## 寫新的跳轉時

只要會改 `ps.bookIndex / chap / sec` 並讓使用者覺得「換了位置」，最後就觸發 `chapchanged`；只是 activate 節變了 (同一章) 用 `secchanged` (replaceState)。
