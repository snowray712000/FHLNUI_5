# 典藏（ob）bug 修正記錄

依據：[`0920b_典藏bug修正規格.md`](0920b_典藏bug修正規格.md)（修正規格）、[`0920c_典藏bug_測試驗證.md`](0920c_典藏bug_測試驗證.md)（重現方式）。

修正對象：`static/ob_api/obphp.js`。四項均已修正並經使用者實測確認可用（2026-09-20）。

## 1. 節號範圍文字組字錯誤

`content.render` 內組 `rtitle4` 的兩處三元運算子補上括號：

```js
if (re_record.bsec != 0)
  res += re_record.bsec.toString() + (this.props.isgb ? "节" : "節");
...
if (re_record.esec != 0)
  res += re_record.esec.toString() + (this.props.isgb ? "节" : "節");
```

## 2. `JSON.parse` 無防護

五處 `JSON.parse(jstr)` 皆改為 `try/catch`，失敗時沿用各自原本 error 分支的訊息文字並 `return`，不繼續往下執行：

- `_set_obdata_from_ajax` 查 `ob.php`：`err_msg: "ob.php錯誤"`
- `_set_obdata_from_ajax` 內巢狀查 `sob.php?book=all`：`err_msg: "sob.php book=all 錯誤"`
- `_query_sob_from_ajax_book_chap_sec`：`err_msg: "sob.php 回應格式錯誤"`
- `_query_sob_from_ajax_idxbook`：`err_msg: "sob.php 回應格式錯誤"`
- `_query_sob_from_ajax_page`：`err_msg: "sob.php 回應格式錯誤"`

（規格建議的訊息文字沿用原 error callback 字串；`_query_sob_from_ajax` 這個既有死碼函式不在規格列出的 5 處範圍內，維持原樣未動。）

## 3. 多次請求無序保護

在 `getInitialState` 加入 `obreqSeq: 0`，`_query_sob_from_ajax_book_chap_sec`／`_query_sob_from_ajax_idxbook`／
`_query_sob_from_ajax_page` 三個查詢函式共用同一個序號空間：

- 發出請求前 `var mySeq = ++this.state.obreqSeq;`
- success／error callback 一開始先比對 `pthis.state.obreqSeq !== mySeq`，不相等代表已有更新的請求發出過，直接 `return`，不寫入 state。

同時移除 `_query_sob_from_ajax_idxbook` 內 `setState({ idxbook, idxbook1, ... })` 裡無用途的 `idxbook1` 欄位寫入，改為只留 `idxbook`。

`componentWillReceiveProps` 觸發的查詢與使用者手動點擊觸發的查詢共用同一個 `obreqSeq`（採規格建議的作法）。

## 4. React 重複初始化多查一次頁

採規格建議的方向 2（影響範圍最小）：在 `frame.componentWillReceiveProps` 內比較 `nextProps` 的
`ibook`／`ichap`／`isec`／`isgb` 是否與 `this.props` 完全相同，相同就直接 `return`，不重新查詢：

```js
componentWillReceiveProps: function (nextProps) {
  if (nextProps.ibook === this.props.ibook &&
      nextProps.ichap === this.props.ichap &&
      nextProps.isec === this.props.isec &&
      nextProps.isgb === this.props.isgb) {
    return;
  }
  this._query_sob_from_ajax_book_chap_sec(nextProps.ibook, nextProps.ichap, nextProps.isec);
},
```

未採用方向 1（移除 `FhlInfo.init` 最後的 `this.render(ps)`），因其影響範圍涉及其他分頁的初始化流程，方向 2 只動
`obphp.js` 單一檔案，風險較低。
