# 原文字典：高亮正在讀的經文 (active address)（6.8.1）

## 緣由

浸宣 (twcb) 原文字典的條目常常是「一個字的所有用法」的總覽，例如 G5355 φθόνος：

> 「羨慕，嫉妒」。帶κακία惡毒，#多3:3|。在惡事的一覽表中，#羅1:29;提前6:4|……不好懂，或許經文上有缺損，經文：πρὸς φθόνον ἐπιποθεῖ τὸ πνεῦμα靈是至於嫉妒麼，#雅4:5|……

讀者真正關心的是：**我正在讀的這節，被歸在哪個義項底下？** 以前要自己在一堆 `#…|` 裡找「雅4:5」。
現在把與「正在讀的經文」(active address) 相同的引用高亮，並自動捲過去，旁邊的解說 (例「不好懂，或許經文上有缺損」) 就是讀者最需要的那句。

CBOL 的內容較短，需求沒那麼強，但同一個 dialog 內一起套用。

## 比對分級

| 等級 | 條件 | class | 樣式 |
|---|---|---|---|
| 2 同一節 | 引用含 active address 那一節 | `.ref-act-verse` | 黃底粗體；dialog 自動捲到第一個 |
| 1 同一章 | 同書同章但節不同；**或整章引用** | `.ref-act-chap` | 淡黃底＋虛線底線 |
| 0 | 其它 | — | 不標 |

- 讀雅4:5 查 G5355 → `#雅4:5|` 是等級 2。
- 讀雅4:2 查 G5355 → `#雅4:5|` 是等級 1。兩種樣式刻意分開，否則使用者會以為字典在講 4:2。
- `#羅1:29;雅4:5|` 這種多處寫在一起的，只要其中一處命中，整段高亮。
- **整章引用視作同一章**：`#雅4|`、或 `雅3:1-5:3` 這種跨過整章的範圍，展開後也「含」4:5，但那不是在講這一節。判斷：該引用在 active 那章的節數 ≥ 該章總節數 (`BibleConstant.COUNT_OF_VERSE`)，且該章不只 1 節。

## 為什麼容易做

twcb 內容經 `twcbflow` → `splitReference` 後，每段經文都已變成
`<span class="ref" addr-data='[{book,chap,verse},...]'>`，而且**範圍已展開成逐節** (`BibleConstantHelper.generateAddressesTp*`)。
所以不用再解析文字，dialog 顯示後掃一遍 `.ref[addr-data]` 比對即可；「包含」就是「陣列中有沒有這一節」。

## active address 從哪來 (重點)

`queryDictionaryAndShowAtDialogAsync(jo)` 多了可選的 `jo.activeAddr = {book, chap, verse}` (book 1-based)。
**由呼叫端決定**，沒給才退回 `ps.bookIndex / ps.chap / ps.sec`。不在 dialog 裡直接讀全域，否則從搜尋結果開字典會標錯。

| 入口 | activeAddr |
|---|---|
| 即時SN dialog (`FhlLecture.es2023.js` `mouseenter_sn_dialog` → `show_dialog`) | hover 的那一節 (`re_dict.one ?? one`，來自 `ps.book_hover/chap_hover/sec_hover`)。即時SN 本身的 CBOL `.ref` 也高亮；在裡面點 `.sn` 開完整字典時傳下去 |
| 搜尋結果中的 SN (`SearchDialog_es2023.js` `.seSN` click) | 那筆結果的 `.sd-addr` 的 `ibook/chap/sec`。**注意 `ibook` 是 0-based**，要 +1 |
| Parsing 表、註釋中的 SN、其它 | 沒給 → `ps` 目前閱讀位置 |

驗證過：讀雅4:5 時，把 `ps.sec` 改成 1 再從即時SN 點 SN，仍標 4:5 (用的是 hover 的那節)；讀雅4:5 時搜尋 G1937，點「羅 7:7」那筆的 SN，標的是 `#羅7:7;13:9|`，`#雅4:2|` 不標。

## 檔案

- `index/highlightActiveRefs.es2023.js`
  - `getDefaultActiveAddr()`：從 `ps` 取
  - `normalizeActiveAddr(addr)`：hover 的 attr 是字串，統一轉 number；接受 `verse` 或 `sec`；不合法回 `null`
  - `matchLevel(addrs, act)` → `0|1|2`，純函式，有單元測試
  - `highlightActiveRefs($root, act)`：加 class，回傳最該被看到的元素 (第一個同節，否則第一個同章)
  - `scrollRefIntoView(scroller, el)`：不在可視範圍才捲到約上方 1/3；只捲 dialog 本身 (`DialogHtml` 的 `dlg` 就是捲動容器)，不動整頁
- `index/queryDictionaryAndShowAtDialogAsync.es2023.js`：`registerEventWhenShowed` 裡高亮＋捲動
- `index/FhlLecture.es2023.js`：即時SN dialog
- `index/SearchDialog_es2023.js`：`.seSN` click 帶 activeAddr
- `index/fhl.css`：`--ref-act-verse-bg`、`--ref-act-chap-bg`、`--ref-act-chap-border` (照 `--ob-*` 的作法，將來換 theme 只覆寫變數)
- `tests/highlightActiveRefs.test.js`

## 之後可以做
