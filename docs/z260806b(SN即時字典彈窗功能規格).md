## 1. 功能概述與三條觸發路徑

在閱讀畫面中，經文文字裡凡是「原文編號本身」（渲染為 `.sn`）或「編號所指的中文/英文詞」（渲染為 `.sn-text`）都可以點擊，跳出一個彈窗顯示該 Strong's Number 的字典資料。

專案裡實際上存在 **三條並存但邏輯不同的 `.sn`/`.sn-text` click 觸發路徑**，統一用 jQuery **事件委派**（delegation），沒有對個別元素直接綁定：

| 路徑 | 委派容器 | 開出的彈窗種類 | 內容 |
|---|---|---|---|
| **(A) 閱讀主畫面**（`#lecMain`） | `$lecMain` | 「即時 SN 摘要」彈窗 | 標題（原文/簡義/parsing）+ 左欄（次數統計+字典本文）+ 右欄（同源字清單） |
| **(B) Parsing 分頁**（`#parsingTable`） | `$('#parsingTable')` | 「原文字典」彈窗 | 標題（同上）+ 浸宣字典本文 + CBOL 字典本文（無左右欄、無次數、無同源字） |
| **(C) 註釋分頁**（`#fhlInfoContent`） | `$('#fhlInfoContent')` | 同 (B)「原文字典」彈窗 | 同 (B) |

只有路徑 (A)——閱讀主畫面——才會開出含左右欄（次數統計 + 同源字清單）的完整彈窗；(B)、(C) 開的是內容較單純、只顯示字典本文的彈窗，兩者都呼叫同一支函式 `queryDictionaryAndShowAtDialogAsync`。

`Dialog_Sn_Info_Summary.when_click_on_sn(e)`（`FhlLecture.es2023.js:1530-1568`）流程：

1. 取得 `currentTarget` 所在的 `.lec`（該節經文容器）。
2. 若該節尚未 `.selected`（即使用者還沒先點選這一節）：模擬觸發該 `.lec` 的 click 事件（先做「選節」動作），然後 `return`——**這次點擊不會開彈窗**。

`mouseenter`/`mouseleave` 對應 `when_mouseenter_on_sn`/`when_mouseleave_on_sn`：在「即時彈窗模式」開啟時，滑鼠移入即顯示、移出即關閉；同時呼叫 `SN_Act_Color.s.act_add`/`act_remove` 做同源字同色高亮（此高亮機制細節見 [z260806a] 第4節 (B)）。

## 3. Dialog 容器機制：`DialogHtml` 基底類別

檔案：`index/DialogHtml.es2023.js`

這是專案裡所有彈窗共用的 jQuery UI `.dialog()` 封裝（範例 HTML 中的 `ui-dialog`、`ui-draggable`、`ui-resizable` class 即為 jQuery UI 原生產物，非自訂）：

```js
export class DialogHtml {
    dlg = null;

    showDialog = (jo) => {
        const idDlg = this.#getIdOfDialog();          // 每次新建一個 <div id="iddlgN">，不重複使用
        const dlg = $(`#${idDlg}`).dialog({ autoOpen: false });
        dlg.on("dialogclose", () => {
            dlg.parent()[0].outerHTML = "";             // 關閉即銷毀整個 DOM
            this.dlg = null;
        });
        dlg.html(jo.html);
        dlg.dialog("option", "maxWidth", jo.maxWidth ?? window.innerWidth * 0.80);
        dlg.dialog("option", "maxHeight", jo.maxHeight ?? window.innerHeight * 0.80);
        dlg.dialog("option", "width", jo.width ?? window.innerWidth * 0.80);
        if (jo.position) dlg.dialog("option", "position", jo.position);
        dlg.dialog("option", "title", jo.getTitle());   // 只能是純文字（jQuery UI 限制）
        dlg.dialog("open");
        jo.registerEventWhenShowed(dlg);                 // 開啟後才能操作 DOM，用來掛內部事件、覆蓋標題 HTML
        this.dlg = dlg;
    };

    closeDialogViaTriggerCloseButton = () => { /* 觸發 .ui-dialog-titlebar-close 的 click */ }
}
```

重點：

- **沒有子類別**。專案裡不存在 `SnDialog`/`StrongDialog`/`SnInfoDialog` 之類繼承 `DialogHtml` 的類別。所有呼叫方一律 `new DialogHtml()`，靠傳入的 `{html, getTitle, position, maxHeight, maxWidth, width, registerEventWhenShowed}` 這組物件客製化內容，用「組合」取代「繼承」。
- **`getTitle()` 只能回傳純文字**（jQuery UI dialog 的 `title` option 限制），但實際標題需要含 `<span class="sn">`、原文字形、意義等 HTML 結構。解法：在 `registerEventWhenShowed(dlg)` 回呼裡，事後用 `dlg.parent().find('.ui-dialog-title').addClass('realtime-sn').html(richHtml)` **直接覆寫 jQuery UI 產生的 `.ui-dialog-title` 元素內容**。這是必須留意的實作手法，另一專案若用其他 dialog 元件（非 jQuery UI），可以直接支援 HTML 標題，不需要這個 workaround。
- **每次開新的，關閉即銷毀**：不是「隱藏/顯示」同一顆 DOM，而是每次 `showDialog` 都新建一個 `<div id="iddlgN">`，`dialogclose` 事件時把整個 `.ui-dialog` 容器 `outerHTML = ""` 清空。id 累加（`iddlg0`, `iddlg1`, ...）不重複使用。
- 同一時間只允許存在一個「即時 SN 摘要」彈窗：`show_dialog()`（見第4節）一開始會先關閉前一個還開著的同類彈窗。

> **注意**：`tests/sn-dictionary-dialog.js`、`tests/sn-dict-ISnDlgAddor.js`、`tests/sn-dict-DlgReuse.js` 這一套 `SnRefDialog`/`ISnDialogAddor`/`DlgReuse`（彈窗重用機制）是**測試資料夾裡的實驗性/原型設計，並未被生產程式碼採用**。生產程式碼（`FhlLecture.es2023.js`、`queryDictionaryAndShowAtDialogAsync.es2023.js`）一律走上面「每次新建、關閉銷毀」的 `DialogHtml` 邏輯。撰寫技術文件或依此重新實作時，請以生產程式碼為準，不要誤把原型當作現行設計。

## 4. 「即時 SN 摘要」彈窗（路徑 A）的組裝細節

主體邏輯在 `show_dialog(re_parsing, re_dict)`，`index/FhlLecture.es2023.js:1116-1469`。

### 4.1 標題結構

對照本文件開頭範例 HTML 的 `.ui-dialog-title.realtime-sn` 內容，由以下幾個 span 組成（第 1130-1423 行）：

| 元素 | class | 內容來源 |
|---|---|---|
| SN 代碼 | `.sn`（`attr sn/tp`） | `H3303 ` / `G1080 ` 這種字串，點擊可重新查詢自己 |
| 出現經文按鈕 | `.fn-search-sn`（`attr sn/tp`） | 固定文字「出現經文」，點擊會把 SN 帶入搜尋框並觸發全文搜尋，然後關閉自己 |
| 原文字形 | `.orig` | 從 `re_dict.record[0].same` 中找出 `csn == sn` 那一筆的 `word` |
| 簡義 | `.mean` | 同一筆的 `cexp` |
| 詞性/文法分析 | `.parsing` → `.one-parsing`（可能多筆） | 見下方「Parsing 分析」 |

**Parsing 分析**（`find_sn_parsing`，第 1227-1252 行）：從另一支 API（`qp.php`，見第5節）回傳的 `re_parsing.record[1..]`（`record[0]` 是整節總覽）中，篩出 `element.sn == sn` 的所有筆，並以 `wform`（分析文字）去重（相同的只留一筆），組成：

```html
<span class="one-parsing">
  <span class="item-title">詞性:</span><span>{element.pro}</span>
  <span class="item-title">分析:</span><span>{element.wform}</span>
</span>
```
（一個 SN 在同一節裡若對應到多種詞形變化，會產生多個 `.one-parsing`。）

### 4.2 內容結構（left-column / right-column）

第 1380-1389 行：

```js
let div_content = $("<div>").addClass('column-parent')
let div_right_column = $("<div>").addClass('right-column').addClass('column')
let div_left_column = $("<div>").addClass('left-column').addClass('column')
div_content.append(div_left_column).append(div_right_column)
div_left_column.append(span_count).append("<hr/>").append(span_cbol_part)
div_right_column.append(span_same)
let html = div_content[0].outerHTML
```

**left-column**：
1. `span_count`：三段出現次數文字——「本章 N 次，本書 N 次，聖經 N 次。」（來源分別是 `get_sn_count_in_chap`／`get_sn_count_in_book`／`get_sn_count_in_bible`，見第5節「靜態資料」），加上「本書主要於 X 章。次數為 Y」（取本書各章次數排序前 3 名，並列名次一起顯示，邏輯見第 1170-1204 行）。
2. `<hr/>`
3. `span_cbol_part`（class=`cbol`）：CBOL 字典中文本文，取自 `re_dict.record[0].dic_text`，用 `get_cbol_dict_part_data()` 略過原文前段（依 `\n\n` 切段），並用 `splitReference()` 把文字中偵測到的經文引用（如 `#提後2:23|`）轉成可點擊的 `<span class='ref' addr-data='[...]'>`。

**right-column**：
- `span_same`：同源字清單。舊約（`tp=='H'`）固定顯示「舊約無資料。」；新約則對 `re_dict.record[0].same` 依 `ccnt`（出現次數）由高到低排序、過濾掉自己（`csn != sn`），每筆組成：
  ```html
  <span class="one-same">
    <span class="sn" sn="{csn}" tp="G">G{csn}</span>
    <span>({ccnt})</span>
    <span>{cexp，含經文引用連結}</span>
  </span>
  ```
  （排序/過濾/正規化前導零等規則與 [z260806a] 第4節 (A)、第6節完全一致，不重複展開。）

### 4.3 `registerEventWhenShowed` 內掛的事件

第 1414-1467 行，共三組：

1. `.fn-search-sn` click → 把 `H{sn}`/`G{sn}` 填入 `#searchTool .search-input`，觸發 `.searchBtn` click 做全文搜尋，並關閉自己。
2. `.ref` click（left-column 字典本文或 right-column 同源字說明裡的經文引用連結）→ `queryReferenceAndShowAtDialogAsync({addrs, event})`，開交互參照彈窗（另一個獨立功能，非本文件範圍）。
3. `.sn` click（彈窗**內部**的 SN 連結，包含標題裡自己的 SN、以及同源字清單裡每一筆的 SN）→ 呼叫 `queryDictionaryAndShowAtDialogAsync(jo)`，再疊開一層「原文字典」彈窗（路徑 B/C 用的那種簡化版）。原始碼在此處留有 `// BUG:` 註解（第 1463 行），暗示這裡有已知問題，另一專案實作時可留意「彈窗內再點 SN 開巢狀彈窗」這個情境是否有邊界 bug。

## 7. 完整呼叫流程（Step by Step，以路徑 A 為主）

### Step 0：DText 的 `sn`/`tp2` 屬性從哪裡來

原始聖經文字（`unv`/`kjv`/`rcuv`/`fhlwh`/`bhs` 等譯本）帶有 `<WG2424>`、`{<WH0834>}`、`(WTG5772)` 這類原文標記字串，經過以下轉換鏈才產生帶 `sn` 屬性的 DText：

1. **`index/cvt_others.js`**：`cvt_one()`（第 41-73 行）為主流程：
   - `replaceOrigToPair()`（132-158行）先把 `<WTH0834>` 這種單標籤轉成 DOMParser 能解析的成對標籤 `<WTH0834I></WTH0834I>`。
   - `doUsingDOMParsor()` → `getAllDTextsFromAllChildrenNode()`（320-447行）用 `DOMParser` 把文字轉 DOM 樹再遞迴走訪；命中形如 `WA?(T?)(H|G)(\d+[aA]?)(I?)` 的標籤時（第 403-436 行）：設定 `dtext.tp`（`'G'`/`'H'`）、`dtext.sn`（去前導零）、`dtext.tp2`（`WG`/`WTG`/`WAG`/`WTH`/`WH`）、可能的 `isCurly`（是否在花括號內）。**這一步產生的 DText 帶 `sn` + `tp2`，代表「原文編號本身」，渲染出來就是 `.sn`（不是 `.sn-text`）**。
   - 若 `version` 屬於 `['unv','kjv','rcuv','fhlwh','bhs']`，額外呼叫 `add_sn_text()`（`cvt_others.js:75-79`）→ `attach_sn_text()`（`index/attach_sn_text.js:88-107`）：把「原編號前面的中文/英文詞」也標上同一個 `sn`/`tp`（但**不加 `tp2`**），渲染時因為沒有 `tp2` 會被判斷為 `.sn-text`。規則（`try_set_sn_text`，第 49-81 行）：跳過已有 `sn` 或純標點的節點；往後找下一個 SN 元素時，若遇到冠詞 `G3588` 或 `sn>=9000` 或 `tp2` 含 `"T"`（時態標記）則跳過繼續找下一個；找到後把 `sn`/`tp` 複製到該中文/英文詞上。

2. 舊版對應機制：`index/add_sn_text.js`（操作對象是已渲染出來的 jQuery DOM，而非 DText 陣列），規則與 `attach_sn_text.js` 對齊，供舊流程/測試沿用。

### Step 2：使用者點擊 `.sn`/`.sn-text`（路徑 A）
