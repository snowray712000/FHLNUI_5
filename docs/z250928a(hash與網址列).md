## 分析動作

- 新分頁開啟時
- 同分頁，使用者直接改 hash
- 同分頁，使用者按 back/forward

- 程式變更 hash
  - 因為 ... 「使用者輸入的 hash」需要被改
    - hash 是舊式的，例如 #/bible/Ge/3/5 或 #/bible/Ge/3
    - hash 是錯誤的，例如 #/bible/Ge999:1
  - 因為 ... 「使用者操作 UI」需要反映在 hash 上
    - 使用者，按了「下一章」「上一章」
    - 使用者，使用「切換書卷」功能，切換到某書卷、某章
    - 使用者，使用「瀏覽記錄」功能，切換到某書卷、某章
    - 使用者，使用「瀏覽記錄，上一筆，下一筆」功能，切換到某書卷、某章
    - 使用者，同一章，但「Activate 節」改變

❓ 問題

❓ 問題
剛剛想的是繪圖 fhllecture，即經文的內容，若現在想著 fhlinfo 的畫面，那麼，關鍵應該就是 activate 節，對嗎？

是的

❓ 問題
承上，若 fhlinfo 的繪圖，按下「下一段」資料，是要整合型的那一段資料，還是接續聖經順序的下一段？

聖經順序的下一段

❓ 問題
有沒有可能，經文位置描述包含著，譯本？例如 #/bible彼前2:1;3:1-5，然後指定 esv 或是 unv，或是多個譯本「esv, unv」？

browser 有「上一頁」「下一頁」功能，看起來好像有「歷史記錄」，但「歷史記錄」又包含不是這次頁面的結果，要如何統一呢？難道是一載入頁面，就使用 pushState 把之前的 歷史記錄都加進來？還是要將「歷史記錄」視作單純的書籤功能。然後點擊後，的確也會 pushState？
