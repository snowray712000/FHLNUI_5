# 7.5.12.3 字縮小時，節與節之間的留白跟字走

## 問題
手機靠眼睛近，字可以設到最小 (整體 70%)，但看起來「行距」還是太大。

## 量測 (手機寬度，--fontsize 12pt → 8.4pt)
- 段落內的行距：`.vercol { line-height: 1.1em }`，70% 時 12px / 字 11.2px，**有跟著字縮**，不是主因。
- 每節 / 每段上下留白：`#lecMain > .lec-grid .paragraph { padding: 7px … }`，**固定 px**，上下共 14px，比一行還高，這才是看起來鬆的原因。搜尋結果、交互參照的 `.verse-grid .paragraph` 同樣固定 5px。

## 改法 (index/fhl.css)
| 位置 | 原本 | 現在 (100% 時等值) |
|------|------|------|
| `#lecMain > .lec-grid .paragraph` | `7px` | `0.4375em` |
| `.verse-grid .paragraph` | `5px` | `0.3125em` |

em 以 `.paragraph` 自己的 font-size (`--fontsize`) 為準；實測 16px → 7px、11.2px → 4.9px。左右 padding (`rem`) 不動。

## 沒動 / 想法
- 行內 `1.1em` 沒動：對中文已經偏緊，字放大時再縮會擠。
- 70% 時每節上下留白約 10px (原 14px)；若手機上仍嫌鬆，可再調小 em (例如 `0.3em`)。
- 參考：iOS Dynamic Type 每個字級配固定行高，且行高隨字級縮放 (Body 17/22、Footnote 13/18…)，沒有「字小就縮緊行距」的規範；這裡的問題是留白沒跟字縮，不是行距比例。
