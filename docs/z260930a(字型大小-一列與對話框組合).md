# 字型大小：側邊欄一列 + 對話框與組合

6.11.11。

## 緣由

原本設定裡有 4 列字型大小 (字體大小、H字大小、G字大小、SN字大小)，各自 A- A+ 滑桿 文字框：

- **按鈕會跑走**：每列的標籤 `float:left`，標籤長短不同 (「字體大小:」「SN字大小:」)，A- A+ 在每列起點不同；hover 又設了 `top:1px; left:1px`；`inline-block` 在左欄寬度變時會換行
- 主字型按一下 ±2，其它 ±1；滑桿只綁 `change`，放開才看得到
- 四個各自獨立，想整體放大要調四次；「H G SN」不好懂；沒有預覽、沒有回到預設

## 做法

> 下面「側邊欄」「狀態」是第一版 (經文為基準、組合存絕對 pt)。之後改成「整體大小 × 情境」，見文末〈整體大小 × 情境〉。

### 側邊欄 (`FontSizeTool`)

一列 `字體大小: [A−] 12 [A+] ⚙`。按鈕 `<button>` 固定寬度，數字 `.fs-val` 固定 2em 寬 (tabular-nums)，hover 只變底色不位移。

- A− A+ 調「經文」(ps.fontSize)，一次 ±1
- ⚙ 開對話框；右鍵、手機長按開快速選單 (組合、我的組合、設定…)，樣式沿用 SN 篩選的 `.snf-menu`
- 訂閱 `FontSize.onChange`：同步數字；停下來 (isSettled) 時 `FhlLecture.s.reshape` (併排時重新對齊各節高度)

原本 H/G/SN 三列是 `Settings.init` 另外 append 的 (`FontSizeToolBase`)，已移除。

### 狀態 (`FontSize`)

- **值仍存在 ps**：`fontSize`、`fontSizeHebrew`、`fontSizeGreek`、`fontSizeStrongNumber`，css 變數照舊 `--fontsize`、`--fontsize-hebrew`、`--fontsize-greek`、`--fontsize-sn`。舊使用者設定不變，其它讀 ps 的地方也不必改
- localStorage `fhlFontSize`：`link` (原文、SN 是否跟著經文等比例，預設 true)、`ratio`、`custom` (我的組合)
- **比例存起來**，不每次由目前的值推：`hebrew = round(main × ratio)`，若每次由四捨五入後的值推比例，連按 A+ A- 會越跑越偏 (測試有驗來回 7 次回到原值)。比例在：改單一項 (該項)、套用組合、打開 link 時重算
- 值夾在 6 ~ 60；夾住時比例不變，縮回來會恢復
- 拖曳滑桿 (`set(key, v, false)`) 先只改 css 變數，停 200ms 才存 ps、存 localStorage、通知 isSettled (reshape 較費時)
- `activeId`：四個值與哪個組合完全相同 (內建 id 或 `u0`…)，用來把組合標成 active

內建組合 `FONT_PRESETS` (經文 / 希伯來 / 希臘 / SN，pt)：

| id | 名稱 | 值 | 用途 |
|---|---|---|---|
| default | 預設 | 12 / 26 / 26 / 14 | 原本的預設值 |
| study | 研讀 | 14 / 32 / 28 / 11 | 原文放大，SN 小一點不搶眼 |
| share | 分享、投影 | 22 / 40 / 36 / 12 | 整體大字 |
| compact | 精簡 | 10 / 20 / 18 / 10 | 一次多看幾節 |

數值是初訂，實際使用後可調整；測試檢查各組合值在範圍內且彼此不同 (否則 activeId 分不出來)。

### 對話框 (`FontSizeDialog`)

由上而下：組合、我的組合 (+ 存成組合、× 刪除，同名覆蓋，同 SN 讀經組合)、經文、「原文、SN 跟著經文等比例」勾選、希伯來文 / 希臘文 / 原文編號 (左邊框紅色表示正在跟著)、預覽 (中文 + `<G3056>`、希臘文、希伯來文，用 `--fontsize*` 變數與 `.greek-char` `.hebrew-char`)。

- 值改變時只同步 input 的值與 active 標記 (`#sync`)，**不重畫**，否則正在拖曳的滑桿會中斷；正在 focus 的 input 不覆寫。只有我的組合增刪才 `render()`
- 組合 chip 沿用 `.snf-dlg .snf-lens` 樣式 (外層 `class="snf-dlg fs-dlg"`)
- **對話框的字固定 15px**：`.ui-dialog-content` 的字是 `var(--fontsize)`，其它對話框跟著經文變大是刻意的；但這個對話框若也跟著變，拖曳時控制項會變大移位 (又是「跑走」)。只有預覽區跟著變

## 介面字型

經文、原文、SN 可調，但左欄 (`.leftWindow div` 10pt)、譯本名稱列 (`#lecMainTitle`)、右邊分頁標籤 (`#fhlInfoTitle` 12pt / 選中 20px)、`#fhlInfoContent` 的底字 (10pt)、即時 SN 視窗 (`#parsingPopUpInside`) 都寫死，有人覺得太小又沒辦法調。

- 介面實際大小 (pt，12 = 原本大小，夾在 9 ~ 24)。起初是獨立的 `ui`、不在組合裡；後來併入情境，見〈整體大小 × 情境〉
- css 不改成某個基準字，而是 `--ui-k` (= ui / 12，無單位) 乘原本的值：`calc(10pt * var(--ui-k, 1))`。原本的大小各不相同 (10pt、12pt、20px、8pt)，乘倍率最不會改到預設的樣子；fallback 1，沒設時等於原本
- 跟著字變的高度也乘：`#lecMainTitle` 高 30px、`#lecMain` / `.chapControl` 的 top 30px、`.versionName` 高 21px、`#fhlInfoTitle` 高 30px、`#fhlInfoContent` top 30px。`#commentTitle` 框高 40px 固定，字最多 ×1.5
- `index.html` 最前面的 inline script (與主題同一段) 先把 `--ui-k` 設在 `<html>`，第一次繪製就是對的大小；之後 `applyCss` 設在 body
- 典藏分頁 (`static/ob_api/ob_api.css`)：資料本身 (表格的年代書名作者、卡片標題、簡介) 算經文，`calc(var(--fontsize) × 原px ÷ 16)`，預設時與原本相同；篩選、chip、輸入框、表格 / 卡片切換、徽章、看更多、閱讀頁的按鈕與書名頁碼列算介面，原 px × `--ui-k`。舊的 `.obtable` (ob_table.css) 本來就用 `--fontsize`
- **沒納入**：上方工具列 (已用 rem、高度 `--tb-h` 44px 與斷點是 px，要動得一起改)、書卷選擇 (版面是固定寬高的格子)、jQuery UI 對話框標題、onOffSwitch 開關裡的字。右邊分頁標籤 `overflow: hidden`，很大又很窄時後面的分頁會被切掉

## 整體大小 × 情境

> 2026-10-08：profile 裡的「介面」已拿掉，介面改為基準 (12pt × 整體大小)，內建組合只留預設、投影，見 `z261008a(字型大小-以介面為基準與觸控下限).md`。下面關於介面在情境裡、分享投影介面 14 的敘述已過時。

原本以「經文」為基準，原文、SN 相對於它；介面加進來後要決定以誰為基準。結論：**全部相對於一個「整體大小」**。

- 兩種需求不同：**整體** 跟眼力、裝置有關，設一次就不太動 (長輩、平板)；**內容** 跟情境有關 (研讀、投影、多看幾節)，常切換
- 若介面跟著經文：投影時把經文放大，左欄、分頁標籤也跟著大，吃掉經文的空間
- 以整體為基準：眼力不好的人在外面 A+ 全部一起大；切換情境只換比例，**不會把調好的整體大小洗掉** (第一版組合存絕對 pt，長輩調到 16 再點「研讀」會被拉回 14)

### 資料

- 實際 = round(`profile[k]` × `scale` / 100)，夾在範圍內 (介面 9 ~ 24，其它 6 ~ 60)；夾住時 profile 不變
- `scale`：整體 %，70 ~ 200，一次 ±10
- `profile`：情境 = 經文 / 希伯來 / 希臘 / SN / 介面 在 100% 時的 pt，**存小數**。內建組合 `FONT_PRESETS` 與我的組合都是 profile；組合比對 (`activeId`) 取到小數第二位
- 對話框改某項的「實際值」v：profile = v × 100 / scale；**實際值沒變就不動** (110% 時 12 × 1.1 = 13.2 顯示 13，滑桿停在 13 不該把 profile 改成 11.82)
- A+ A-：profile 加減 100 / scale (一個實際 pt)，不由取整後的實際值反推，否則非 100% 時來回會偏 (`stepActual`，測試驗 100 / 110 / 130%)
- 經文、原文、SN 的實際值仍寫回 ps，css 變數照舊；介面 → `--ui-k` = 介面實際 / 12。啟動時 `index.js` 的 `init_fontsize_css_variable_from_pagestate` 改呼叫 `FontSize.s.applyCss()`
- localStorage `fhlFontSize` = `{ v: 2, scale, profile, link, custom }`。舊格式 (`link / ratio / custom / ui`) 由 `migrateFontSize` 轉：整體 100%、profile = ps 目前的值 + 舊的 ui，畫面完全不變；舊的我的組合補上 ui
- 分享、投影的介面設 14 (稍大)、精簡 11，其它 12

### 畫面

- 側邊欄 `字型大小: [A−] 100% [A+] ⚙`，調整體。**這一列固定大小** (`#fontSizeTool` 10pt，不乘 `--ui-k`)，否則按 A+ 時按鈕自己變大、跑走
- 字型大小移到設定的**第一項**：上面的設定項目會跟著介面變大，放在下面時按 3 下 A+，A+ 往下移了 108px；放第一項後上面只剩兩行標題 (實測 0px)
- 對話框由上而下：整體大小 (%)、情境 (預設、研讀、分享投影、精簡)、我的組合、經文、原文 SN 跟著勾選、希伯來 / 希臘 / SN、介面、預覽。滑桿與數字顯示**實際**大小；情境 chip 的 title 顯示在目前整體大小下各項的實際值

## 拿掉的

舊 `FontSizeTool` 改字型時會設 `.lec` 上下 margin `sz × 1.25 − 15` px。這只在改的當下設，換章重畫就沒了 (啟動時也不設)，是暫時性的，所以拿掉。若要「字大時節距也大」，應改成 css 用變數算。
