# 7.5.7 字型大小：分項滑桿拖曳無效、⚙ 移到最前面、視窗貼頂

## 問題

1. 字型大小視窗裡，「整體大小」滑桿拖曳有效，但「經文、希伯來文、希臘文、原文編號」分項滑桿拖曳沒效果；按 A− A+ 才會變。
2. 側邊欄那一列 `A− 100% A+ ⚙` 在左欄很窄時，⚙ 在最後面會先被截掉。
3. 視窗跳出的位置偏下，預覽時擋不到、也看不到後面的經文。

## 原因與修正

### 分項滑桿無效

`FontSize.set(key, v, isSettled)` 呼叫 `clampOf(key, v)`，這個函式在重構成「介面為基準」(docs/z261008a) 後已不存在 (只剩 `clampPt`)，每次拖曳都丟 `ReferenceError`，被事件處理吞掉，沒有任何畫面訊息。

- A− A+ 走 `step()` → `stepActual()`，不經過 `set()`，所以正常。
- 整體大小走 `setScale()` → `clampScale()`，所以正常。
- 修正：`clampOf(key, v)` 改 `clampPt(v)`。

教訓：滑桿的 `oninput` 丟例外不會有人看到；改名、刪函式後要實際拖一次。

### 按著滑桿時不重排 (針對觸控的防禦，非本次根因)

`#write(false)` 停 200ms 就存檔並 `emit(true)` (側邊欄 `FhlLecture.reshape`)。手指按著不動超過 200ms 就會重排，可能打斷觸控拖曳。

- `FontSize.isHolding`：對話框的滑桿 `pointerdown` 設 true；為 true 時 timer 到了不存、不重排。
- `pointerup` / `pointercancel` / `change` 設回 false 並 `set(value, true)` 一次生效 (有些觸控裝置不送 `change`)。

### ⚙ 放最前面

`FontSizeTool.render`：`fs-ctl` 子元素順序改成 `⚙ A− n A+`。css `.fs-gear` 改 `flex: none; margin-right: 4px`，窄的時候最後被截的是 A+，⚙ 一定看得到。

### 視窗貼頂

`FontSizeDialog.open` 的 `showDialog` 加 `position: { my: 'center top', at: 'center top', of: window }`，水平置中、top = 0。視窗高約 564px，768px 高的視窗放得下。

## 驗證

瀏覽器內以模擬事件：拖 經文 / 希伯來文 / 原文編號 滑桿，`--fontsize*` 立即變，放開後 localStorage `fhlFontSize` 的 profile 更新；按住 500ms 不存檔。沒有用真手指在 iPad 上測。
