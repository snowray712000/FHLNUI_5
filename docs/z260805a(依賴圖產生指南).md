# 依賴圖（Dependency Graph）產生指南

> 本文件示範如何為一個「無 build 工具、直接用 ES modules」的專案，產生一份給人看也給 AI 看的模組依賴圖，並讓它可以在專案有大更新時重新產生，而不需要每次都重新掃描整個 codebase。

## 情境

FHL NUI 專案（`index.html` 為入口，`index/index.js` 用 `<script type="module">` 載入）沒有 webpack/vite 這類 bundler，模組間單純用 ES `import`/`export` 互相依賴。專案裡同時存在：

- `index/*.es2023.js`：目前主要在用的模組（大多數，但不是全部都用這個命名）
- `index/*.js`（不含 `es2023` 字樣）：有些也是真正被 import 使用中的檔案，不能單靠檔名判斷
- `ijnjs/`、`ijnjs-fhl/`：核心/擴充工具庫
- `static/js/`：舊版 Vue/webpack 產物，已不再主動修改

隨著檔案越來越多，人腦已經很難單靠讀程式碼記住「誰依賴誰」，AI 每次被問到架構問題時也只能重新掃一遍檔案，浪費 token 又不保證看到全貌。

## 目標

產生一份：

1. **人看得懂**：不用裝額外軟體就能開啟、瀏覽
2. **AI 看得懂又不會太肥**：可以整份貼進 context，不會佔用大量 token
3. **可重複產生**：專案大更新後，一個指令就能重新產生最新版本，不需要重新設計流程
4. **可被 `CLAUDE.md` 之類的入口文件連結**：用連結指過去，而不是把整份圖直接寫進 `CLAUDE.md`，避免 `CLAUDE.md` 越養越肥

## 方法

用 [dependency-cruiser](https://github.com/sverweij/dependency-cruiser) 這套工具，靜態分析 JS 的 `import`/`require` 關係（**注意：這是「檔案模組」層級的依賴，不是 function/class 呼叫關係的 call graph**），輸出成 [Mermaid](https://mermaid.js.org/) 格式的文字圖：

- 存成 `docs/dependency-graph.mmd`，用連結的方式讓 `CLAUDE.md` 指過去
- 寫一個 `npm run depgraph` script，之後重新產生只需要一行指令
- 不特別篩選檔名（不只抓 `*.es2023.js`），因為有些「真正在用」的檔案沒有這個命名慣例

## 詳細細節

### 預備工具

1. 確認專案有 `package.json`（沒有的話先 `npm init -y`）
2. 確認本機有 node/npm 環境：
   ```bash
   node -v
   npm -v
   ```
3. 安裝 dependency-cruiser 為 devDependency（裝成正式 devDependency 比每次 `npx --yes` 臨時下載更好，版本固定、之後可重複使用）：
   ```bash
   npm install --save-dev dependency-cruiser
   ```

### 產生指令

在 `package.json` 加一個 script，固定住產生指令，避免每次都要重打一長串參數：

```json
{
  "scripts": {
    "depgraph": "depcruise index/index.js --no-config --output-type mermaid --output-to docs/dependency-graph.mmd"
  }
}
```

之後只要跑：

```bash
npm run depgraph
```

指令拆解：

| 參數 | 用途 |
|---|---|
| `index/index.js` | 分析的進入點（entry point）。注意：dependency-cruiser 只認 JS 模組，**不會**去解析 `index.html` 裡的 `<script src="...">`，所以要找出 HTML 裡真正用 `type="module"` 載入的那個 JS 檔案當進入點，而不是直接指定 `.html` |
| `--no-config` | 專案沒有 `.dependency-cruiser.cjs` 設定檔時，用這個略過設定檔檢查，直接用預設規則跑 |
| `--output-type mermaid` | 輸出成 Mermaid 流程圖文字格式（見「為何不生成最完整的」） |
| `--output-to` | 輸出檔案路徑 |

### 使用方法

1. **給人看**：把 `docs/dependency-graph.mmd` 的內容貼到任何支援 Mermaid 的地方即可預覽（例如 GitHub 會自動渲染 `.md` 裡的 ` ```mermaid ` 區塊、VS Code 裝 Mermaid 外掛、或貼到線上 Mermaid Live Editor）
2. **給 AI 看**：在 `CLAUDE.md`（或任何 AI 會讀的入口文件）用連結指過去，不要把整份圖內容貼進 `CLAUDE.md` 本體：
   ```markdown
   | `docs/dependency-graph.mmd` | Module import graph (mermaid)，從 index.js 進入點產生。大更新後用 `npm run depgraph` 重新產生 |
   ```
   這樣 AI 只有在真的需要了解架構時才會去讀這份檔案，平常不會佔用 context。
3. **更新時機**：
   - **需要重新產生**：新增/刪除模組檔案、模組間的 import 關係改變、大規模搬移或重構檔案結構
   - **不需要重新產生**：只是改了某個 function 裡面的邏輯，import 關係沒變的話，圖不會過時

### 為何不生成最完整的（SVG / 完整 JSON）

一開始有試過兩種更「完整」的輸出，但都不適合當作長期維護的產出：

- **SVG**：dependency-cruiser 輸出 `--output-type dot` 之後要另外用 [Graphviz](https://graphviz.org/) 的 `dot` 指令轉成圖片，這台機器沒裝 Graphviz，且多一個外部依賴、多一道轉檔手續，對「之後任何人都能重跑」這個目標是負擔。改用內建的 `--output-type html` 可以產生不需要 Graphviz 的互動式網頁圖，但檔案較大（本專案約 1MB），適合偶爾手動看一眼，不適合當作要被 AI 讀的常態文件。
- **完整 JSON**：`--output-type json` 會把每個模組的完整 metadata（路徑、規則檢查結果、orphan 標記等等）都列出來，本專案跑出來約 378KB、172 個模組。內容對「程式再加工」很有用（例如自己寫腳本抓循環依賴），但對 AI 來說資訊密度太低、太肥，不適合直接塞進 context。

結論：**Mermaid 純文字格式**在「人可讀」與「AI 好讀又精簡」之間最平衡（本專案約 9.6KB、746 行），所以最終選它。

### 為何不生成 include-only 的

一開始有試過用 `--include-only "es2023\.js$"` 只抓 `*.es2023.js` 檔名的模組，想說這樣範圍更小、更聚焦在「目前主力在用」的程式碼。但這個假設是錯的：專案裡有些檔案（例如 `AppVersion.js`、`ai_get_address_chapter.js` 等）**沒有** `es2023.js` 這個命名後綴，卻仍然是被 `index/index.js` 這條 import 鏈真正用到的程式碼。

如果用檔名 pattern 過濾，會把這些「真正有用到、只是沒照命名慣例取名」的檔案漏掉，產生一份看似乾淨、實際上失真的依賴圖 —— 這種「看起來對、實際上誤導」的文件比沒有文件更危險，尤其是給 AI 讀的時候，AI 會誤以為那些檔案不存在依賴關係。

因此最終版本**不做檔名篩選**，直接從真正的進入點 `index/index.js` 完整往下追蹤所有被 import 到的檔案，用進入點本身的「可達性（reachability）」來決定範圍，而不是用命名慣例猜測。
