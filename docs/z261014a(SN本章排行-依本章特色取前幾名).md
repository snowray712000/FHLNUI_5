# SN 本章排行：主導詞改用名次，不再用固定次數 (7.5.15 之後)

## 為什麼

「本章主導詞」原本是 `leitwort`：和合本在本章出現 ≥ N 次的實詞，N 固定 (2 / 3 / 4 / 5 / 8)。
長短不一的章節用同一個 N，數量差很多：約1 (51 節) ≥ 3 次一大串，短章 ≥ 3 次可能只剩兩三個。
TODO 裡的「SN 排序」就是這個想法：取這章排名最前面的幾個，而不是固定次數。

## 做法

- 資料不用新檔：`sn_cnt_chap_unv_min.json.gz` (`dict[tp][sn][book][chap]` = 和合本次數) 加上 `sn_pos.json.gz` (只取實詞 `n pn v a`)。
- 本章字數 `len` = 這章所有 SN 次數加總；全約字數 `all` 與各 SN 全約次數 `total` 也由同一份資料加總 (只算一次，`WeakMap` 快取)，單位一致。
  新約書卷只有 G、舊約書卷只有 H (七十士譯本在舊約書卷時沒有統計，前幾名是空的)。
- `rankLeitwort(items, {len, all}, by)` (純函式，有測試)：
  - **本章特色** `feature` (預設)：期望次數 `E = len × total / all`，分數 `c × ln(c / E)`。次數高過期望才有分數。
    εἰμί、λέγω、καί 這種到處都是的字 `c` 接近 `E`，分數低；少見但在這章反覆出現的 (約15 常在 μένω、果子、恨；得1 回 שׁוּב；拿1 約拿、海、大) 排前面。
  - **次數** `count`：`c` 由多到少，同次數依特色。
  - 只出現 1 次的不算 (c ≥ 2)；特色分數 0 的不進 feature。
- `topOfRanking(ranked, k, by)`：前 k 名，並列的一起算進來。
- `SnFilter`：`cfg.leitTop` (0 = 不用，與 `leitwort` 並列，同樣「符合任一就顯示」)；`leitBy` 是全域一個 (排行榜與前幾名共用，存 localStorage `snFilter`)；`chapterRanking()` 依章快取；`#leitTopSet` 取前 k 名 (資料沒載入回 null，不快取，載好後 `applyAll`)。
- 讀經組合「本章主導詞」(`leit`) 改為 `leitTop: 5`，說明檔 `docs/SN讀經組合說明.md` 同步。「≥ N 次」仍在細項的下拉選單。

## 介面

SN 篩選對話框：
- 細項的本章主導詞一列：下拉 `不用 / 前 3、5、8、10、15 名 / ≥ 2 … 8 次`，旁邊 `依本章特色 / 依次數`。
- 「本章排行」(可收合，預設展開)，放在「其它的 SN」與「字上色」之間：名次、SN、字、長條、本章次數 (游標停上去看全約次數)、＋ / −。
  - 列的顏色就是目前設定的樣子 (`SnFilter.snSource`)：藍 = 符合規則 (前 N 名、預設組合…) 而顯示；紅 = 「另外加」；灰 = 不顯示；灰加刪除線 = 排除。設前 3 名，前 3 列藍、其餘灰，一眼看出現在設幾個。動詞形態是每個字各自判斷，不算在顏色裡。
  - 按鈕 (`SnFilter.setSnShown`)：顯示中的是 −，按了變「不要」：從另外加拿掉，規則仍會顯示它就加進排除 (前 3 但排除這個)；沒顯示的是 ＋，按了變「要」：從排除拿掉，規則不會顯示它就加進另外加 (前 3 再加這個)。
  - 「顯示 SN」不是「只顯示指定的」時，排行榜下方提示並可一鍵改過去 (否則按了經文沒變化)。
  - 點一列：用 `SN_Act_Color` 標出 (同滑鼠移過去的紅色)，並捲到第一個可見的位置，再點跳下一個。
  - 字從畫面 `#lecMain .sn-text:not(.sn)` 抓 (最常見的兩種寫法)；SN 關閉時畫面沒有 SN，字欄是空的 (只有 SN 代碼)。
  - 換章時 `MutationObserver` 看 `#fhlLecture`，400ms 後只重畫排行榜 (`#renderRank`)，不動上面的設定。
