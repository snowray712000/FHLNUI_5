# SN 本章排行：窄視窗欄位收緊與清單撐滿 (7.6.2.2)

## 問題

SN 對話框「本章排行」的每一列是 CSS grid：`序號 / SN / 字 / 藍條 / 次數 / ＋−`。

1. 對話框窄 (使用者把右側工具面板拉窄) 時，藍條欄固定 6em，字欄最少 3em，總寬超出，列表出現橫向捲軸，最右邊的次數與 ＋ / − 被推出畫面，使用者完全不知道還有這兩欄。
2. 欄與欄的空白 (gap 0.5em、序號欄 2em、SN 欄 5em) 在窄時太浪費。
3. 「實詞，和合本的次數…」「依下面的名次顯示…」「藍 / 紅 / 灰」三段說明在窄時佔位，而且 `?` 已有說明。
4. 清單 `max-height: 16em` 固定，對話框高 (預設視窗 90%) 時下方留一大片空白。

## 做法 (`index/fhl.css`、`index/SnFilterDialog.es2023.js`)

- **藍條先縮**：欄寬改 `2em 5em minmax(2em, 1fr) minmax(0, 6em) 3em 1.8em`。grid 先讓字欄保有 2em，剩下的給藍條，不夠就縮到 0；次數與 ＋ / − 是固定欄，一直露出。`.snf-rk-list` 加 `overflow-x: hidden`，不再出現橫向捲軸。藍條只是美化，沒有它也行。
- **窄版收緊**：`.snf-rank` 設 `container-type: inline-size`，`@container (max-width: 30em)` 時欄寬改 `1.3em 3.6em minmax(2em, 1fr) minmax(0, 4em) 2em 1.3em`、gap 0.2em、列內距 0。用 container query 而不是 media query，因為這個對話框的寬度跟視窗寬度無關 (可拖、貼在右側面板)。
- **說明文字**：移除「實詞，和合本的次數；特色 = …」那行 (`?` 的說明已涵蓋)；「依下面的名次…」與圖例加 `.snf-rk-hint`，同一個 container query 內 `display: none`。選擇器要寫 `.snf-dlg .snf-rank .snf-rk-hint`，否則圖例後面的 `.snf-rk-legend { display: flex }` 同權重會蓋掉。「沒有藍條」直接用 30em 近似，不去偵測藍條實際寬度。
- **清單撐滿**：去掉固定 16em。`.ui-dialog-content:has(> .snf-dlg > .snf-rank)` 變 flex column，`.snf-dlg` → `.snf-rank` → `.snf-rank-body` → `.snf-rk-list` 一路 `flex: 1; min-height: 0`，清單最矮 6em。

## 踩到的

- 先試 `.snf-dlg { height: 100% }`：`.ui-dialog-content` 是 `.dlg-fluid` 的 flex 子項，百分比高度沒有解成定值，`.snf-dlg` 仍長到內容那麼高 (835px，內容區只有 695px)，清單沒縮；要讓內容區自己 flex 才行。
- 本章排行以外的分頁 (組合 / 細項) 沒有 `.snf-rank`，`:has()` 不會套到，維持原本捲動。

## 驗證

瀏覽器開 約12，拉窄右側面板：藍條縮短到消失、次數與 ＋ / − 還在、說明隱藏；對話框拉高時清單跟著變高。沒有加單元測試 (純 CSS)。
