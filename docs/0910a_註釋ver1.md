# 功能逆向分析

我要你針對既有專案中的一個功能，進行 **feature-by-feature reverse engineering（逐功能逆向分析）**。

目標不是重構程式碼，也不是提出新的架構，而是：

- 從現有程式碼反推出這個功能實際如何運作
- 找出它的入口、主要流程、資料流、狀態、UI 更新與外部依賴
- 區分目前仍在運作的程式碼、可能已廢棄的程式碼，以及無法確認的部分
- 最後整理成一份可以供未來重構或重新實作使用的功能規格

請以「現有程式碼證據」為主要依據，不要因為某種設計看起來合理，就假設原系統一定如此。

# 2. 我認為這個功能的目的

我目前理解這個功能主要是：

> [請填寫]
- > 註釋資料，是由 信望愛 核心成員查經漸漸型成。
  - > 以單一書卷的為例，其完整資料在這 [a2z.fhl.net](https://a2z.fhl.net/php/pcom.php?book=3&engs=Jude)
- > 後來為了能夠被 app 被整合，將書卷切割為 api，公開使用。
  - 完整 api 在此。 https://bible.fhl.net/json/
  - 其中 註釋 資料，是使用 sc.php。
  - 注意，註釋 資料，一定是 book=3。
    - 注意，這個 book 是指注釋書代號，與程式中 book 語意用作書卷代號不太一樣，程式中 book 大多時候是指 「創世記」 就是 1，
  - 例子
    - 猶大書，當閱讀到 1:1 時
      - https://bible.fhl.net/json/sc.php?book=4&engs=Jude&chap=1&sec=1&gb=0
- 範圍
  - 註釋 資料，屬於 範圍型的。
  - 例如，猶大書，1:1， query 後，得到的其實是 1:1-1:2。
    - 也就是說，query 1:1 與 1:2 的結果會是完全同一筆資料
  - 範圍並非一定同樣長度
- 書卷背景
  - 書卷背景，通常傳入的就是 0 章 0 節。算是特別的參數
- 內容 是個 純文字
  - 信望愛 發展，是在 bbs 發展年代興起。因為網路速度非常慢，所以當代流行的是純文字時代，所以早期整理的資料，其實並非如現代的 word 或是 markdown 方式。所以
    - 資料排版，有很多空白 - 為了縮排、凸排
    - 例如 
      - `●家「譜」：SNG00976，「書卷」、「紀錄」。\r\n      ●「家譜」：SNG00976+SNG01078，「世系紀錄」、「家譜的記錄」或「歷史的記\r\n                  錄」、「起源」，此字就是七十士譯本「創世記」的標題。七十士\r\n                  譯本的#創 2:4;5:1|也出現這個字。\r\n      `
      - 按現代呈現應該會是
      - `●家「譜」：SNG00976，「書卷」、「紀錄」。\r\n●「家譜」：SNG00976+SNG01078，「世系紀錄」、「家譜的記錄」或「歷史的記錄」、「起源」，此字就是七十士譯本「創世記」的標題。七十士譯本的#創 2:4;5:1|也出現這個字。`
- 內容 是 list 為主
  - 與文章不同，當時的資料，除了「背景」的說明比較像是「一般的文章 - 段落式的描述」，查經資料內容，多半是清單式的。(其實就跟這份文件差不多)
  - 承上，因此可能內容可能會看到
    - 零 壹 貳 ... 一 二 三 ... 1 2 3 ... 
      - 到時候看程式碼就能看到
    - ● ◎ ☆ ○
- 內容 可能包含 原文 (Strong Number，或簡稱 SN)
  - 例如，馬太福音 1:1，就是個好例子
    - 其回傳中的文字，局部為 `●「基督」：SNG05547，「受膏者」之意，等同於希伯來文「彌賽亞SNH04899」。`
      - SNG05447，就是 Greek Strong Number 5447
      - SNG04899，就是 Hebrew Strong Number 4899
    - 此例，可以知道，新約的註釋內容，並非只會出現 Greek Strong number，也可能會有 Hebrew strong number。
    - 此例 api
      - https://bible.fhl.net/json/sc.php?book=3&engs=Matt&chap=1&sec=1&gb=0 
- 內容 可能包含 `交互參照` (或稱為 `經文參照`)
  - 仍然以，馬太福音 1:1 的內容為例
    - 局部回傳資料 `壹、序言：君王的誕生 #1:1-2:23|\r\n  一、耶穌的家譜 #1:1-17|\r\n      ○#路 3:23-38|`
    - `#1:1-2:23|` 與 `#1:1-17|` 與 `#路 3:23-38|` 與 `#代上 3:17-19;申 25:5-10|` 都是 交互參照的 字眼。
  - 注意，交互參照，信望愛有明確的格式
    - `https://bible.fhl.net/new/allreadme.html`
  - 另外，若 交互參照 沒有指定 書卷，就是「目前 address 的「書卷」或「章」
    - 例如
      - `#1:1-17|`，因為這是 馬太福音1:1 為參數的，所以這裡指的是 `太1:1-17`。
      - `#1:1;路3:23`，其實就是 `太1:1;路3:23`
- 內容 可能包含 `表格`
  - 非常少，但存在。例如，列王記上背景

如果有使用者操作流程，也可以簡單描述：

- > [請填寫]
- 一般情境
  - 閱讀某段經文時，會有 activate address 概念。例如，click 猶大書 1:1 經文時，就有一個 div 會去自動抓對應的內容，然後經過轉換，呈現結果。

      - 跳出 SN 字典
    - 交互參照

      - 方式2 跳出方塊直接顯示經文
      - 方式3 提供 2 種選項
      - (依設定值決定會怎麼作)
- 後一段、前一段 註釋
  - 呈現的界面，會有 ui 可以點擊，跳至 前一段 或 後一段 的註釋
  - 例如，本次是 猶大書1:3-4
    - 前一段，即跳至 1:1-2
    - 後一段，即跳至 1:5-7
  - 特例
    - 若目前是「第一段」，再往前一段，就會跳至「背景」。

    - 若目前是「書卷的最後一段」，點擊「後一段」，不會有效果。

      - 此時若按「上一段」或「下一段」
        - 就會回傳「第一段」
      - 此時若按「返回」，就會回到剛剛那一段
