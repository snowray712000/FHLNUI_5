前言

這資料是純文字資料，是早期年代所寫。甚至縮排都是靠著空白鍵做的。所以要整合的話，要前處理。只用 pre tag 處理的話，但很醜，樣式也不一致。

我覺得在程式處理上
- 不是直接想「怎麼畫」
- 而是先想「怎麼存成中繼資料」
- 想像它是有 parent children 結構，到時候再用 unordered list 之類的畫出來。

目前我風險與挑戰有
- 縮排是空白鍵
- 空白鍵數量不一致
- 項目符號不能假設是第幾層

空白種類
- 空白符號，有三種空白。
- 第 1 種: 一種是縮排而有的空白。
- 第 2 種: 一種是文字很長，換行，但為了排版而有的空白。
- 第 3 種: 一種是文內的空白
- 例子1
  - 例如 `            (2)父的計畫  #5:20-23| `
  - 此例 (2) 的前面，就是第 1 種，而 計畫 與 #5:20-23| 之間的空白，就是第 3 種。
- 例子2
    - 例如 `               ◎此處耶穌慎重的說明自己做這些「衝撞傳統」的事情，並非是自\r\n                 發的，而是看到上帝的作為，才跟著去做。\r\n            (2)...`
    - ◎ 前面的空白與 (2) 前面的空白，都是第 1 種，而 自 與 發 中間的換行與空白，就是第 2 種。

流程(目前)
- 要先移種 第 2 種空白
- 再使用第 1 種空白，判斷縮排層級
- 產生 parent children 結構的中繼資料，此時就可以去除 第 1 種空白了。
