這卷《啟示錄》的註釋資料非常有價值，它展現了比之前更複雜的巢狀結構（Nesting），特別是在神學觀點的辯證（如千禧年論立場）以及七教會的結構化分析中。

我已完成驗證，並發現以下新特徵需要更新到規則檔中：

### 驗證與發現摘要

1. **更深的英數層級 (Deep Alphanumeric Nesting)**：
* 在第 20 章關於「千禧年」的討論中，出現了 `A.` -> `(a)` -> `a.` 的結構。這打破了原本對 `A.` 和 `a.` 的簡單假設。
* **修正**：需要擴充層級定義，將 `(a), (b)` 納入 `Lvl_5` 或 `Lvl_6`，並確認 `A.` (大寫) 的權重高於 `a.` (小寫)。


2. **跳級結構 (Hierarchy Gapping)**：
* 在「四、特徵」之後，直接接了 `(1)`。
* **修正**：解析器不能強制要求連續層級（不能要求 `Level 1` 下面一定要是 `Level 2`）。如果 `Level 1` 下面出現 `Level 5` 的符號，應直接視為其 Child。


3. **隱性標題的變體**：
* 七教會的結構大量使用了「隱性鍵值」，如 `(1)基督自稱：`。這其實是 `Type A (有序)` 與 `Type C (隱性)` 的混合體。
* **修正**：當一行同時具備「序號」與「冒號結尾」特徵時，優先視為 `Type A`（List Item），但內容應保留冒號前的標籤意義。


4. **ASCII 表格的確認**：
* 文件中包含複雜的表格（如七印、七號比較表）。
* **確認**：現有的 `Type D` 規則足以捕捉，但需要確保表格內的文字不會被誤判為清單項目。

這份文件記錄了處理中文聖經研經資料（Legacy Text）的解析邏輯。

#### 1. 行類型定義 (Line Types)

程式讀取每一行時，應優先判斷該行屬於哪種類型：

* **Type A: 明確層級 (Explicit Hierarchy)**
* 特徵：以「有序符號」開頭。
* 層級權重（Stack Hierarchy）：
* `Lvl_0`: `^零、|^壹、|^貳、...` (大寫數字 + 頓號)
* `Lvl_1`: `^一、|^二、|^三、...` (中文數字 + 頓號)
* `Lvl_2`: `^（[一二三四五六七八九十]+）` (括號中文數字)
* `Lvl_3`: `^\s*\d+\.` (數字 + 點，如 `1.`)
* `Lvl_4`: `^\s*[A-Z]\.` (大寫字母 + 點，如 `A.`)
* `Lvl_5`: `^\s*\(\d+\)` (括號數字，如 `(1)`)
* `Lvl_6`: `^\s*\([a-z]\)` (括號小寫字母，如 `(a)`)
* `Lvl_7`: `^\s*[a-z]\.` (小寫字母 + 點，如 `a.`)




* **Type B: 標記項目 (Symbol Item)**
* 特徵：以「無序符號」開頭。
* 符號：
* `●` (Exegesis/Definition): 經文註釋或字義解釋。
* `◎` (Reflection): 感想、應用或神學討論。
* `○` (Cross-ref): 相關經文。
* `☆` (Note/Meta): 特殊註記或補充資料（有時作為 Parent 出現）。


* 行為：通常作為當前 `Type A` 的 Child。


* **Type C: 隱性鍵值 (Implicit Key-Value)**
* 特徵：無上述符號，但具有 Metadata 性質。
* Pattern: `^\s*(時間|地點|人物|原因|特徵|背景|作者|受書人)：` (以冒號結尾的特定關鍵詞)。
* 行為：視為一個 List Item，層級通常等同於當下的 `Lvl_1` 或 `Lvl_2`。


* **Type D: 表格區塊 (Table Block)**
* 特徵：包含製表符號 `┌`, `─`, `│`, `└`, `├`, `┤`, `┴`, `┬`。
* 處理：
* 進入 `Raw Block Mode`。
* **忽視**區塊內任何看似清單的符號（如 `1.` 或 `A.`），直到表格結束。
* 表格結束通常由連續的空白行或新的 `Type A/B` 觸發。




* **Type E: 延續內文 (Content Continuation)**
* 特徵：不符合 A, B, C, D 且不是空行。
* 判斷邏輯（關鍵）：
* 若本行縮排（Indentation） `>=` 上一行有效內容的起始位置 -> **合併 (Concat)**。
* 若本行縮排明顯少於上一行 -> 視為新段落或層級錯誤（需記錄 Error Log，但在 Legacy Data 中通常視為上一層的 Sibling）。





#### 2. 解析策略 (Parsing Logic)

* **堆疊管理 (Stack Management)**
* 維護一個 `Stack` 記錄當前的 Path，例如 `[Lvl_1, Lvl_3, Type_B]`.
* **跳級處理 (Gap Jumping)**：
* 如果當前是 `Lvl_1` (一、)，下一行出現 `Lvl_5` ((1))。
* **不要** 補齊中間的 2, 3, 4 層。
* 直接將 `Lvl_5` Push 進 Stack，視為 `Lvl_1` 的直接 Child。
* 邏輯：`Parent = Stack.peek()`。




* **符號的浮動性 (Floating Symbols)**
* `Type B` (`●`, `◎`) 通常是 Leaf Node（葉節點），但有時會包含 Child。
* 例外：若 `●` 下面出現 `a.` 或 `(1)`，則 `●` 升級為 Parent Node。


* **混合型處理 (Hybrid Patterns)**
* 若遇到 `(1)基督自稱：`，同時符合 `Type A (Lvl_5)` 和 `Type C (Pattern)`。
* **優先級**：視為 `Type A` (List Item)，文字內容包含冒號。
