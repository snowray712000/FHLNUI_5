這份 `full_texts4.txt`（包含申命記、雅歌、以西結書、但以理書、何西阿書、撒迦利亞書）的資料非常關鍵，它幫助我們確立了舊約筆記中**不同於一般學術格式的獨特層級**，並引入了「劇本式」的對話結構。

### 驗證與發現摘要

1. **確立「反直覺」的層級權重：`(1)` > `a.**`
* **發現**：在以西結書 1:4-14 和但以理書 9:20-27 中，結構明確呈現為 `1.` -> `(1)` -> `a.`。
* **分析**：一般學術格式（如 Turabian）通常是 `1.` -> `a.` -> `(1)`。但這位作者的習慣將 `(1)` 視為比 `a.` 更高（或更外層）的層級。
* **結論**：目前的規則權重 `(1)` (70) < `a.` (80) 是**正確的**，必須堅持這個設定，否則結構會亂掉。


2. **劇本式對話標籤 (Script-like Dialogue Labels)**
* **發現**：在《雅歌》中，大量出現如 `女主角：`、`眾女子：`、`新郎：` 的行首。
* **分析**：這不屬於原本定義的 `Type C`（Metadata 關鍵字），而是「發言者標籤」。
* **修正**：需擴充 `Type C` 的定義，允許捕捉「短中文詞彙 + 冒號」的格式。


3. **無冒號的標題**
* **發現**：出現 `標題 1:1` 這樣的行。
* **修正**：這應視為特殊的 Metadata 行。

以下是更新後的 **Parsing Rules (Ver 5.0)**。這份規則針對「劇本式對話」與「作者獨特層級」進行了最終調校。

### 檔案：parsing_rules5.md (Ver 5.0)

這份文件記錄了處理中文聖經研經資料（Legacy Text）的解析邏輯，包含劇本式對話與舊約特有格式。

#### 1. 行類型定義 (Line Types)

程式讀取每一行時，應優先判斷該行屬於哪種類型，並依據 **權重 (Weight)** 決定層級：

* **Type A: 明確層級 (Explicit Hierarchy)**
* 特徵：以「有序符號」開頭。
* **通用權重順序 (Hierarchy Weight)**：
* *(數字越小，層級越高)*
* `10` : `^零、|^壹、|^貳、...`
* `20` : `^一、|^二、|^三、...`
* `25` : `^第[一二三四五六七八九十]+(回合|次|輪)`
* `30` : `^（[一二三四五六七八九十]+）`
* `35` : `^\s*[IVX]+\.` (羅馬數字)
* `40` : `^\s*[A-Z]\.` (大寫字母)
* `50` : `^\s*\d+\.` (阿拉伯數字)
* `60` : `^\s*\([A-Z]\)` (括號大寫字母)
* **`70` : `^\s*\(\d+\)` (括號數字)** *(注意：作者習慣將 (1) 置於 a. 之上)*
* **`80` : `^\s*[a-z]\.` (小寫字母)**
* `90` : `^\s*\([a-z]\)` (括號小寫字母)




* **Type B: 標記項目 (Symbol Item)**
* 特徵：以「無序符號」開頭。
* 符號：
* `●`, `◎`, `○`, `☆`, `★` (標準符號)
* `^\s*-\s+` (短橫線清單)
* `^\[.*\]` (方括號標題，如 `[背景註釋]`)


* 行為：預設為 Leaf Node，若後續有更深縮排的 Type A，則升級為 Container。


* **Type C: 鍵值與對話 (Key-Value & Dialogue)**
* 特徵：具有「標籤」性質的行。
* **Pattern 1 (Metadata)**: `^\s*(時間|地點|人物|原因|特徵|背景|作者|受書人|寫作目的|主題|經文|結論|標題).*`
* *註：`標題` 可能沒有冒號，需特殊處理。*


* **Pattern 2 (Speaker/Dialogue)**: `^\s*([\u4e00-\u9fa5]{2,10})：`
* *解釋：捕捉 2-10 個中文字元後接冒號的行（如 `女主角：`），排除網址或時間格式。*


* 行為：視為 List Item，冒號前為 Key，後為 Value。


* **Type D: 表格區塊 (Table Block)**
* 特徵：包含 `┌`, `─`, `│` 等製表符。
* 處理：Raw Text Mode。


* **Type E: 延續內文 (Content Continuation)**
* 特徵：非 A/B/C/D。
* 判斷：若縮排 >= 上一層級，合併至上一行；否則視為無符號的 Sibling 段落。



#### 2. 核心解析邏輯 (Logic Refinements)

1. **相對層級優先於絕對層級**：
* 雖然定義了權重，但解析器應具備「容錯性」。若 Stack Top 是 `1.` (50)，來了一行 `a.` (80)，入棧。若下一行是 `(1)` (70)，依權重應出棧 `a.`，這符合資料邏輯。
* **重要規則**：若遇到 `Type B` (`●`)，它通常「重置」其下的數字層級。例如 `●` 下面出現 `1.`，該 `1.` 是屬於 `●` 的 Child，不受 `●` 外部的 `1.` 影響。


2. **合併斷行 (Concatenation)**：
* 針對《雅歌》等詩歌體裁，可能會有較多「排版性換行」。
* 若一行判定為 `Type E` 且縮排與上一行相同，應優先視為同一句的延續，中間補一個空白即可。


3. **劇本模式 (Script Mode)**：
* 當檢測到連續的 `Type C (Pattern 2)` 時（如對話錄），應將這些項目視為同一層級的 List Items。
