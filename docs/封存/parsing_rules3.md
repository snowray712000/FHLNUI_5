這份 `full_texts2.txt`（包含創世記、哥林多前書、以弗所書、歌羅西書、彼得後書、猶大書）提供了非常關鍵的結構變體，特別是在**英文字母層級**的使用上。

最重要的發現是：**這份資料證實了「雙軌制」的層級混用**，且發現了新的層級符號 `(A)` 和 `★`。

### 驗證與發現摘要

1. **英文字母的完整巢狀結構 (The "Alphabet" Hierarchy)**：
* 在《猶大書》和《以弗所書》中，出現了完整的英文層級：
`A.` -> `(A)` -> `a.` -> `(a)`
* **修正**：原本規則中只有 `A.` 和 `a.`，且順序未定。新資料證實了 `(A)` 的存在，且確立了 `a.` 是 `(a)` 的 Parent（與原本規則 `(a)` > `a.` 的假設相反）。


2. **新符號 `★**`：
* 在《以弗所書》6:10 出現：`★保羅的「末了的話」....`。
* **修正**：需將 `★` 加入 `Type B`（無序符號）列表，地位等同於 `☆`。


3. **層級跳躍與混用**：
* 有些書卷（如歌羅西書）用 `1.` -> `(1)` -> `a.`。
* 有些書卷（如猶大書）用 `A.` -> `(A)`。
* **結論**：Parser 不能預設「所有書卷都用同一套層級」，而是要在該書卷內保持「相對一致性」。


4. **括號數字的縮排陷阱**：
* 有些 `(1)` 的縮排非常深，有些則很淺。這再次確認了**「不能只靠縮排空白數」**，必須依賴**「符號權重 + 堆疊相對性」**。

以下是更新後的 **Parsing Rules (Ver 3.0)**。

### 檔案：parsing_rules3.md (Ver 3.0)

這份文件記錄了處理中文聖經研經資料（Legacy Text）的解析邏輯，針對多卷書混合的複雜情況進行了優化。

#### 1. 行類型定義 (Line Types)

程式讀取每一行時，應優先判斷該行屬於哪種類型：

* **Type A: 明確層級 (Explicit Hierarchy)**
* 特徵：以「有序符號」開頭。
* **通用權重順序 (Hierarchy Weight)**：
* *(註：權重越小越上層。)*
* `10` : `^零、|^壹、|^貳、...` (大寫數字)
* `20` : `^一、|^二、|^三、...` (中文數字)
* `30` : `^（[一二三四五六七八九十]+）` (括號中文數字)
* `40` : `^\s*[A-Z]\.` (大寫字母, 如 `A.`) *註：有時作為最高層級，視上下文而定*
* `50` : `^\s*\d+\.` (阿拉伯數字, 如 `1.`)
* `60` : `^\s*\([A-Z]\)` (括號大寫字母, 如 `(A)`) **[NEW]**
* `70` : `^\s*\(\d+\)` (括號數字, 如 `(1)`)
* `80` : `^\s*[a-z]\.` (小寫字母, 如 `a.`) **[Reordered]**
* `90` : `^\s*\([a-z]\)` (括號小寫字母, 如 `(a)`) **[Reordered]**




* **Type B: 標記項目 (Symbol Item)**
* 特徵：以「無序符號」開頭。
* 符號：
* `●` (Exegesis): 經文註釋。
* `◎` (Reflection): 感想、應用。
* `○` (Cross-ref): 相關經文。
* `☆` (Note): 註記。
* `★` (Emphasis): 強調/特殊段落 **[NEW]**


* 行為：預設為 `Stack.peek()` 的 Child。


* **Type C: 隱性鍵值 (Implicit Key-Value)**
* 特徵：`^\s*(時間|地點|人物|原因|特徵|背景|作者|受書人|寫作目的|主題|經文)：`
* 行為：視為 `Type A` 的變體，層級通常隨依附的父節點而定。


* **Type D: 表格區塊 (Table Block)**
* 特徵：包含 `┌`, `─`, `│`, `└`, `├`, `┤`。


* **Type E: 延續內文 (Content Continuation)**
* 判斷：非 A/B/C/D，且縮排位置顯示為上一行的延續。



#### 2. 核心解析邏輯 (Core Parsing Logic)

針對 `full_texts2.txt` 中出現的複雜結構，採用 **"Adaptive Stack" (自適應堆疊)** 策略：

1. **路徑堆疊 (Path Stack)**：
* 堆疊中儲存物件：`{ type, level_weight, raw_content, children }`。
* `level_weight` 參考上方 Type A 的數值。


2. **入棧規則 (Push Rule)**：
* 若 `Current_Line.weight` > `Stack.Top.weight`：
* 視為 **Child**。Push 入棧。


* *例外*：若中間跳過了數層（例如從 `一、` 直接跳到 `1.`），允許跳級，直接視為 Child。


3. **出棧規則 (Pop Rule)**：
* 若 `Current_Line.weight` <= `Stack.Top.weight`：
* 持續 Pop，直到找到一個節點其權重 `<` 當前行，或者堆疊為空。
* 將當前行加入該節點的 Children，並將當前行 Push 入棧。


* *同級判斷*：若權重相同，視為 Sibling（Pop 當前 Top，Push 新的）。


4. **英數混用處理 (Alpha-Numeric Interleaving)**：
* 觀察到 `A.` (40) 和 `1.` (50) 的關係不穩定。
* **策略**：若 `A.` 出現在 `1.` 之下，則在該區塊內，暫時將 `A.` 的權重視為 `55` (即視為 Child)。這需要一個 `Context_Flag`，但目前的資料多數遵循 `A.` > `1.` 或 `1.` > `a.`，衝突不大。主要遵循 `a.` (80) > `(a)` (90) 的新順序。



#### 3. Regex 更新

* `Re_Lvl_Upper_Paren`: `^\s*\([A-Z]\)`  (Captures `(A)`, `(B)`)
* `Re_Type_B`: `^\s*[●◎○☆★]` (Added `★`)
