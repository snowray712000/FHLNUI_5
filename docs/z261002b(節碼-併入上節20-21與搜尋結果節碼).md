# 節碼：併入上節顯示「20-21」；搜尋結果格內加節碼

7.0.8 (2026-10-02)。處理 app_versions.json TODOs 的兩項 (A、B)，都跟節碼有關，一起處理。

## 一、qsb.php 怎麼表示「併入上節」

例如和合本 西2:20-21 譯成一節。qsb.php 仍回傳 sec=21 這一筆，但 `bible_text` 只有一個字 `"a"`：

```json
{"chineses":"西","engs":"Col","chap":2,"sec":21,"bible_text":"a"}
```

`strong=1` 也一樣是 `"a"`。其它譯本 (例 KJV) 21 節照常有經文。經過 `cvt_others` 後 dtexts 是 `[{ w: 'a' }]`。

## 二、共用的判斷 (index/VerseGrid.es2023.js)

經文區、交互參照、搜尋結果三處原本各寫一份 `dtexts.length == 1 && dtexts[0].w == 'a'`，改成共用：

| 函式 | 用途 |
|------|------|
| `isMergedWithPrev(dtexts)` | 這節是不是併入上節 (`"a"`) |
| `extendVerseLabel(label, sec)` | 上一節節碼延伸：`'20'` → `'20-21'`，`'20-21'` → `'20-22'` |
| `mergedPlaceholderDTexts()` | 沒有上一節可延伸時，格內顯示灰色「（併入上節）」(`.vg-merged`) |

`renderVerseLec` 的節碼一律用 `generate_verse_number_jdom(label, version)` 產生 (以前 label 不等於 sec 時直接 `.text()`，bhs 會少了 `‏`)。

`.vg-merged` 的灰色從 `Search.css` 移到 `fhl.css` 的 `.verse-grid .vg-merged` (交互參照也用)。

## 三、各處的處理

### 經文區 (index/lecture/FhlLecture_render_core.js)

`build_view_model` 本來就會把上一節的 `verseLabel` 改成 `20-21`、本節留 placeholder (`hideVerseContent`)，並排 grid 時上一段 `grid-row: r / span 2`。

**bug**：「上一節」是 `verses[verses.length - 1]`，只在同一段內找。mode 1/2 是一節一段 (假分段)，21 節自成一段，找不到 20 節 → 節碼還是「20」。mode 3/4 若 21 節剛好是新段落的第一節也一樣。

**修正**：每個譯本記 `lastReal` (上一個真的節)，跨段也能延伸。

另外 mode 2 (交錯) 整段都是 placeholder 時原本仍產生一個空的 `.paragraph`，現在略過 (並排的 `render_grid` 本來就略過)。

### 交互參照 (index/queryReferenceAndShowAtDialogAsync.es2023.js)

同一組 (連續的節) 內本來就會延伸上一節。新增：這組從併入上節的那節開始 (例 `#西2:21-22|`)，以前那格是空的，現在顯示「（併入上節）」。

### 搜尋結果 (index/SearchDialog_es2023.js `toVerseRowsAsync`)

- **A：格內加節碼**。以前 `hideVerseNumber: true` (標籤欄已有經文位置)，複製對照表時搜尋結果沒有節碼，與經文區、交互參照不一致。現在與交互參照相同：左側標籤欄 + 格內節碼。
- 併入上節的那格：只寫「（併入上節）」，不加節碼。
- 同一批有取到下一節、而且是 `"a"` → 節碼 `20-21` (可連續延伸)。
- **限制 (決定不處理)**：搜尋結果只取搜到的節。只搜到 20 節、沒有 21 節時，不知道 21 併入了 20，節碼只顯示「20」。要補得每節多取下一節，資料量約兩倍，不值得。
