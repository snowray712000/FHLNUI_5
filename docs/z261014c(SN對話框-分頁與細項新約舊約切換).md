# SN 篩選對話框：分頁、細項的新約 | 舊約切換 (7.5.16.3)

## 為什麼

對話框把所有東西疊在一起：顯示模式、讀經組合、我的組合、其它的 SN、本章排行 (可收合)、字上色、細項設定 (可收合，新約、舊約兩大塊)。細項一展開就很長，手機要一直捲；本章排行與主導詞設定又分在兩個地方。

## 做法 (`SnFilterDialog.es2023.js`)

三個分頁 (分段按鈕 `.snf-tabs`，手機寬度各約 1/3，手指時高度不低於 `--touch-min`)：

| 分頁 | 內容 |
|---|---|
| 組合 (預設) | 顯示 SN、讀經組合、我的組合、其它的 SN (隱藏 / 變淡)、字上色 |
| 本章排行 | 本章主導詞規則 (`不用 / 前 N 名 / ≥ N 次`)、依本章特色 / 次數、排行榜 |
| 細項 | 新約 \| 舊約 切換，該約的詞類、動詞形態、另外加、排除、含未譯出的 `{<…>}`、顯示時態碼 |

- 只畫目前的分頁 (`#tab`)；`#rankBox` 只在排行分頁存在，`#renderRank` 對 `null` / 未接上 DOM 直接返回，所以換章時的 `MutationObserver` 不用拆。
- 最後停的分頁存 localStorage `snfTab`，下次開回到那裡；切分頁後 `dialog('option', 'position', …)` 重新定位 (高度變了)。
- **主導詞規則搬到排行分頁**：列的顏色就是它的結果，同一頁改、同一頁看。它編輯的是「正在讀的書卷所屬的約」(新約書卷改 G、舊約改 H)，換書卷時隨 `#renderRank` 一起重畫；另一約的規則由讀經組合設定。細項分頁不再有這一列。
- **細項的新約 | 舊約**：不拆成兩個分頁。預設是正在讀的那一約 (`#detailTp = null`)，使用者切過就固定到對話框關閉；旁邊一行說明 (「目前讀的是這一約」/「…這裡改的是舊約的設定」)。
- 「另外加」「排除」框一次只有一約：框裡寫了另一約代碼 (例在新約框貼 `H3068`) 會加進另一約的清單，不會被丟掉 (`#onSnsInput(boxes, tp, prop, isRewrite)`)。
- 讀經組合、我的組合仍同時套用新約與舊約，不受切換影響。
- **內建組合亮不亮 (`SnFilter.activeLensId`)**：「前幾名」是參數，不是組合的身分。套用「本章主導詞」(前 5 名) 後在排行分頁改成前 3 名，回「組合」分頁它仍亮著 (比較內建組合時 `leitTop` 只看有沒有用)；改成「≥ N 次」或不用就不再亮。「我的組合」仍是完全相同才亮，且優先。

## 前 N 名有並列時 (測試時的誤會)

前 3 名改前 5 名、前 5 名改前 3 名看起來「沒變」：第 3 名有好幾個字同次數，並列的一起算進來 (`topOfRanking`)，兩種設定剛好都顯示 5 個。排行分頁現在會在設定列下方提示「前 3 名中有並列，實際顯示 5 個」。

## 沒做 / 之後

- 四個分頁 (字上色獨立) 不做：字上色只有一列加圖例，放組合分頁就夠。
- 分頁沒有鍵盤左右鍵切換 (`role="tablist"` 只標了語意)。
