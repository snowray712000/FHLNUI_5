**Parsing／原文分析**：顯示目前經節的聖經原文、原文直譯，以及逐詞的詞性與字彙分析。

主要 API 線索為 `qp.php`（作者稱 qp 為 query parsing）。參考網址供後續分析時查核，本次整理未驗證線上內容：

### 3.2 新約、舊約與原文／直譯配對

作者提供：希臘文靠左、由左至右；希伯來文靠右、由右至左；中文由左至右。希臘文與希伯來文各有獨立字型大小設定，設定來源與套用位置待查。

- 希臘文樣本（太 1:2）：按換行拆分後，原文與直譯逐行配對。例如 `Ἀβραὰμ ἐγέννησεν τὸν Ἰσαάκ,` 對應「亞伯拉罕生以撒，」。其餘兩行見附件「例子 of 原文 與 原文直譯 of greek」。
- 希伯來文樣本（創 1:2）：原文行序與直譯相反；以拆分後陣列表示，是 `word[2] ↔ exp[0]`、`word[1] ↔ exp[1]`、`word[0] ↔ exp[2]`。
  - `וְהָאָרֶץ הָיְתָה תֹהוּ וָבֹהוּ` ↔ 地是空虛混沌，
  - `וְחֹשֶׁךְ עַל־פְּנֵי תְהוֹם` ↔ 淵面黑暗；
  - `וְרוּחַ אֱלֹהִים מְרַחֶפֶת עַל־פְּנֵי הַמָּיִם׃` ↔ 上帝的靈運行在水面上。
- 附件含 `\n`、`\r\n`、`\n\r`，不要直接把「用 `\r?\n` 拆分再 reverse」當成完整演算法。請確認實際正規化位置，避免誤認為每一層都要反轉。
- 作者說「舊約沒有詞性」，應確認是沒有／不顯示 `pro` 欄位，而非沒有字彙分析或文法資訊。

### 3.3 `wid`：經節內的詞索引

作者提供：`wid` 是 word id，逐詞索引從 1 開始，識別的是該節中一次出現的位置。同字出現兩次仍有不同 `wid`；不可和 SN 混為一談。

例如太 1:1：

```text
Βίβλος γενέσεως Ἰησοῦ Χριστοῦ υἱοῦ Δαυὶδ υἱοῦ Ἀβραάμ.
   1       2       3       4      5      6      7      8
```

作者記得上方原文可對應下方同一位置的分析。局部程式證據：`FhlInfoContent.registerEvents` 以 `wid` 找 `#parsingTable` 內的區塊，再複製到 Parsing dialog；懸停時另取該區塊的 SN 與語言識別呼叫共用變色功能。因此須區分「按 wid 找詞」與「按 SN 標示相同詞號」。

### 3.4 `+` 與韋式／聯式差異

作者提供：新約原文可能以三個 `+` 分隔版本差異：

```text
+ {韋式} + {聯式} +
+ + {聯式} +
+ {韋式} + +
```

後兩種表示其中一方沒有文字，不應僅憑空段判定資料錯誤。`+` 本身也占一個 `wid`，畫面隱藏符號後詞索引可不連續。

太 1:9 樣本：

```text
Ὀζίας δὲ ἐγέννησεν τὸν Ἰωαθάμ,
Ἰωαθὰμ δὲ ἐγέννησεν τὸν + Ἀχάς + Ἀχάζ +,
+ Ἀχὰς + Ἀχὰζ + δὲ ἐγέννησεν τὸν Ἑζεκίαν,
```

- 六個 `+` 的 wid 為 10、12、14、15、17、19。
- 第一組顯示詞為 wid 11「(韋：Ἀχάς)」與 wid 13「(聯：Ἀχάζ)」。
- 作者與樣本顯示：韋式偏黃（`#ffff99`），聯式偏紅（`#ffcccc`）；下半部 class 線索為 `.greek_w`、`.greek_u`。上下半部都需確認。
- **版本名稱待查**：作者稱聯式為 UBS5，但附件太 1:9 備註寫「Westcott Hort和UBS4不同」。報告先用「韋式／聯式」，在確認來源前不得統一宣稱 UBS4 或 UBS5。

### 3.5 逐詞排版與顏色

作者提供：欄位標題為綠色，連接詞、動詞、介系詞各用不同顏色協助閱讀與結構分析。附件「table 顏色實例1」（雅 2:26）提供例子。

局部程式證據：`parsing_render_bottom_table.es2023.js` 的 `get_pro_class` 選擇 `.parsing-conj`、`.parsing-verb`、`.parsing-prep`。最終顏色仍須查 CSS，不能只憑 class 名稱判斷。

作者提及未來以 CSS variables 支援深色背景：這是**未來改善想法**，不是目前行為，也不是本次實作要求。

### 3.6 備註：文法圖片與 SN 參照

作者提供的待驗證轉換規則與樣本：

- `[#2.6#]` 對應文法截圖 `https://bible.fhl.net/new/pimg/2.6.png`。
- 圖片標記可混在說明中，例如 `אֶרֶץ 加冠詞時，根音第一個音節的母音拉長變為 אָ。[#2.20#]`。
- 一組標記可能包含多張圖片：`[#2.9, 4.2, 11.9#]`；需追出拆分、連結產生與點擊行為。
- 備註可能含 SN 參照，例如王上 3:5 的 `名詞 אָדוֹן (主, SN136)`；完整原始段落見 ver1「可能有 SN 參照」。
- 作者回報疑似漏抓案例：`בֶּן (兒子, SN 112  1)和 גֶּבֶר (基別, SN 1398)合起來為專有名詞，人名。`。作者認為 `SN 112  1` 應指 SN112 與 SN1，但目前只偵測 SN112。請確認資料語意與解析實作，不要直接將作者解讀變成 API 規格；此案例的確切經節尚未提供。

1. **DText 是否參與 Parsing**：作者記得 HTML 生成前可能統一轉成 DText；DText 能表示 SN、交互參照、list item 與巢狀 tag。這來自註釋功能的記憶，不能直接套到 Parsing。從 `index/DText.js` 與 Parsing 真正的 caller／callee 確認，沒有用到也應明說。

3. **歷史錯誤線索**：`app_versions.json` 搜尋「原文Parsing工具 列上3:5 9001 字彙分析 + 2 排序 Bug。」（ver1 指向約第 646 行）。例句為 `字彙分析: לְךָ 的停頓型，介系詞 לְ + 2 單陽詞尾`。作者說畫面可能錯排成 `2 + לְ`；必須區分來源字串、DOM 邏輯順序、視覺順序與複製結果。歷史修正記錄不等於目前已驗證修正。

- 前後節跨界、即時彈窗開關、Esc／focus、空資料／失敗與快速切節：各依實際環境記錄結果。

## 證據可信度

- **Confirmed**：有明確程式證據。附路徑、symbol、目前行號與支持該結論的呼叫／條件／讀寫；瀏覽器實測另記操作與結果。
- **Inferred**：有結構上的推論依據，但缺少完整證據；寫明缺哪一段。
- **Unknown**：目前資料不足；寫明需要什麼才能確認。

作者觀察、記憶、附件與程式註解都是線索，不能單獨證明目前 runtime 行為。不能把 Inferred 寫成 Confirmed；「有函式」不等於「功能會走到它」。若作者記憶與程式衝突，並列兩者與證據。

## 最終輸出格式

分析完成後，另產出一份報告，依序包含以下十節；本任務書與來源附件保留不覆寫。

1. **功能摘要**：功能、使用方式、系統完成方式。
2. **Entry Points**：主要入口、來源、觸發條件與證據。
3. **Runtime Flow**：用 tree／箭頭表示真實流程，包含重要分支，每一步說明做什麼。
4. **Data Flow**：經節／設定 → request → response → 正規化／內部資料 → HTML／DOM，列重要欄位及轉換。
5. **State / Side Effects**：重要 state、讀寫者、更新時機、影響範圍。
6. **Important Business / Behavior Rules**：只記錄有證據的現有規則，涵蓋本文的特殊資料與操作。疑似 bug、設計意圖、未來改善另標，不混成規則。
7. **Important Files / Functions**：真正理解功能所需的核心檔案與函式，不列出全部搜尋結果。
8. **Dead / Legacy Code Candidates**：分高度可能未使用、可疑、無法確認，附理由與尚缺證據；沒有足夠證據不建議刪除。
9. **Confirmed / Inferred / Unknown**：集中整理結論、作者記憶的核對結果與未解問題。
10. **Recovered Feature Specification**：以 Input／Behavior／Output 描述系統做什麼，不寫函式名稱；只把已確認行為納入正式規格。尚未確認的行為另列待確認，現有缺陷另列限制，不將 bug 寫成未來必須保留的要求。

## 重要限制

- 這次只分析與文件化，不重構、不修 bug、不大量提出新架構。
- 不因舊程式不好看就判定錯誤；不只依名稱或沒有直接 caller 就判定 dead code。
- 優先追實際 caller／callee／import／event／runtime path，必要時確認啟動載入鏈。
- 本文件列出的步驟與範例是調查方向，不是要求實作這些行為。
- 範圍外的重要問題可以簡記依賴或待辦，不無限制擴大調查。
- 無法確認就寫「目前無法確認」，不補合理答案；只有確實需要作者決定或補充的資訊才向作者提問。
