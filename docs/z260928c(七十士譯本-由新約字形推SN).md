# 七十士譯本每字加 SN：由新約字形推得（6.10.9）

## 起因

新約原文、舊約原文都嵌了 SN（見 `z260928a`），TODOs 還剩「原文直譯，用程式從 Parsing 整合入 SN」。評估後，原文直譯做不到同樣的效果；七十士譯本（lxx）反而可行，就先做 lxx。

## 原文直譯 (cbol) 為什麼難

- qsb.php 的 cbol 經文，就是 `bible_parsing.db` 每節 wid=0 的 `exp`（一字不差）。它是**整節的中文**，沒有「哪幾個中文字對到哪個原文字」。
- 逐字 (wid>=1) 的 `exp` 是**字典式字義**，不是直譯裡實際用的詞。約3:16：

| 原文 | SN | 逐字 exp | 直譯實際寫的 |
|---|---|---|---|
| μονογενῆ | G3439 | 唯一的 | 獨生子（和 υἱὸν 合成一個詞） |
| ὁ | G3588 | 視情況翻譯… | （沒譯出） |
| ἀπόληται | G622 | 失去、毀滅、殺害 | 滅亡 |

- 試算：拿逐字字義（以 `、` 切開）去直譯裡找，找得到的新約 44.3%、舊約 51.4%，找到的也常不確定（一節好幾個「他」）。
- 新舊約原文能做，是因為原文本身就一個字一個字切好。直譯要「中文片段 ↔ 原文字」的對齊資料，目前不存在；要做就是規則比對 + 人工校對（約 45 萬字）或 AI 對齊（沒有標準答案可驗證）。
- 較可行的退一步：直譯不嵌 SN，改成與原文並排時，滑到原文字顯示逐字字義。**TODOs 那項保留。**

## 七十士譯本：資料

- qsb.php `version=lxx` 沒有 SN（`strong=1` 也是純希臘文）；`bible_parsing.db` 沒有 lxx 的表。
- 信望愛的 lxx **已對應和合本章節**（詩9 有 20 節、詩119 有 176 節），可以直接接到讀經。qsb 取得 22719 節（舊約 23145 節，缺的 qsb 本來就沒有）。
- 經文裡的特殊字元：大寫字母的氣號重音寫在**字母前面**的 spacing 字元（`᾿Εμμανουήλ`、`῾Η`，U+1FBF、U+1FFE、U+1FCE…），U+1FBF 也當省略號（`ἐπ᾿`）。另有 `(35η)` 這類編號。

## 做法：tools/gen_bible_lxx.mjs（npm run gen:lxx）

1. 經文：qsb.php 逐章取 929 章（4 個並行、重試 3 次），快取 `tools/.cache/lxx_qsb.json`（要重抓就刪它）。
2. 新約字形表：`fhlwhparsing` wid>0 的 `uword` → 各 SN 出現次數，精確與去重音各一份；另記 SN → 原型 (`uorig`)。存 `tools/.cache/nt_greek_sn_table.json`（18246 個精確字形、17496 個去重音字形、5411 個 SN）。需先有 `gen:orig` 下載的 `bible_parsing.db`。
3. 每個 lxx 字（空白切開）依序試：
   - **精確字形**：小寫、grave 當 acute、ς→σ、去標點省略號；spacing 氣號重音先換成字母後面的 combining（`᾿Εμμανουήλ` → `Ἐμμανουήλ`）
   - **去掉所有重音氣號**
   - **補可移動的 ν**：字尾 ε / ι 且前兩步都查無此字形，試加 ν（lxx `ἐποίησε`、`εἰσί`，新約多是 `ἐποίησεν`、`εἰσίν`）
   - 該字形在新約**只有一個 SN，或最多的 SN 佔 90% 以上**才標，否則不標
4. SN 接在最後一個字母（含重音、省略號）後面，格式同新約原文 `Ἐν<WG1722> ἀρχῇ<WG746>`。
5. 輸出 `index/bible_lxx.json.gz`（約 1.7MB），`{col, ver, src, data}` 同 `bible_fhlwh.json.gz`；`src` 記 qsb 取得日期與 parsing zip 的 Last-Modified。報告在 `tools/.cache/gen_bible_lxx_report.txt`。

### 結果（478567 字）

| | 比例 |
|---|---|
| 精確字形唯一 | 79.2% |
| 精確字形多數 (≥90%) | 2.2% |
| 去重音唯一 / 多數 | 2.1% / 0.1% |
| 補 ν | 0.9% |
| **有 SN 合計** | **84.5%** |
| 新約有此字形但 SN 不一（οὗ 3739/3757、ἐναντίον 1726/1727、ἦ/ἥ…） | 0.3% |
| 新約沒此字形 | 15.2% |

沒 SN 的前幾名：人名地名（Σαλωμων 319、Μωαβ、Ιωαβ、Ιεροβοαμ…）、新約沒有的字（ἀλλόφυλος 外族人、ὁλοκαύτωμα 燔祭、πατριά 的變化形 πατριῶν）、新約沒出現過的變化形（λήψεται、φάγεσθε）。

限制：**Strong's 希臘文 SN 只收新約的字**，新約沒有的字根本沒有 G 號，不可能全部都標。同字形而實為不同字時，若新約只出現其中一個，會標成那一個，屬已知風險（沒有逐一檢查）。

## App 端

- `index/Bible_lxx_json.es2023.js`：同 `Bible_bhs_json`，顯示此譯本才載入。
- `lecture_get_data_async_es2023.js`：`lxx` 且舊約書卷時走 `get_orig_async`，不打 qsb.php（新約書卷選 lxx 仍走 qsb.php）。
- `cvt_others.js`、`attach_sn_text.js`：可有 SN 的譯本清單加 `lxx`，於是 `sn-text`、滑鼠 active、點 SN 查字典都能用。
- **只有 lxx 的 SN 顯示 `<G2532>`**（`cvt_others.js` 的 `add_tp_to_sn_label`，只改顯示文字，`sn` 屬性不變）：lxx 一定在舊約，並排的和合本、馬索拉原文是 H，只顯示數字會誤以為 `<1732>` 是同一個字。其它譯本只可能是一種（新約都 G、舊約中文英文都 H），不加。字母與數字同大小（討論過小一號，決定不要）。
- lxx 的 G 與和合本舊約的 H 是不同字典，滑鼠 active 不會跨這兩者連動。

驗證（dev server）：賽7 並排和合本 + 馬索拉原文 + 七十士，lxx 載入 `bible_lxx.json.gz`，滑到 ἡμέραις 本章 7 個 G2250 一起標；SN 顯示 `<G2532>`，和合本 `<1961>`、約3:16 新約原文 `<1161>` 不變；詩23 開關原文編號，沒有 `<WG…>` 外露；console 無錯誤。
