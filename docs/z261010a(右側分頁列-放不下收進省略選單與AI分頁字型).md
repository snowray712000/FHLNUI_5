# 7.5.8.6：右側分頁列放不下時收進「⋯」選單，AI 分頁跟介面字型

## 1. 分頁列 (原文 註釋 講道 串珠 典藏 有聲 地圖 AI)

### 問題
字型 (介面) 調大或右側面板拉窄時，分頁放不下。原本 `li` 是 inline-block，放不下就換到第二行，而 `#fhlInfoTitle` 高度固定且 `overflow: hidden`，所以最右邊的分頁 (例如 AI) 直接被藏起來，使用者不知道還有。

### 做法 (`FhlInfoTitle.es2023.js`)
- `ul` 改 `white-space: nowrap`，不換行。
- `layoutOverflow()`：量每個 `li` (`offsetWidth + 6`，6 = 左右 margin)，總寬 > `#fhlInfoTitle.clientWidth` 才顯示最右邊的 `<button.tab-more>⋯</button>`，並把放不下的 `li` 加 `.tab-over` (`display: none !important`)。可用寬度要扣掉 ⋯ 本身的寬度。
- 有 ⋯ 時 `#fhlInfoTitle.tabs-over` 改靠左排；原本置中，標籤會被 ⋯ 壓到。
- 按 ⋯ 開 `.tab-more-menu`：只列 `.tab-over` 的分頁，選中的標成強調色。點項目就對該 `li` `trigger('click')`，沿用原本的切換流程。選中的分頁被收進選單時，⋯ 也變強調色，提示「目前在被藏起來的分頁」。
- 選單掛在 `#fhlInfo` 下 (不是 `#fhlInfoTitle`)，因為後者 `overflow: hidden` 會把選單切掉。點選單外面就關閉。
- 重排時機：`ResizeObserver` (`#fhlInfoTitle` 寬度)、`MutationObserver` (`<html>` 的 `style` / `class`，字型大小改的是 css 變數)、`document.fonts.ready`、點分頁後 (選中的字較大 `20px × --ui-k`)、`render()` (簡繁切換會重建 `li`)。以 `requestAnimationFrame` 合併。
- 樹狀圖分頁平常是 `display: none` (只在羅馬書出現)，量寬度時略過 inline `display: none` 的 `li`。

### 試過、放棄
- 邊緣淡出漸層：會蓋住最後一個看得見的分頁 (「有聲」被切成半個字)，只留 ⋯ 加一條細分隔線。
- 換行成多列：佔固定高度的空間，不採用。
- 只靠橫向捲動：觸控以外看不出可捲，不採用。

## 2. AI 分頁

- 按鈕 (`.btn.ai-tool`)、標題 (`h5.ai-h`) 字型改跟介面 (`12pt × --ui-k`)，不再跟內容大小 (`--fontsize`)；手指時最小高度 `--touch-min`。
- 原本字大時按鈕之間多出一截空白：容器是行內排版，行高跟著放大；按鈕行高 1.5、內距 `0.375em 0.75em` 也偏大。改成 `#fhlInfoContent:has(.ai-tool)` flex 換行 + 與 `--ui-k` 成比例的 `gap`，按鈕行高 1.25、內距 `0.25em 0.6em`，標題 `flex: 0 0 100%`。
- 按鈕上的 ❓ 改成共用的 `.intro-help` 圓形 `?` (同「同源字」「原文SN」旁的 ?)，原本的事件 class (`ai_parsing_help`、`ai_translation_help`) 保留。`.intro-help` 加 `inline-flex`，`<span>` 也能用。
- 踩到的坑：用 python 取代含引號的 JS 字串時，把 `method='" + method + "'` 的跳脫弄壞，`method` 屬性變成字面的 `" + method + "`，點說明抓不到是哪個。改完要重新載入並點一次。

## 3. 沒測的
簡體模式、觸控 (手指點 ⋯ 與選單項目)、每個 AI 按鈕的說明視窗 (只點了第一個)。
