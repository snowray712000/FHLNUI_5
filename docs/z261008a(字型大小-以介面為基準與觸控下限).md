## 一、背景：為什麼電腦與平板的字會不一致

這段是討論時整理的概念，不是這個專案獨有的。目的是讓之後規劃字型時知道「問題從哪來、各概念為了解決什麼」。

| 歷史上遇到的問題 | 發明的概念 |
|---|---|
| 同樣 12 pt，Mac (72 ppi) 與 Windows (96 dpi) 大小不同；pt 本來是印刷單位 (1/72 英吋) | 邏輯 DPI |
| 螢幕解析度變高，網頁會縮得很小 | CSS 像素、`devicePixelRatio` (實體像素 vs CSS 像素) |
| 手機、平板拿得近，電腦拿得遠 | CSS 的 1 px 定義為「手臂距離看 96 dpi 螢幕時一個像素的視角」，即 px 是視角不是長度，用來補償觀看距離 |
| 手機縮小網頁後字看不清 | `<meta viewport>`、`text-size-adjust` (iOS 會自動把部分字放大) |
| 手指點不到 | 最小觸控目標：Apple 44 pt、Material 48 dp、WCAG 2.2 最低 24 px (較舒適的目標 44) |
| 分不出手指還是滑鼠 (iPad 寬度與小筆電差不多) | `pointer: coarse / fine`、`hover: none`；注意 iPadOS 13 起 Safari 預設假裝桌面版，用裝置名稱判斷不可靠 |
| 每個人視力不同 | rem / em (相對瀏覽器預設字)、Android sp、iOS Dynamic Type、系統顯示縮放 |

CSS px 的視角補償只是近似 (姿勢、實際螢幕密度各異)，所以「電腦合適、平板不合適」是常態。結論：字型要分三件事各自想，**內容字** (讀得舒不舒服：距離、視力)、**介面字** (標籤、按鈕)、**觸控範圍** (手指按得到，跟字大小無關)，再用一個整體倍率統一縮放。

專案原本「通通 14 pt」是只有電腦一種裝置時的做法；z260930a 先做了「整體大小 × 情境」，本次把基準講清楚。

## 二、決定的模型

```
介面 (UI) = UI_BASE 12pt × 整體大小 %           (夾在 9 ~ 24pt)
內容實際  = round(情境 profile × 整體 % / 100)    (經文、希伯來、希臘、SN)
```

- **介面是基準，也是最小的**：坐在電腦前、手臂距離時剛好舒服的大小 = 整體 100%。介面**只由整體大小決定**，情境不動它。
- **整體大小** = 坐得近還是遠、眼力、裝置。設一次就不太動；側邊欄 A− A+ 調的就是它，一次 ±10%，70 ~ 200%。
- **情境 (組合, profile)** = 經文、希伯來文、希臘文、SN 相對於介面的比例。存成「整體 100% 時的 pt」(= 比例 × 12，可有小數)，所以「預設」的經文 12 就是與介面一樣大。切換情境只換比例，不動整體大小。
- 版面高度 (標題列、分頁標籤) 乘同一個介面倍率，介面變大它們一起變高。
- 為何以介面為底而不是以經文為底：介面是最小、最不能再縮的東西，內容 ≥ 介面，「從底線往上長」不會出現介面字比內容字大；投影時把內容放很大，介面不必跟著大 (沒人在點它)。

## 三、觸控最小可按範圍

字大小與可按範圍是兩個獨立的尺度，所以下限不是第二個百分比，而是 css 的 `max()`：

```css
body { --touch-min: 0px; --bar-h: max(calc(30px * var(--ui-k, 1)), var(--touch-min)); }
@media (pointer: coarse) { body { --touch-min: 44px; } .fs-btn, .th-btn { min-height: var(--touch-min); } }
```

- 電腦 (滑鼠) `--touch-min` 是 0，版面不變；手指 (`pointer: coarse`) 是 44px。
- `--bar-h` 取代原本散在 7 處的 `calc(30px * var(--ui-k, 1))`：`#lecMainTitle` 高與字行高、`#lecMain` / `.chapControl` / `#fhlInfoContent` 的 top、`#fhlInfoTitle` 高與行高、選中分頁的行高。標題列與其下方內容共用同一個變數，才會一起變。
- `--bar-h` 必須宣告在 `body` (不是 `:root`)：`--ui-k` 由 `applyCss` 設在 body，宣告在 `:root` 會讀到 html 上舊的值。
- 只對**可點**的東西設下限，不是每個元素都撐到 44px，否則一屏看不到幾節經文。

**沒做**：經文裡 `.sn` / `.ref` 這類行內元素擴大可按範圍 (硬加內距會改排版、跨行換行時不穩)；左欄其它小控制項 (SN 篩選、譯本選擇…) 沒納入觸控下限。

## 四、經文區原文欄一直沒接上希臘文、希伯來文大小

**現象**：調希臘文、希伯來文大小時，有時外面看得到變化、有時看不到。

**原因**：`--fontsize-greek` / `--fontsize-hebrew` 只套在 `.greek-char` / `.hebrew-char` 的 span (解析分頁、字典、註釋、即時視窗)。經文區的原文欄 (新約原文 `fhlwh`、七十士譯本 `lxx` 是希臘文，馬索拉原文 `bhs` 是希伯來文) 在 7.0.2 經文區 grid 化後，舊的 `#fhlLecture .lecContent.bhs.hebrew { font-size: 18pt }` 與 `setFont()` 加的 `.nwh` / `.greek` 都對不到任何元素 (grid 的 DOM 是 `.vercol > .paragraph > .lec[ver]`)，原文欄一直跟經文大小。實測新約原文欄固定 16px，與 `--fontsize-greek` 無關。

**修法** (`index/fhl.css`)：以 `.lec[ver]` (ver 屬性即譯本代碼) 對：

```css
#lecMain .lec[ver="fhlwh"], #lecMain .lec[ver="lxx"] { font-family: COBSGreekWeb; font-size: var(--fontsize-greek); }
#lecMain .lec[ver="bhs"]  { font-family: COBSHebrew;  font-size: var(--fontsize-hebrew); }
```

- 決定 (使用者)：經文區原文欄跟希臘文、希伯來文大小，字型也用 COBS (與解析、字典一致)。
- 舊的 `.lecContent.bhs.hebrew { 18pt }` 規則已刪。
- 預設值因此改成希臘文 12、希伯來文 16：原本的 26 是配合解析、字典裡 COBS 字形較小設計的，直接套在經文區太大 (節碼、SN 標籤也跟著整欄放大)。
- 副作用：經文區的節碼與 SN 標籤跟著整欄字級走，欄位字大於經文時它們也一起變大 (投影 48pt 時看起來會很大)。
- **待確認**：解析、字典裡的希臘文現在預設 12pt，可能偏小；希伯來文欄只改了 css、沒在畫面上看過 (當時頁面沒開馬索拉原文，`COBSHebrew` 字型是 unloaded)，要看字是否靠右、方向對不對。

## 五、譯本選擇對話框

`.ui-dialog-content` 的字是 `var(--fontsize)` (內容大小)，但 Bootstrap 的 `.btn` 寫死 `1rem`、內距用 rem。內容字變大時按鈕不變，行高 (1.5 × 內容字) 把每個按鈕撐出一圈空白，按鈕裡的字也沒跟著內容大小。

- 修法：`#bible-version-dialog .btn { font-size: inherit; line-height: 1.5; padding: .375em .75em }`，`.btn-sm` 為 `.25em .5em`。預設 (16px) 時與原本相同 (6px 12px、行高 1.5)。
- 「選取、常用、Sets」(`.group-help`，點了分別是清除所選、清除常用、清除 Sets) 是**介面**：字 `calc(12pt * var(--ui-k))`、做成有邊框的按鈕外觀 (`--line-strong` / `--btn-bg` / hover `--pressed-bg`)、手指模式寬高不低於 `--touch-min`。原本 `position: absolute; right: -.75rem; top: -1rem` 掛在群組框右外側，變大後會超出對話框或蓋住上一組，改放進群組框右上角 (`right/top: 4px`)，群組右側 `padding-right: calc(var(--gh-w) + 8px)` 留位，`--gh-w = max(72px × ui-k, --touch-min)`；群組 `min-height` 用 `!important` 蓋過 html 內嵌的 `min-height: 2.5rem`。
- **選擇器要 `div.group-help`**：對話框自己的 `BibleVersionDialog.min.css` 比 `fhl.css` 晚載入，同優先權時它的 `right / top / font-size` 會蓋掉。第一次寫 12px 還比介面基準小，加上這個 bug，使用者看到「還是很小」。
- 其它用 Bootstrap 按鈕又放在跟內容大小走的對話框裡的，可能有同樣問題，**尚未檢查**。

### 順手修好的舊 bug：右側內容區超出下緣

`#fhlInfoContent` 是 `top: var(--bar-h)`，在窄螢幕媒體查詢裡又寫了 `height: 100%`，所以比外框多出一個標題列高度，貼底的元素 (註釋的「書卷背景」按鈕) 被切掉一截。改成 `height: calc(100% - var(--bar-h))`。這個問題在放大前就有 (標題列固定 30px 時只是不明顯)；影響整個右側內容區，各分頁底部現在多出原本被吃掉的那段。

### 順手修好的舊 bug：搜尋「摩西」在大字型下無法捲動

對話框內容 (`.ui-dialog-content`) 跟內容大小，搜尋對話框的控制列與篩選 chip 也繼承它；內容 48pt 時群組 chip 就佔 596px，對話框才 598px，捲動的 `.sd-results` 只剩 12px。控制列與 chip 改用介面大小並限高後，同條件下結果區約 358px 可捲動。**通則**：對話框裡「固定在上方的控制區」不要跟內容大小，否則會把會捲動的區塊擠掉。

### 搜尋對話框的篩選區可收合

控制列多一顆「篩選 ▾」(`.sd-fold`)：點了收起群組 / 書卷 chip (`.search-dlg.sd-folded`)，收合時顯示「篩選 ▸：目前範圍」(分類或單卷名)。狀態記在 `localStorage` `fhlSearchFold`，沒有篩選可用時 (經文查詢、無結果) 按鈕隱藏。做法同典藏 (z260927b 第 4 節)。窗格隱藏時 `innerHeight` 為 0，對話框高度會失真，量高度要在窗格顯示時。

### 測試手法

用瀏覽器窗格直接設 `document.body.style.setProperty('--ui-k', '1.5')` / `('--fontsize', '24pt')` 看畫面與 `getComputedStyle`，驗完要 `removeProperty`。改 CSS 後 vite 會整頁重新載入，正在跑的 javascript 會被截斷，要重新執行。地圖 tooltip 在窗格裡用 `dispatchEvent` 模擬點擊才不會導頁。

## 八、測試時踩到的坑

- 瀏覽器窗格的平板模擬 (`resize_window`) **不會打開 `pointer: coarse`**，所以觸控下限只能用手動 `body.style.setProperty('--touch-min', '44px')` 模擬；真的 iPad 還沒測。
- 字型實際值會寫回 `fhlPageState` (ps 的 `fontSize` / `fontSizeHebrew` …)。只刪 localStorage 的 `fhlFontSize` **不會清掉**它，下次啟動 `migrateFontSize` 會把 ps 的值當成 profile (這是刻意的舊使用者遷移路徑)。測試時要連 `fhlPageState` 的這四個值一起重設，否則前一輪的放大會殘留 (本次中間幾張截圖的比例因此失真)。
- 測試時要切譯本：`fhlPageState` 的 key 是 `version` (陣列)，不是 `versions`。
- 在對話框裡點「選取」會清除所選譯本 (只是對話框內的狀態)，測完要還原 `version`。
