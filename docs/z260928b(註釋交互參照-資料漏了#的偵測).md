# 註釋交互參照：資料漏了 # 的偵測（6.10.7）

## 現象

TODOs 的「注釋，徒20:13，有的交互參照沒被偵測到」。實際是 徒20:7–12 那段：

```
●「講論」徒 20:7|、「講了」#徒 20:9|：SNG01256
```

`徒 20:7|` 少了開頭的 `#`，畫面上是純文字，連 `|` 都露出來。`#…|` 標記齊全的都偵測得到（徒20 整章 8 段、30 個）。

> TODOs 裡的 ✅ 不代表已修：3.7.1 把 `Bug)` 前綴統一換成 `✅ Bug:`。

## 全部註釋的狀況

用信望愛公開的 `bible_comm.zip`（https://ftp.fhl.net/FHL/COBS/data/，sqlite，表 `comment`，36333 筆）掃過：

| 問題 | 處數 | 例 |
|---|---|---|
| 全形 `＃` | 3 | 路24:50 `＃徒 10:2;來 9:6;13:15|`、太6:5 `＃6:7-8|`、徒書卷背景 `＃徒 1:1|` |
| 漏了 `#` | 7 | 徒20:7、帖前2:5 `#徒 17:5|;徒 18:3;20:34|`、林前13:4 `僅出現於徒 17:16;林前 13:5|`、來11:8 `11:20-22|`、太28:11 `28:15|`、創2:8 `同 2:5|`、創10:21 `結 27:10;30:5|` |
| 全形 `｜` 結尾 | 1 | 創19:1 `#撒上 15:23｜` |
| `#` 後漏了 `|` | 2 | 創7:6 `#7:21都…`、創18:9 `#18:13才…` |

最後一種以前更糟：`/#([^|]+)\|/` 會從那個 `#` 一路吞到下一個 `|`，變成一大段錯的連結，並把後面真正的參照（`#7:4,23|`）吃掉。

## 修改

`index/comments/convertDocToDText.js` 的 `REGEX_COMMENT_REF` 取代 `/#([^|]+)\|/`：

- 第 1 組：`[#＃]([^|｜#＃]+)[|｜]`，全形也收；中間不跨過 `#`
- 第 2 組（漏了 `#`）：像經文位置、緊接 `|` 的文字
  - 書卷只認聖經縮寫（繁簡，長的先試），所以「於徒 17:16」不會吃到「於」
  - 至少要有一個「章:節」（lookahead `(?=[^|｜]*:)`），多個用 `;`
- 測試 `tests/commentRef.test.js`，案例都是上面的真實資料

用全部註釋比對新舊：原本 115949 個參照都還在；多了 17 個（上表 10 + 1，加上 6 個原本被漏 `|` 的 `#` 吞掉的）；消失的 5 個是舊式子吞出的錯誤長段落。
