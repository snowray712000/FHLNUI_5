# SN 篩選：讀經組合與說明

接續 [z260928e(SN篩選顯示-規畫)](z260928e(SN篩選顯示-規畫).md)。

## 緣由

SN 篩選的細項 (詞類、動詞形態、主導詞、指定/排除) 都做好了，但它們是「零件」：使用者得自己知道勾哪幾個才看得出東西，切換也麻煩。
語言學老師不會說「勾語氣=分詞」，而是說「來看這段的主要動詞」。所以在細項上加一層 **讀經組合**：一個組合 = 一個要問經文的問題，附簡單說明與經文例子。

## 組合

`SN_LENSES` (`index/SnFilter.es2023.js`)，每個組合給新約、舊約各一份部分設定 (`presets` `morph` `leitwort` `showTvm`)，套用時整組取代細項 (沒列的用 `newCfg()` 的預設，所以「另外加」「排除」會清空)。

| id | 名稱 | 新約 | 舊約 |
|---|---|---|---|
| conj | 連接詞 | 詞類 連接詞 (c+t) | 同 (ו 看不到) |
| main | 主要動詞 | 語氣 限定動詞 | 形式 敘述 完成 未完成 連續 意志 |
| nonfin | 分詞、不定詞 | 語氣 不定詞 分詞 | 不定詞附屬形 獨立形 分詞 |
| will | 命令與意願 | 語氣 命令 祈願 | 意志式 |
| narr | 敘事主線 | (不顯示) | 敘述式 |
| perf | 完成時態 | 時態 完成 過去完成 | (不顯示) |
| god | 神的名號 | 神的名字 | 同 |
| leit | 本章主導詞 | ≥ 3 次 | 同 |
| content | 實詞 | 實詞 | 同 |

- 命令與意願沒有放新約的假設語氣：ἵνα 子句的假設語氣太多，會淹沒真正的勸勉
- 同時設定新約、舊約：讀到哪一約都有對應的意義；只對一約有意義的 (`only`)，另一約不顯示 SN

## 目前是哪個組合

不另存「目前組合」，而是比對設定：`activeLensId` 把目前的新約+舊約設定與每個組合的完整設定比 (`cfgKey`，清單不計順序、空的形態組不計)。
所以套用後再動細項，組合就自然不亮；改回來又亮。與內建相同的「我的組合」優先亮。

## 我的組合

`SnFilter.custom = [{name, nt, ot}]`，與其它設定一起存在 localStorage `snFilter`。同名覆蓋；「把目前設定存成組合」用 `prompt()` 問名字 (目前是我的組合時預設它的名字)。

## 說明 (?)

- `docs/SN讀經組合說明.md`，每節 `## 名稱 (id)`，`(intro)` 是「讀經組合」標籤旁的 ?。`splitHelpSections` 分節，只顯示那一節
- markdown-it 與 `fixLinks` 共用 `Help.es2023.js` (第一次用才從 CDN 載入)
- 經文位置寫成 `[約1:1](#/bible/約1:1)`：`fixLinks` 不動 # 開頭的連結，點了由 hashchange 跳過去；說明對話框另外攔 click 套用組合
- build：`vite.config.js` 的 `LEGACY_COPY` 加了這個 md (docs/ 其它不上傳)
- `tests/snFilter.test.js` 檢查每個組合都有說明、用到的預設組合與形態選項都存在

寫說明時每個例子都用 `sn_morph`、和合本快取 (`tools/.cache/unv_qsb.json`) 核對過，畫面上看得到才寫。踩到的：

- 創1:26「我們要…造人」形式上是未完成式 (不是鼓勵式)，改用 創11:3、11:7
- 創22:3 最後的「去」和合本標 H3212，原文是 H1980，對不到，所以說明中註明
- 約1:1 的 καί 在和合本沒有 {}，不適合當「未譯出」的例子；改用 林前15:3-5 的四個 {ὅτι}

## 快速切換

漏斗按鈕的 `contextmenu` (右鍵；Android 長按也會觸發，iOS Safari 不會) 開 `.snf-menu`：組合、我的組合、全部 SN、設定…。

## 對話框

- 上方：顯示 SN、讀經組合、我的組合、其它的 SN (隱藏/變淡)；細項收在 `<details>` (展開狀態在 render 重畫時保留)
- 高度依內容 (maxHeight 85%)，展開/收合時重新定位，才不會超出視窗下緣
- 說明對話框放在設定對話框右邊 (`collision: 'fit'`)
