## 一、規則（使用者 2026-10-01 決定）

> 跨欄或跨列之後，複製都是整個 cell 為單位，clipboard 都有 table 與純文字兩種。只有開始與結束都落在同一 cell 才只有純文字，並且不是整個 cell 的內容，而是看水滴的開始與結束。

- **格 (cell)** = 畫面上的一格 = 一個 `.paragraph`
  - mode 1：一節；mode 3：一段；交錯 (2/4)：一個譯本的一節或一段；VerseGrid（搜尋結果、交互參照）：一列的一個譯本
- **起訖在同一格**：只有 `text/plain`，照水滴（原生反白）的起訖，不是整格
- **跨格（跨欄或跨列）**：一律整格；`text/html` `<table>` + `text/plain`（tab 分隔）
  - 單一譯本跨列也是表格（一欄），以前的「單一譯本特例」拿掉了
- **矩形**：並排時，欄 = 起點格的譯本到終點格的譯本（照畫面順序），列 = 起訖之間的列（`#lecMain` 用節的位址，對話框用 `data-row`），再擴成整格
  - 原因：原生選取是照 DOM 畫的，從「和合本 5 節」斜拉到「新譯本 3 節」時，DOM 範圍沒碰到和合本 3–4 節，舊做法會漏格；改用兩個角圍出矩形就不會漏

## 二、反白怎麼畫

- 跨格時 `.lct-crossed ::selection { background: transparent }`，要複製的格整個 div 加 `.lct-cell` 底色（`--lct-hl`）。像 `index/lecture/01-05/03_smart_table_selection_rect_demo.html`（demo 3）
- 拿掉了 CSS Custom Highlight（`::highlight(lec-copy)`）：整格就不必算字的範圍
- 隱藏的文字不複製：`rangeRuns` 遇到父元素 `checkVisibility()` 為 false 就略過（曾經測到把隱藏的 SN「900」複製進去）

## 三、平板 (iPad Safari) 的坑與做法

### 坑

1. **iOS Safari 不理 `::selection` 的底色**：原生藍色反白與水滴是系統畫的，網頁蓋不掉。所以「跨格就把反白改透明」在電腦有效、在 iPad 沒用
2. **放開水滴不送 `touchend` / `pointerup`**：開始拖水滴時有 `touchstart`（有時有 `pointercancel`），放開時什麼都沒有，網頁無從得知放開
3. **拖曳中收掉原生選取，水滴也會一起消失**：第一版一跨格就 `removeAllRanges()`，結果使用者還沒放開水滴就不見，只能框到隔壁一格
4. **長按出現的「拷貝 / 查詢…」選單**會擋住放在選取旁的按鈕

### 做法

- 拖水滴跨格中：原生選取留著（水滴才拖得動），同時畫整格矩形（底色），按鈕跟著
- 「放開」= 選取 `LecCopyTable.IDLE_MS`（1000ms）沒變。之後 **sticky**：收掉原生選取（藍色、水滴、iOS 選單一起消失），只留整格底色與按鈕
  - 副作用：拖到一半停 1 秒會被當成放開；實機覺得太快再調 `IDLE_MS`
- sticky 之後：
  - 矩形左上、右下各一個圓點 `.lct-knob`（44px 觸控範圍），拖它以「格」為單位改範圍，對角那格固定。用 pointer capture + `elementsFromPoint`（略過圓點自己）找手指下的格。拖回對角那格（變單格）不理會
  - 在同一範圍長按某格 → 起點格到那格（像 Shift+點；是「改角」不是「聯集」，所以也能縮小）
  - 輕點（< 450ms、< 10px，不是按鈕、圓點）→ 取消
  - 按鈕上方小提示 `.lct-tip`：「拖圓點改範圍 · 長按另一格也可 · 點空白取消」（不然沒人知道長按可以改範圍）
- 觸控時按鈕放在畫面下方中央（不放選取旁，避開 iOS 選單）；電腦仍在選取最後一行右下
- 判斷觸控用 `matchMedia('(pointer: coarse)')`；電腦的流程完全不經過上面這些
- 目前沒做：拖圓點到畫面邊緣自動捲動（可先捲再拖，或長按延伸）

### 踩到的 JS 坑

本專案不寫分號。`#knobDown` 裡

```js
this.#knobDrag = { ... }
/** @type {HTMLElement} */ (e.currentTarget).setPointerCapture(e.pointerId)
```

第二行以 `(` 開頭，被接成 `{...}(e.currentTarget)` 呼叫 → TypeError，`#knobDrag` 沒設上，圓點拖不動。改成先 `const knob = /** @type */ (e.currentTarget)`。**以 `(`、`[`、`` ` `` 開頭的行要小心。**

## 四、用 iOS 模擬器測（Claude Code 桌面版）

- 工具：`mcp__Claude_Code_iOS_Simulator__control`，iPad Pro 13-inch (M5)。若面板打不開、錯誤是 CoreSimulator 版本不符（Xcode 更新後），重開 Claude app
- Safari 開 `http://127.0.0.1:5173/`（`open_url` 每次會開新分頁）；載入後等 6–7 秒再操作，不然長按會按到空白
- 座標是 device points（1032×1376），截圖顯示 1500 寬 → points = 顯示 × 0.688
- 模擬「長按選字 → 拖水滴」：`tap` duration 1 秒長按，再 `touch_path` 從水滴位置出發，**先停 400ms 再移動**（沒停的話拖不動）
- 看不到 Safari console：除錯時在頁面放一個 `position:fixed` 的 `<pre>`，把事件與 `window.onerror` 印上去，測完刪掉
