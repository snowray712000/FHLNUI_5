# 拖曳把手：統一的小方塊；搜尋出處欄寬、原文解析上下可拖

7.2.5 (2026-10-08)。把「可以拖的分隔線」都加上同一種中間小方塊，並補上兩個原本不能拖的地方。

## 一、統一的小方塊 (把手)

細線（2px）或 12px 灰框不容易看出「可以拖」，也不好按。三種分隔線都在中間畫一個圓角小方塊：

| 地方 | 方塊 | 位置 (css) |
|------|------|------------|
| 譯本之間的欄寬 (經文區、交叉參照、搜尋結果) | 8×22 | `.lec-col-handle::before` |
| 左 / 右側欄灰框 | 6×36 直條 | `.leftWindow > .ui-resizable-handle::after`、`#fhlInfo .ui-resizable-handle::after` |
| 左側欄裡上下灰框 | 36×6 橫條 | `#fhlLeftWindow .leftWindowInside > div > .ui-resizable-handle::after` |
| 原文解析上下灰框 | 36×8 | `#parsingSplit::before` |

- 原本灰框上的 ☰ 字（`<span>`）隱藏，免得與方塊重複。
- 滑過去變強調色 `--accent`；欄寬線「自訂過」也是強調色。
- 手指 (`@media (pointer: coarse)`)：可按範圍 44px、方塊長度不低於 `--touch-min`。灰框原本的透明 `::before` 加寬區（docs/z261002d）沒動，所以方塊用 `::after`。
- 淺灰表頭（`.verse-grid .vg-head`）上方塊與底色太接近：改用 `color-mix(in srgb, var(--fg) 40%, transparent)`，淺 / 深色主題都看得到。

## 二、搜尋結果的出處欄寬可拖

- 最左邊「經文出處」欄原本固定 `6.5em`（各批載入的 grid 要同一個寬才對得齊），字型大時不夠、或有時太寬。
- `labelWidth` 改成 `var(--vg-label-w, 6.5em)`，變數放在 `.sd-results`，表頭與各批 grid 一起變。
- 表頭最左空格右緣加分隔線：拖曳改寬 (px，最小 40)，雙擊回預設，記在 localStorage `fhlSearchLabelW`（`addLabelHandle`，`SearchDialog_es2023.js`）。
- **單一譯本也有表頭**：以前只有並排多譯本才畫表頭。現在 `side` 版面一律畫；多譯本才建立 `ColWidth`（單一譯本沒有譯本之間的欄寬）。
- 「交錯」版面沒有表頭，出處欄放的是譯本名，目前不能拖。

## 三、原文解析上下灰框可拖

- 以前上方經文 `#parsingTop` 高度 `200px`、灰框 `top: 200px`、下方 `#parsingTable` `top: 212px` 三處寫死。
- 改成 css 變數 `--parsing-top-h`（預設 200px，放在 `#fhlInfoContent`）：`#parsingTop` 高度、`#parsingSplit` 的 `top`、`#parsingTable` 的 `top: calc(var + 12px)`。
- 灰框從行內 style 改成 `<div id='parsingSplit'>`；`parsing_render_async_es2023.js` 的 `setupSplit` 處理拖曳 (pointer events)：上下各至少 60px，雙擊回預設，記 localStorage `fhlParsingTopH`。
- 每次換節 `html()` 重畫，變數在 `#fhlInfoContent` 上不會被洗掉，`setupSplit` 重新綁在新的灰框上。

## 四、注意

- 這三種都只改外觀與新增拖曳，不影響 jQuery UI resizable 的行為。
- 小方塊顏色一律用語意變數 (`--handle-bg`、`--accent`、`--fg`)，沒有寫死顏色 (`tests/theme-colors.test.js`)。
- 版本號：7.2.3 → 7.2.5。
