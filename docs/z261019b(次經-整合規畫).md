# 次經：整合規畫

2026-10-19 規畫；P0 於 7.7.2.1、P1（能讀 c1933）於 7.7.2.2 完成（見文末兩節紀錄），其餘尚未實作。依據：另一專案（FHL-MCP-Go）整理的 `qsub.php` / `sesub.php` 指南、信望愛官方次經閱讀頁（`bible.fhl.net/new/readsub.php`）、以及本專案當天對上游的實測。做法直接沿用使徒教父（docs/z261019a，7.6.4.* / 7.7.1）已走通的路。

## 結論

- 書卷 id 101–115 就是上游 `bid`，`BookRegistry` 的 `CORPUS_RANGES.apo = [101, 199]` 已預留。
- 取經文 `qsub.php`、搜尋 `sesub.php`（對應 `qaf.php` / `seaf.php`）。**兩支都回 CORS，網頁可直接 `fetch`**。
- **次經有兩個文本**（官方閱讀頁可勾選並對照）：`c1933`（1933年聖公會出版，純文字）與 `chdc`（1933年次經全書，HTML、有小標與專有名詞底線）。這與使徒教父「只有一種文本、固定一欄」不同，所以次經適合走**一般譯本的路**（可選、可並排），不是固定一欄。
- 書名採「**信望愛站名為預設，天主教通行名並行**」：官方閱讀頁用的就是信望愛站名；兩套都存、都認得，顯示用哪套由設定決定（見下）。
- 比使徒教父單純的地方：沒有註腳、沒有 `sec=0`、沒有書卷導論命中、沒有 Strong's number 與地理資料（官方頁的選項存在，但 c1933 的資料是空的）、`gb=1` 原生支援簡體（不需要 `s2t.json`）。
- 要多處理的地方：兩個文本的**節數不一致**（見「兩個文本」）、c1933 有 26 處「併入上節」佔位、chdc 的 HTML 結構不乾淨。
- 不內嵌全文（版權沒查證），即時抓取 + 記憶體快取。

### 官方閱讀頁（readsub.php）

- 書名（`select chineses`）就是信望愛站名；上游短名（`馬一`、`比`…）是 `chineses` 的 value。

### chdc 內容掃描（5371 節）

- 少兩卷：**107（以斯拉續編上卷）第 1 章整章沒有**（c1933 有 107 節），**114（比勒與大龍）整卷沒有**。

## 兩個文本怎麼進來

官方就把它們當**譯本**（同一書卷、可對照），所以走本站的譯本機制，不是使徒教父那種「固定一欄」：

- 在 `譯本選擇` 對話框新增分類「次經」，兩個譯本：`c1933`（1933年聖公會出版）、`chdc`（1933年次經全書）。名稱不在 `uiabv.php`，與 afhuang 一樣自己給（`BibleVersionDialog` 的 `cna` 機制 / `abvphp_snapshot.js` 手補）。
- `lectureVersions(ps)` 依書卷類別過濾 `ps.version`：
  - 讀次經：取 `ps.version ∩ {c1933, chdc}`，沒有就預設 `['c1933']`；
  - 讀新舊約：去掉 `c1933` / `chdc`，剩空就退回預設譯本（和合本）；
  - 讀使徒教父：維持 `['afhuang']`。
  這樣使用者選了哪些譯本都不被破壞，勾了 chdc 就在次經的書上多一欄。
- `lecture_get_data_async`：次經走 `qsubAsync({ bid, chap, version, gb })`，每個譯本一個請求（快取鍵含 version、gb）。
- 兩欄節集合不同時，缺的格留空（`VerseGrid` 本來就以節號對齊）；整章沒有（chdc 的 107:1、114）顯示「此譯本沒有這一章」。
- **chdc 的 HTML** 走 `parsingToDOMs`：`<h1>` 會變小標、`<u>` 專有名詞底線（認得）、`<i>` 斜體（`DText.isItalic` 已有）、`<br/>`；`<p>` 與多餘 `</p>` 需補丁並測試。不好看的話 chdc 先去掉 `<p>`，只保留 `h1` / `u` / `i` / `br`。
- 搜尋：`sesub` 只搜 c1933，命中位置再依使用者勾選的譯本用 `qsubAsync` 取各版文字（`SearchSession` 本來就是「命中位置 → 各譯本取文」的流程，次經版不必像 af 把經文隨搜尋帶回來）。chdc 專屬的節（如 101:1:64）搜不到，是上游限制，說明文字帶一句。

## 風險與未驗證

- **泛化 af 寫死的地方**是最大風險：`SearchSession` / `SearchDialog` / 選書 UI 都是單一類別寫法，要保住使徒教父既有行為。P1 前先跑一次 `npm test` 當基準（`qaf` / `searchAf` / `bookRegistry` / `afHelp` 測試）。
- `lectureVersions` 的過濾規則會影響所有讀經流程（歷史、複製、對照）；要測「在新舊約與次經之間切換時，使用者原本選的譯本不亂」。
