# 功能逆向分析

我要你針對既有專案中的一個功能，進行 **feature-by-feature reverse engineering（逐功能逆向分析）**。

目標不是重構程式碼，也不是提出新的架構，而是：

- 從現有程式碼反推出這個功能實際如何運作
- 找出它的入口、主要流程、資料流、狀態、UI 更新與外部依賴
- 區分目前仍在運作的程式碼、可能已廢棄的程式碼，以及無法確認的部分
- 最後整理成一份可以供未來重構或重新實作使用的功能規格

請以「現有程式碼證據」為主要依據，不要因為某種設計看起來合理，就假設原系統一定如此。

    - greek 與 中文，用 \r?\n 符號就可以對齊，以此例來說。
      - `Ἀβραὰμ ἐγέννησεν τὸν Ἰσαάκ,` 對應 `亞伯拉罕生以撒，`

    - hebrew 卻要 split 後，還要 reverse，以此例來說
      - `וְהָאָרֶץ הָיְתָה תֹהוּ וָבֹהוּ` 對應 `地是空虛混沌，`

      - `וְרוּחַ אֱלֹהִים מְרַחֶפֶת עַל־פְּנֵי הַמָּיִם׃` 對應 `上帝的靈運行在水面上。`
      - 即 word[2] 對應 exp[0], word[1] 對應 exp[1], word[0] 對應 exp[2]
- `wid`
  - wid: word id
  - 這一節的 id, 用來辨別每個原文 1based.
  - 例如 `Βίβλος γενέσεως Ἰησοῦ Χριστοῦ υἱοῦ Δαυὶδ υἱοῦ Ἀβραάμ.`
    - 分別 wid 就是 1 2 3 4 5 6 7 8
  - 從上例可知，就算有同一個字，字序出現2次，還是2次
  - 我印象中，我有用這個特色，滑鼠移到上面原文時，是可以知道是下面 table 原文的哪一個。
  - `+` 若原文出現這個，仍然算一個 wid，下面會介紹到。
- `+` 號
  - `Ὀζίας δὲ ἐγέννησεν τὸν Ἰωαθάμ,\nἸωαθὰμ δὲ ἐγέννησεν τὸν + Ἀχάς + Ἀχάζ +, \n+ Ἀχὰς + Ἀχὰζ + δὲ ἐγέννησεν τὸν Ἑζεκίαν,`
  - 原文可能有 「韋式」與「聯合聖經公會 (UBS5)」的差別，會用 + 號隔開。
  - 通常就 3 個一組 `+ {韋式} + {聯式} +`
  - `+` 號也佔一個 wid。
    - 以此例，6 個 `+` 的 wid 分別是 10 12 14 15 17 19。
  - 通常韋式用黃色背景，聯式用紅色背景，當然，之後換成 cssVar 更好，因為深色背景可能用到
    - 這是第一組的例子 render 後，呈現的例子 `<div class="greek-char"><span wid="6" class="sn-btn">Ἰωαθὰμ</span> <span wid="7" class="sn-btn">δὲ</span> <span wid="8" class="sn-btn">ἐγέννησεν</span> <span wid="9" class="sn-btn">τὸν</span>  <span wid="11" style="background-color: rgb(255, 255, 153);" class="sn-btn">(韋：Ἀχάς)</span>  <span wid="13" style="background-color: rgb(255, 204, 204);" class="sn-btn">(聯：Ἀχάζ)</span> , </div>`
    - 上面的 原文 與 原文直譯，會這樣呈現
    - 下面的 各個字的 table 也會 背景顏色不同 [[docs\0911d_原文ver1-data.md:36:39]]
  - 若韋式或聯式，其中一個沒有，會出現類似 `+ + {聯式} + ` 或 `+ {韋式} + + ` 這種，這並沒有錯
- render 使用文，非表格
  - 我記得當時考量是，這樣 copy paste 才會是純文字。在 ai 對話的時代，能複制純文字很重要。
  - 下面的 table，title 是綠色，同樣，將來就變成 varCSS 才好
  - 連接詞，是常常要看的，所以會用另一個顏色。
  - 動詞，在作結構分析時，動詞很重要，所以又用另一個顏色
  - 介系詞，在作結構分析時，容易有「子句」的語感，所以也用另一個顏色。
  - 一個 html 實例 [[docs\0911d_原文ver1-data.md:30:32]]
- render 字型大小
  - 希伯來文，與希臘文，都有獨立的字型大小設定。
- render 原文
  - hebrew 是靠右對齊，從右到左
  - greek 是靠左對齊，從左到右 (中文也是)

# 證據可信度

分析結果請嚴格區分三種：

## Confirmed

有明確程式碼證據。

例如：

> `changeVerse()` 明確呼叫 `reloadCommentary()`。

## Inferred

根據程式結構合理推論，但目前沒有完整證據。

例如：

> `commentaryCache` 看起來是避免重複 API request 使用，但尚未找到所有讀寫位置。

## Unknown

目前程式碼不足以確認。

例如：

> 尚無法確定 cache 是否跨 chapter 共用。

**不要把 Inferred 寫成 Confirmed。**
