# 原文搜尋：信望愛內碼與新舊約（6.5.3）

在搜尋框輸入希臘文或希伯來文，就查原文：

| 輸入 | 查的譯本 | 怎麼查 |
|---|---|---|
| 希臘文 | 新約原文 `fhlwh` + 七十士譯本 `lxx` | fhlwh：`ssn.php` 以內碼查；lxx：`se.php` 以 Unicode 查 |
| 希伯來文 | 舊約原文 `bhs` | 載入 `index/bible_bhs_code.json.gz`，在本機以 regex 比對 |

不論目前選了哪些譯本（`SearchSession` 的 constructor 直接換掉 `versions`）。

起因：同事提醒「新約原文你直接用 unicode 找對吧？要用內碼來找」，並舉 `29641 | 1 Thess | 5 | 19 | to; pneu'ma mh; sbevnnute,` 為例。

---

## 1. 核心觀念：伺服器存的是「信望愛內碼」

FHL 很早期的資料庫，希臘文、希伯來文都用一套 ASCII 編碼存（配合當時的字型），顯示時才由 PHP 轉成 Unicode。

| | 內碼例 | Unicode | 轉換 (PHP → 本專案) |
|---|---|---|---|
| 新約 | `to; pneu'ma mh; sbevnnute,` | τὸ πνεῦμα μὴ σβέννυτε, | `gcode($t, 2)` → `index/gcode2.es2023.js` `gcode_2` |
| 舊約 | `~yih{l/a a"r'B` | בָּרָא אֱלֹהִים | `umscode()` → `index/hebCode.es2023.js` `umscode` |

PHP 原始碼在 `VirtualApi/api_php/code.php`。

### 看起來一樣、其實不同的字元（最容易踩的坑）

- **希臘文重音**：FHL 用 oxia（έ U+1F73），鍵盤與 NFC 正規化產生 tonos（έ U+03AD）。
- **希臘文標點**：`{` → U+0387（·）、`}` → U+037E（;），NFC 後變 U+00B7、ASCII `;`。
- **希伯來文組合符號順序**：PHP 的 שׂ 是 05E9 05C2 05BC（點在 dagesh 前），NFC 是 05E9 05BC 05C2。
- **編輯器與工具會偷偷正規化**：在測試裡寫希臘、希伯來字面字串，存檔後可能已被換掉。**測試的預期值一律用 `\u` 寫**；對照表從 PHP 原始碼用程式取出，不要手抄。

---

## 2. 新約原文（fhlwh）

### API 的現況

- `se.php?VERSION=fhlwh` → `Fail:fhlwh not found!`，se.php 不支援 fhlwh。
- `ssn.php`（新約字彙分析，`bible.fhl.net/new/ssn.php`，回 **HTML**）可以查：
  - `word`（原文字）/ `orig`（原型）：**信望愛內碼**，可靠。
  - `uword` / `uorig`：Unicode，但**字尾 σ/ς 的字與 tonos 輸入都查不到**（λόγος 0 筆；`lovgos` 68 筆）。
  - **前綴比對**：`lovgo` → λόγος λόγου…（277 筆）；`ovgo` 0 筆。
  - **上限約 500 筆**，超過回「資料太多，共有 N 筆」，沒有 `offset` / `limit`（試過 offset、limit、page、start、from、max、all 都無效）。
  - 可加 `engs=Matt` 只查一卷。
  - **沒有 CORS**。

### 做法（`SearchApi_es2023.js`）

1. `greekToFhlCode`（`index/greekToFhlCode.es2023.js`）：Unicode → 內碼，`gcode_2` 的反向。
   - 對照表由 `gcode_2` 的表（`GCODE2_TABLES`）反推。
   - tonos / oxia / NFD 輸入都接受；σ、ς 都轉 `s`。
   - 大寫用與小寫相同的符號（`AJ` `A[` `Aj`，即資料庫的寫法；orga 表裡的 `A%` `A~` 沒在用）。
2. `searchFhlwhAsync`：每個詞查 `word` 與 `orig` 取聯集（原型搜尋可找到變化形，例 πνεῦμα → πνεύματος）；多個詞取交集。
3. `searchSsnAsync`：超過上限時改成逐卷查（27 卷）；逐卷仍太多的書卷列在狀態列「原文結果太多，未列入」（例 καί：太、可、路、約、徒、啟）。
4. `parseSsnHtml`：從 `href="fhlwhparsing.php?engs=…&chap=…&sec=…"` 取出位置。
5. 網址：開發時 `http://127.0.0.1:15600/new/ssn.php`（**VirtualApi proxy，要先啟動**），上線時同源 `/new/ssn.php`（NUI 要部署在 bible.fhl.net 底下）。

### 七十士譯本（lxx）

`se.php?VERSION=lxx` 直接用 Unicode 查即可（子字串、依經文原樣：`καί` 查不到 `καὶ`、`λόγος` 查不到 `λόγον`）。

## 3. 舊約原文（bhs）

### API 的現況

- `se.php?VERSION=bhs`：存的是內碼，**Unicode 查一律 0 筆**（不報錯，使用者只看到查無資料）。回傳的 `bible_text` 就是內碼。
- q 直接放進 SQL LIKE：`%`、`_` 是萬用字元（`q=%` 取得全舊約 23144 節），有 `limit` / `offset`。
- 但 LIKE **分大小寫**，而 dagesh 變體多半只差大小寫（`y` י / `Y` יּ、`b` ב / `B` בּ），只用子音也粗篩不了（אלהים 只剩 `a`，21727 節）。

### 內碼的特性

- **視覺順序**（由左到右，字型用）：`umscode` 把整個字串反轉。多行經文連行的順序也倒了，所以 `qsb.php` 取 bhs 後要把行再反轉（主畫面 `modify_bhs_bible_text`；搜尋在 `queryQsbAsync`）。
- 母音在它所屬子音之前（視覺順序）。
- 母音有三組碼（瘦 / 胖 / 右），PHP `mscode` 依子音選；資料庫實際：瘦子音配瘦母音、胖子音配胖母音，ד ר（畸形子音）大多配瘦母音但 holam 用 `o`；還有 furtive patah 等例外。資料庫全是 ASCII，沒有 161–170 的「右母音」。

### 做法

1. `tools/gen_bible_bhs_code.mjs`（`npm run gen:bhs`）以 `se.php?q=%` 分頁取得全舊約內碼，存成 `index/bible_bhs_code.json.gz`（約 950KB，格式同 `bible_fhlwh.json.gz`：`{col, data: [[book, chap, sec, code]]}`）。
2. `Bible_bhs_code_json`（`BaseJson`）第一次搜尋希伯來文時才載入。
3. `hebSearchRegex`：**不反推成單一內碼**，而是產生在內碼上比對的 regex：
   - 子音：dagesh、shin/sin 點有打才要求；字尾形視為相同。
   - 母音：沒打不限（希伯來文鍵盤預設不打母音）；有打就要剛好那些，三組碼皆可、順序不限。
   - 重音符號（cantillation）、meteg 忽略；多個詞（空白、maqaf）取交集。
4. 上色 `hebLooseRegexSource`：只比對字母，中間可以有任何附加符號。搜尋結果的 bhs 經文 `dir="rtl"`。

## 4. 驗證方式

全部拿「伺服器的內碼」與「伺服器轉好的 Unicode（`qsb.php`）」整本比對：

| | 資料 | 結果 |
|---|---|---|
| `gcode_2` | `bible_fhlwh.sqlite`（VirtualApi）全新約 7958 節 vs `qsb.php` | 除換行位置外全同 |
| `greekToFhlCode` | 全新約 19785 個字，來回轉換 | 19776 個一致 |
| `umscode` | `se.php` 全舊約 23144 節 vs `qsb.php` | 完全相同 |
| `hebSearchRegex` | 全舊約 54079 個字，找得到自己 | 打母音 54042、只打子音 54050 |

測試：`npm test`（vitest，`tests/*.test.js`；fixture 由全本資料用貪婪法挑出涵蓋所有字元的經節）。

### 順帶修正的舊程式問題

- 舊 JS 版 `gcode_2` 多了「相容舊碼」把落單的 `v ; j J` 轉成 ς ᾽ · ;，PHP 是照原樣輸出 → 移除（VirtualApi 的 `gcode2.js` 也一併修正）。
- `bible_fhlwh.sqlite` 有兩個當初轉碼弄錯的字元：U+0358（`o͘`）是 `u`、U+1E73（`ṳ`）是 `ii`（只在提後 2:16）。

## 5. 已知限制

- 新約：極常見的字（καί ὁ ἐν…）在大卷書逐卷查仍超過上限，不列入。
- 新約：資料庫的 `h~` `w~`（應是 ᾐ ᾠ，例 ᾐτήσατο），PHP 轉成 ἤ ὤ，打 ᾐτήσατο 查不到（全新約 9 個字）。
- 新約：原型搜尋找到的變化形不會上色（搜 Χριστός，經文的 Χριστοῦ 不上色）。
- 七十士譯本：依經文原樣比對，重音不同就查不到。
- 舊約：資料更新時要重跑 `npm run gen:bhs`。

## 6. 可以請伺服器端改善的

- `ssn.php` 加上 `offset` / `limit`，或讓 `se.php` 支援 `VERSION=fhlwh`（可拿掉逐卷查與 HTML 解析）。
- `ssn.php` 的 `uword` / `uorig` 字尾 σ/ς 查不到。
- `se.php` 的 bhs 支援 Unicode 查詢，或 LIKE 不分大小寫。
