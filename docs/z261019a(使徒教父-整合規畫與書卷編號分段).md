# 使徒教父：整合規畫與書卷編號分段

2026-10-19 規畫。P0 於 7.6.4.1 完成，P1 起尚未實作。來源：另一專案（FHL-MCP-Go）整理的信望愛 `qaf.php` / `seaf.php` 整合指南，加上本專案實測。

## 決定：書卷編號用上游的真實 id，每一類佔一個百位段

| 範圍 | 內容 | 狀態 |
| --- | --- | --- |
| 1–66 | 新舊約 66 卷（現有） | 已有 |
| 101–199 | 次經（`qsub.php` / `sesub.php`，上游 101–115） | 之後 |
| 201–299 | 使徒教父（`qaf.php` / `seaf.php`，201–217） | 本次 |
| 301– | 日後新增的資源，同類再用下一個百位段 | — |

好處：上游 id 即站內 id，不用 `book + 134` 之類的轉換，hash、歷史記錄、API 參數都是同一個數；日後同一類有新書，插在自己的百位段就好，不影響其他類。

代價：**id 不再連續，不能再當陣列索引**。現有程式大量使用 `ARRAY[book - 1]`（`index/` 與 `libs/` 約 53 處、29 個檔案）與 `book <= 66` 的上限檢查（約 12 處）。所以第一步要先建一個「書卷註冊表」，把這些查詢收斂進去。

## 上游 API（實測）

- 基底用 **`https://bible.fhl.net/api/qaf.php`**。`/json/qaf.php` 是另一支不認 `bid` 的端點（永遠回革利免一書），不能用；`qsb.php` 在 `/json/`，這兩者路徑不同，不能照抄 `qsbAsync` 的 `/json/` 前綴。`/api/` 回 `Access-Control-Allow-Origin`（回 request 的 Origin），dev (`127.0.0.1:5173`) 可直接 `fetch`。dev 時 `qsb` 走本機 `127.0.0.1:15600`，那個後端有沒有 `/api/qaf.php` 未確認，P1 先直接打 `bible.fhl.net/api`。
- `qaf.php?bid=212&chap=1&strong=0[&sec=1-2]`：省略 `sec` = 整章。回 `record[]`（`engs`、`bid`、`chineses`、`chap`、`sec`、`bible_text`）與 `prev` / `next`（會跨書）。
- **章節不存在** 仍回 `success`、0 筆。
- **`chap=0` 被當成 `chap=1`**，不會回導論。導論只出現在 `seaf.php` 的 `chap:0 sec:0` 命中。
- **`sec=0` 是真的有的**：`210:14`、`211:4`、`211:21` 整章只有一個沒編號的段落。
- 數字欄位型別不固定（數字或字串），收進來要統一轉成數字。
- `sec` 格式不合時，上游會在 `status` 夾 SQL 片段，所以送出前要先擋（`^[0-9]+(-[0-9]+)?(,[0-9]+(-[0-9]+)?)*$`）。
- 網頁端不需要 User-Agent；Python 預設 UA 會被 403（只影響腳本）。

## 設計

### 1. 書卷註冊表（先做，其他都建立在這上面）

新增 `index/BookRegistry.es2023.js`：

- 以 id 為 key 的 `Map`，每筆：`id`、`corpus`（`'canon' | 'af' | 'apo'`…）、`nameZh`、`nameZhGb`、`abbrZh`、`abbrZhGb`、`engs`、`chapCount`、`verseCounts[]`。
- 1–66 由現有 `BibleConstant` 陣列填入（不動原陣列，舊程式照常運作）；201–217 由 `af_books.json` 填入。
- 提供：`corpusOf(id)`、`isCanon(id)`、`has(id)`、`nameFull(id, gb)`、`nameShort(id, gb)`、`countChap(id)`、`countVerse(id, chap)`、`nextBook(id)` / `prevBook(id)`（同類別內，跨類別時是否銜接另外決定）、`bidOf(id)`（上游 API 用的 id，目前恆等）。
- `BibleConstantHelper` 的 `getCountChapOfBook` / `getCountVerseOfChap` / `getNextAddress` 改委派給註冊表，並移除 `book > 66` 的錯誤。
- 把 `X[book - 1]` 的 53 處逐一改成註冊表呼叫。其中只用在 canon 的（如 TSK、SN 計數、audio）可以改成 `isCanon(book) ? … : null`，不必支援新類別。

### 2. 取經文

`index/qafAsync.es2023.js`：`qafAsync({ bid, chap, sec })` → 驗證參數、`fetch`、數字正規化、補 `book` 欄位，輸出同 `TpOneRecordBibleText` 的形狀，讓 `FhlLecture` 不用知道來源。

`lecture_get_data_async`：`corpusOf(book) == 'af'` 時改走 `qafAsync`。**版本欄固定一欄**（使用者選的譯本不適用），欄名顯示「使徒教父（黃錫木）」。快取：記憶體 Map（鍵 = bid + chap），不寫 localStorage。

**不內嵌全文**：版權條件未查證（黃錫木主編，信望愛提供），所以不做 `.json.gz`。

### 3. 路由與選書

- `location.hash` 的書卷欄允許 201–217；`hash_change_on_initial.makesure_correct_address` 的上限 `66` 改為「該書所屬類別是否存在 + 章節範圍用註冊表」。
- `BookSelectName` 加「使徒教父」群組（17 本），章選擇（`BookSelectChapter`）靠註冊表。
- 上一章 / 下一章：優先使用上游回的 `prev` / `next`（會跨書）；若失敗用註冊表同類別內計算。

### 4. 附屬分頁

| 分頁 | 做法 |
| --- | --- |
| 原文 (parsing)、SN、串珠 TSK、地圖、有聲、講道、典藏 | 非 canon 時停用並顯示「此書沒有…」，不要空白或報錯 |
| 註釋 | `sc.php` 是否有這些書未確認；先停用 |
| 書卷背景 / 導論 | 取自 `seaf.php` 的 `chap:0` 命中，轉純文字（內含 `<h2>`、`<br/>`）；找不到則不顯示 |
| 註腳 `【1】` | 原樣保留（沒有取內容的端點） |
| 字型大小、複製按鈕、歷史記錄 | 應該共用現有流程，需在 P1 驗證；歷史記錄的 `book <= 66` 過濾要放寬 |

### 5. 搜尋（P3）

- `seaf.php?q=&offset=&limit=`；沒有 `gb` 參數，關鍵字先轉繁體再送。`limit=0` 等於不限，上限（是否 500）**未驗證**。
- `chap:0 sec:0` 的命中是整篇導論（可達數千字），結果列表要標示「導論」並截斷。
- 搜尋範圍（`SearchScope`）新增分類「使徒教父」。使徒教父與新舊約是不同 API，要分開查、分開分頁，再在畫面上並列，不要混在一個 offset 裡。
- `cvtAddrsToRef` 要認得這些書名與簡稱，交互參照才能點。
