# 複製：Ctrl / ⌘ + 拖曳加選不連續片段 (branch `copy-multi-select`)

電腦上反白一段後，按著 Ctrl (Mac 用 ⌘) 再拖曳，可以加選另一段不連續的文字，一次複製 (`index/LecCopyTable.es2023.js`)。

## 為什麼要自己記

瀏覽器對「多段原生選取」的支援不一：Firefox 的 Ctrl + 拖曳會有多個 `Range` (`rangeCount > 1`)；Chrome / Safari 永遠只有一個，新選取會取代舊的。
所以：

- 先前選好的片段自己記在 `#extra` (`Seg = { scope, range }`)，用 CSS Custom Highlight API (`::highlight(lct-multi)`，色用 `--lct-hl`) 畫出來；現在拖曳中的那段仍是原生反白
- Firefox 原生就有多段時 (`liveSegments()`) 一併收進來；`mergeSegs` 依 DOM 順序排序、重疊 / 相接的併成一段，所以兩邊記到同一段不會重複
- 不支援 Custom Highlight 的瀏覽器：只是沒有顏色，仍可複製

## 流程

| 動作 | 做什麼 |
|---|---|
| Ctrl / ⌘ + pointerdown (在範圍內，滑鼠 / 觸控筆) | `#stashLive()`：現有選取併進 `#extra`，接著瀏覽器開新選取 |
| 一般 pointerdown | 清掉 `#extra` |
| Esc | 清掉 `#extra` |
| 選取換到別的範圍 (經文區 / 搜尋結果 / 交互參照) | 先前的片段作廢 (`#segments`) |
| 片段的節點被重畫掉 (換章) | 該片段自動丟掉 |

`#update` 只要 `#extra` 有東西 (或 Firefox 多段) 就走 `#updateMulti()`：片段 = 先前記下的 + 現在的原生選取；有效的 (`buildTable` 不為 null，只選到被隱藏的 SN 等不算) 超過一段才是多段 (`#multi`)，只剩一段就當一般單段，按鈕不變。

## 按鈕與輸出

多段時只有三顆：**文字 | 連續文字 | 含出處**。每段各自照單段的規則轉 (`multiText`)：

- 文字：每段一行
- 連續文字：段與段以 ` … ` 接 (標明中間有省略)
- 含出處：每段一行、各自帶出處，例 `2 並且造 ...(創5:2_和合本)`
- Ctrl+C：同「文字」，只有 `text/plain`

表格 / MD / ASCII / ⚙ 多段時不提供 (不連續的格要怎麼擺成表格還沒定)。跨格的整格底色 (`.lct-cell`) 多段時也不畫。

## 未做 / 注意

- 觸控沒有 Ctrl，這功能只針對電腦
- Ctrl + 點 (沒拖) 目前不會移除已記下的片段；要取消用 Esc 或一般點一下
- 測試：工具的拖曳不會帶修飾鍵，所以 Ctrl 部分用合成的 `pointerdown` (`ctrlKey: true`) 加 `setBaseAndExtent` 驗證，真滑鼠 Ctrl + 拖曳需手動試；`Range` 邏輯 (`mergeSegs`) 沒有單元測試 (vitest 是 node 環境，沒有 DOM)
- Chrome / Windows 的 Ctrl + 拖曳是否會被瀏覽器本身吃掉 (例如 Ctrl + 點擊的行為)、Mac 的 ⌘ + 拖曳，需實機確認
