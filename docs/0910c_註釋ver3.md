## 1. 功能摘要

**Confirmed。** 輔助資料選到 `fhlInfoComment` 時，以共用頁面狀態中的聖經書卷、章、節與繁簡設定請求註釋，顯示首筆結果的標題、內容、背景／返回及 API 提供的前後段按鈕。內容經純文字預處理、表格辨識、縮排建樹、DText 轉換後，由專用 renderer 建立清單、文字、SN、參照及部分真正的 HTML 表格。證據：`index/FhlInfoContent.es2023.js:196–208`（render 分支）、`index/comment_render_es2023.js:85–122`（comment_render_async）。

### 4.2 純文字到語意樹

以下皆 **Confirmed（靜態）**。

1. **統一換行、先修特例。** `parseComment.js:30–47` 接受地址陣列或物件，將 `/\r?\n\r?/g` 轉 `\n`，先執行 replaceApiResult，再預處理。地址在這階段用來選特例，不會附加在回傳 DocNode 上。
2. **特例表格替換。** `replaceApiResult.js:1–38` 分派約 1:6–8、斯背景、王上背景、代上背景、賽背景與賽 7:10–16。王上／代上使用 `getJoTableOfKingdomOfJudah()` 的硬編表（同檔 `355–361`）。其他表亦以程式內 cells 取代來源文字，並非通用欄寬解析。核心 `741–760` 按三個文字標記定位，找不到任一個就返回原文；以標頭所在行縮排插入單行 JSON，保留前後文字。約翰的專用版本則找標頭與框線角落（`83–100`）。匹配文字為繁體且沒有 gb 對應分派；能確認規則，不能保證簡體實際資料也命中。
3. **行與續行。** `preprocessCaseToLines.js:8–28,155–204`：縮排以行首 `\s*` 字元數計算（非視覺寬度，tab 也是一字元），依出現順序把差距 ≤1 的縮排歸入既有桶。一般行 trim；空行保留並切斷 prev。有前行、縮排較深、兩行皆非表格且新行非新項目，直接串接 content，不加空白或換行。不是全面刪除行內空白，也不是所有固定寬度折行都合併。
4. **保護條目。** 預處理的新項目判斷包括 ◎●○☆、單字母加點、(數字)、數字加點、全形中文括號、大小寫中文數字加頓號、【註數字】及短標籤冒號。短標籤為冒號前 1–8 字，排除含 #/| 的標籤與 joTable JSON，且前或後非空行須同類且原縮排差 ≤1（`preprocessCaseToLines.js:30–76,177–187`）。這只是防止續行合併；不等於都成為 ordered token。
5. **星號 fence。** 出現可帶斜線的至少十個星號進出 raw 區塊；內部每段 trim 後無分隔串接，保留空白行與首尾 fence 行；以 indent=0、isRaw=true 輸出，切斷一般續行。缺結尾亦輸出收集內容（`78–151,207–214`）。註解「preserve exactly」不是實際逐字保留保證。
6. **表格保護與分塊。** 預處理偵測框線、兩側 │、至少五個 dash／─，以及多空白欄頭後的非空 dash 行，阻止續行合併（`189–253`）。detectTableBlocks 則以框線，或欄頭緊接至少十字元 dash 行起表格；遇 ◎●○☆ 或非框線／欄頭／dash 的非空文字退出，raw fence 強制退出（`detectTableBlocks.js:29–101`）。兩階段門檻和是否跨空行不同，不能混寫成一個規則。
7. **Token。** 表格 block 成一個 table token，保存 lines/text；一般行依序辨識 raw、joTable JSON、◎○☆※ note、● lex、`零壹貳參肆伍陸柒捌玖拾+、`、`一二三四五六七八九十+、`、`（中文數字）`、`(數字)`、`英數字串.` 的 ordered，否則 text（`tokenizeLine.js:13–140`）。**`1、` 沒有 ordered 規則。** ※ 在 tokenizer 支援，但不在前處理新項目保護集合；不能保證它在較深縮排時仍成單獨項目。
8. **JSON 表格檢查。** `tokenizeLine.js:150–186` 要求 rows/cols 正整數、cells 陣列；cell r/c 是整數才保留；span 非正整數退成 1；text 轉字串。沒有檢查 r/c 必須落在宣告尺寸內。
9. **縮排建樹。** `buildTree.js:31–108` 預設 useMarkerRankWhenIndentEqual=false；相同或較淺縮排 pop，較深為 child。正式 caller 沒帶選項（`parseComment.js:54`），所以不以「壹→一→（一）→1」自動決定層級。
10. **正規化。** `normalizeTree.js:1–73` 每次 id 從 n1 重置，產生 id/w/type/children/marker；table 保存 raw metadata，joTable 保存結構資料。其註解說兩者都 table，但實際 joTable type 是 joTable（67–69 行）。

### 4.3 DText、SN、經文參照

**Confirmed。** DText 是 JSDoc 描述的資料形狀，不是這條管線逐項 new 的 class。`index/DText.js:62–92` 定義 refAddresses、children、childrenlist、joTable、marker 等；`comments/TpComments.js:14–17` 引用它。現行註釋使用 children 表示行內片段、childrenlist 表示下層清單；不是通用 HTML tag 容器的完整功能。語意樹、API 包裝與標題按鈕也不是 DText；只能確認正文這條路會通過 DText，不能說全專案或所有 HTML 都先轉 DText。

`convertDocToDText.js:14–92` 遞迴映射 DocNode，捨去 id、一般 type 與大部分 metadata；保留 marker、lex、childrenlist，將 w 轉 inline children，joTable 的 cell.text 亦轉 inline content。raw table 則保留 w、再建立 inline children，不把 rawLines 變為 HTML cells。

SN：`convertDocToDText.js:100–140` 用 `/SN(G|H)\s*([0-9]+)(a?)/gi`，去數字前導零，保留可選 a 尾碼；顯示如 G5547/H4899，產生 sn/tp/tp2。連續 SN token 無普通文字間隔才插「、」；原有 `+` 或空白不會被替換。語言取每個 token 的 G/H，不取當前書卷的新舊約。regex 不分大小寫但輸出 tp 未轉大寫，事件僅比較大寫 H（`comment_register_events_es2023.js:49–51`）；小寫 h 的下游語言判斷不能視為已正規化。

參照標記：`convertDocToDText.js:148–192` 只把 `#([^|]+)|` 轉為 isRef/refDescription，顯示時去 #/|，連續參照才插「、」。缺結尾 | 的字串不成為 commentJump。此時不是完整的經節展開。

**關鍵 caller 差異：** `comment_render_es2023.js:106–110` 把 address 傳給 parseComment，卻呼叫 `convertDocToDText(doc)` 而未傳第二參數。因此 `resolveRefAddress` 在正式路徑因 address 缺省直接返回 null（`convertDocToDText.js:203–205,240–241`），renderer 通常不產生 book/chap/sec attrs（`render_comments_in_dtexts.js:65–74`）。其「裸數字在詩篇代表篇、其他卷代表節」邏輯只是有傳 address 時的能力，不是正式 caller 已接上的規則。

點擊時才完整解析：`comment_register_events_es2023.js:76–102` 以當時 ps 的 `{book,chap,verse}` 呼叫 splitReference(元素文字, defaultAddress)，只取 `dtexts[0]` 交接。`splitReference.es2023.js:109–177` 在同組 refs 內逐項更新書卷／章；省略書卷沿用目前 book，章明示則更新 chap，節範圍沿用 chap；不同群組重新從 default 開始。跨章類型 a 更新 chap 實際寫 `ps[3]`（末節）而非結尾章，143 行可見，不應宣稱所有繼承都正確。單獨純數字 type f 沒書卷會先被降為普通文字（199–223 行）；不能把 `#6|` 一概規格化為同章第六節。

`fix_addr_description`（事件檔 15–39 行）只在描述以數字起頭時補中文書名；沒有冒號，詩篇只加書名，其他卷加目前章（0 改 1），且書名、章、原描述間用空白，沒有補冒號。有 book attr 且沒 refAddresses 才會啟用詩篇等的替代解析（85–90 行）；正式 renderer 因上述 address 缺失不保證此 attr 存在。

## 9. Confirmed / Inferred / Unknown

### Confirmed

- 入口／載入／事件鏈見第 2、3、5 節；FhlInfo、Title、Content 都是 singleton，但 Info.render 僅更新 Content，並非每次同時管理兩者重繪。
- 正文先 DocNode 再 DText；API 原文不是 Markdown，表格包含硬編替換而非全面通用辨識；marker 階層以縮排為準（4.2–4.4）。
- bookIndex 與 book 分離；3 是 state 預設，請求讀 state，沒有硬鎖（4.1）。
- 背景保存的是章／節，沒有書卷與返回 stack；箭頭進背景不保存返回點，故不等同點背景按鈕（5、6）。
- SN 語言按 token；參照在點擊時用當前 state；DText converter 正式呼叫漏第二 address 參數、裸數字不能按其註解視為已接通（4.3）。
- API 樣本證實範圍同文、背景雙箭頭與末段自指；末段「無效果」只能指可見正文可能相同，不能指沒請求或副作用（4.1、6）。
- 繁簡切換會請求內容，但分頁文字陣列只建立一次，符合程式要求 reload 的提示，不保證原頁 Title 文字即時切換（2、5）。

### Inferred

- 缺少取消／序號／分頁核對，可能出現舊回應覆蓋新內容或混用新地址解析舊本文；沒做競態實測（5）。
