# Vite 化：緣由、做法與效果

> 寫給之後接手的 AI（與人）。讀完應該能回答：「為什麼這個專案有 Vite，卻到處都是 `var`、jQuery、`React.createClass` 風格的舊程式？哪些地方可以動、哪些地方不要動？」
>
> 時間：2026-09-25，版本 5.7.1。相關 commit：`93ca36c`（dev server）、`37c5642` … `b74eb11`（build，共 12 個 commit，都在 `main`）。

---

## 1. 一句話總結

這個專案是**十年累積的多代程式疊在一起**：2015–2016 年的 jQuery + React 0.13 元件、一段 webpack 打包的 Vue 2 骨架、作者自製的 `ijnjs` 載入器（XHR 下載後 `eval`），以及 2025 年後改寫的 ES2023 module。

Vite 化**不是重寫**。目標只有一個：**讓首次開頁少載、少等**，並且**畫面與行為完全不變**。所以做法是「在外面包一層 build」，舊程式能不動就不動，只拿掉確定沒在用的東西。

---

## 2. 為什麼要 Vite 化

### 2.1 原本的問題

- **請求太多**：開頁時同網域約 220 個請求。`index/*.es2023.js` 是一支支原生 ES module，瀏覽器要一層層 import 下去（瀑布式）。ijnjs 又用 XHR 一支支下載小檔再 `eval`。
- **傳輸量大**：同網域未壓縮約 3.1MB。其中包含：
  - 沒人用的 Vue 開發版（248KB）
  - 同時載入的 Bootstrap 4.5 與 5.1
  - 兩份 lodash、兩份 jQuery / jQuery UI / linq（`index.html` 一份，ijnjs 又自己載一份）
  - 430KB 的說明圖片
- **同步請求卡住整頁**：`AppVersion` 用同步 `$.ajax` 讀 `app_versions.json`。
- **更新時用強制 reload**：新版本第一次載入會 `location.reload(true)`，但 Chrome 會忽略 `true`，子資源照樣用快取，而且每位新使用者第一次進站都要多載一次。

### 2.2 不能用伺服器解決的原因（重要限制）

- 正式機是 **nginx 1.20.1**，但作者**沒有權限改設定**。
- 所以**沒有 gzip，也沒有 `Cache-Control`**，瀏覽器只能靠啟發式快取（heuristic caching）。
- 因此所有優化都必須在「檔案本身」做：
  - 減少請求數
  - 減少位元組
  - 用網址帶版本號來破快取

### 2.3 其他環境事實

- 這是 **fork** 的 repo。整個工程在 `vite-build` 分支做完、每一步都上傳測試路徑驗證後，才 fast-forward 回 `main`。
- `.gitignore` **故意很寬**（當年為了讓 VS Code 不要偵測太多變更）。新檔案要 `git add -f`。**被 ignore 不代表不該提交。**
- repo 內部分檔案以 **CRLF** 存，部分是 LF。系統 `core.autocrlf=true`，用腳本改檔後直接 `git add`，會變成整個檔案都有 diff。要用：
  ```
  git -c core.autocrlf=false add --renormalize -f <files>
  ```
- 專案路徑含中文（`信望愛`）。在這個路徑下，Node 24 的 `fs.rmSync` 會直接崩潰（0xC0000409）。
  - 所以 `vite.config.js` 關掉 `emptyOutDir`。
  - `npm run build` 改成先用 `fs.promises.rm` 刪掉 `dist/`。

| 新版本首次進站的強制 reload | 有 | 無（改為網址帶版本號） |

- 用 Browser 逐一點過各分頁、對話框、快捷鍵、播放器。

## 4. 現在的程式碼有「三種載入世界」

這是理解本專案最重要的一節。同一頁裡同時存在三種執行方式，各自有規則。

### 4.1 ES module 世界（Vite 真正打包的部分）

- 入口：`index.html` 的 `<script type="module" src="index/index.js">`
- 範圍：`index/index.js` import 到的整棵樹（`index/*.es2023.js`、`index/tsks/`、`index/api/` …）
- build 後：`assets/index-[hash].js` 加上數個 chunk
- 延遲載入（`import()`），見 `FhlInfoContent.es2023.js` 的 `lazyModule`：
  - 註釋、串珠、典藏、AI 分頁
  - SN 資料（第一次 hover 才載入，`ensureSnDataAsync`）
  - `bible_fhlwh.json`（真的要用時才載入）
- **新程式請寫在這裡。**

### 4.2 舊式 classic script 世界（「有 Vite 但看起來很舊」的主因）

- `index.html` 裡一串 `<script src>`：
  - `static/*` 下的舊元件：search、qsb、preach、audio、copyright、fhlmap_main…
  - `index/AppVersion.js`、`FHL.linq.js`、`FHL.tools.js`
  - jQuery 外掛
- 這些檔案**沒有被改寫成 module**。它們大量使用全域變數（`var sephp = sephp || {}`、`var commonR = …`），彼此靠全域互相引用，而且 ES module 那邊也透過 `window.xxx` 或裸名稱呼叫它們。
- build 時由自訂 plugin `bundleLegacyScripts`（見 `vite.config.js`）**原樣串接**成一支 `assets/legacy-[hash].js`，加上 `defer`。
  - 因為是串接而不是打包，top-level `var` 仍然是全域變數，行為與原本逐支載入相同。
  - 必須在 `ijnjs.js` 之前就存在的東西不能放進這裡（因為會變成 defer），只能 inline 寫在 `index.html`。例子：`window._ = { debounce }`。
- dev 模式下 Vite 會嘗試轉換 JS/CSS。所以 `serveLegacyRaw` plugin 讓這些非 module 檔案以原始內容送出。判斷依據是 `Sec-Fetch-Dest` / `Sec-Fetch-Mode`：只有 document 與 ES module 請求才交給 Vite。

### 4.3 ijnjs 的 XHR + eval 世界

- `libs/ijnjs/`、`libs/ijnjs-fhl/`、`libs/ijnjs-ui/`：作者自製的載入器與 UI（書卷章節對話框、版本選擇對話框）。
- 載入方式：用 XHR 下載文字，然後 `eval`，再用 `MergeImports` 以 eval 動態合併 class。多層 eval 互相依賴。**直接改成 ES module 的風險很高，所以刻意沒改。**
- 優化方式：build 時由 `preloadIjnjsFiles` 把 16 支小檔預先打包成 `assets/ijnjs-preload-[hash].js`，內容是 `window.__IJNJS_PRELOAD__ = { files: {路徑: 內容} }`。
  - `ijnjs.js` 的 `getCacheAsync` 下載前會先查這份預載內容，有就直接用，eval 流程不變。
  - dev 模式沒有預載檔，照舊下載。
- `libs/ijnjs` 被 `LEGACY_BUNDLE_EXCLUDE` 排除在 legacy 串接之外，因為 `getSrd` 需要從 `document.scripts` 找到自己的網址。
- ijnjs 原本會自己再載一份 jQuery / jQuery UI / linq / lodash / Bootstrap。現在改為先檢查頁面上是否已經有（`pageProvided` / `isProvidedByPage`），有就沿用。

### 4.4 還有一類：執行時才抓的檔案

用 `$.ajax`、`fetch`、`getCacheAsync` 讀的資料或 HTML，例如：

- `index/*.json.gz`
- `app_versions.json`
- `frmUpdated.html`
- `index/DialogTemplate` 以外的 html 片段

這些檔案 Vite 看不到，由 `copyLegacyFiles`（`LEGACY_COPY` 清單）原樣複製到 `dist/`。

**新增執行時才讀的檔案時，記得確認它在 `LEGACY_COPY` 的範圍內。**

## 5. 版本號與快取（沒有 Cache-Control 時的替代方案）

`versionLegacyUrls` plugin 做兩件事：

1. `index.html` 裡本地的 `<script src>` / `<link href>`，網址加上 `?v=<檔案內容 hash>`。
2. 在 `<head>` 注入一段 script，patch `XMLHttpRequest.open` 與 `fetch`：同網域的 js/css/html/json/gz/txt/md 請求一律加上 `?v=<BUILD_ID>`（`assets/` 本身檔名已帶 hash，所以略過）。

因此：

- 原本「新版本第一次載入就 `location.reload(true)`」的機制已移除。
- `app_versions.json` 仍用 `cache: false` 讀取，因為它的用途就是偵測有沒有新版。現在一頁只讀一次：`AppVersion.s.getVersionsTextAsync()` 共用同一個下載。
- 發版時仍要改 `index.html` 的 `currentSWVer`，以及 `app_versions.json`。

## 7. 不要動的地方（地雷清單）

1. **`index.html` 的 `<head>` 裡有 `<div class="markdown-body">`。**
   - HTML parser 遇到它會提早結束 `<head>`，之後的 `<link>` / `<script>` 其實都在 `<body>`，包括 Vite 注入的 css link。
   - 目前的 CSS 先後順序依賴這個結構。**不要移除，也不要把它後面的東西搬進 head**，除非做過全頁 computed style 比對。
2. **CSS 先後順序**（由前到後）：
   1. jQuery UI css
   2. `index/bs4-compat.css`：帶 `vite-ignore`，刻意不併入 Vite css，留在 BS4 原本的位置
   3. bootstrap-icons、github-markdown css
   4. Bootstrap 5 css：由 `index.js` 在啟動時 append 到 `<head>`
   5. `fhl.css`：`index.js` 在啟動最後以 `<style>` 插入
   6. Vite 打包的 css：在 `<body>`
   7. leaflet.css：切到地圖時 append 到 `<head>` 最後。前後順序等同原本位置，實測 0 差異。
3. **frmUpdated.html 同時有 `data-toggle` 與 `data-bs-toggle`**，因為它也可能單獨以 BS4 開啟。
4. **ijnjs 的 eval 流程**：見 4.3。要改請整組改，不要只改一支。
5. **不要從 `document.scripts` 或模組自己的檔名推算路徑**。build 後 module 會變成 `assets/index-[hash].js`，請用相對於頁面的路徑。
6. **使用者端常常拿到舊版 CSS**（heuristic cache）。會壞掉的關鍵樣式要 inline；畫面不對時，先懷疑樣式沒生效。

## 8. React 移除的細節（為什麼 `static/` 看起來像 React 卻不是）

原本 12 個檔案提到 React，實際在用的只有 4 個功能：

| 功能 | 現在 |
|---|---|
| 講道分頁 | `preach_api.Frame` / `OneFrame`（`static/preach_api/preach_api.js`） |
| 講道裡的播放器 | `commonR.audio.Frame` / `Playrate`（`static/commonR/audio.js`） |
| 進度列 | `commonR.Processbar`（`static/commonR/processbar.js`） |
| 版權宣告 | `copyright_api.render(container, versions)` |
| 有聲聖經版本選單 | `audiobible.render_version_dropdown`（`static/bible_audio_api/audiobible_api.js`） |

- 改寫時**刻意保留原本的 props / state / setProps / render 結構與命名**，所以讀起來仍像 React 元件。這樣方便對照舊版、逐字比對 DOM。
- 共用工具在 `static/commonR/h.js`：
  - `commonR.h(tag, props, ...children)`：取代 `React.createElement`。style 輸出格式與 React 相同（`k:v;`），數字自動加 px。
  - `commonR.setStyle(el, style)`
  - `commonR.syncChildren(parent, nodes)`：更新子節點時，已存在的節點原地保留，播放中的 `<audio>` 不會被搬動或重建，相當於 React 的 reconcile。
- 早已沒在用、直接刪掉的：
  - `static/fhlmap_api/fhlmap.js`：地圖早就改用 `fhlmap_main.js` 的 leaflet。
  - `static/search_api/sephp.react.txt.txtSn.js`
  - 舊版串珠：`index/renderTsk.es2023.js`、`static/tsk_api/tsk.*`。現在的串珠是 `index/tsks/`。
- `static/libs/react/` 檔案還在，只是不再載入；`copyLegacyFiles` 仍會把它複製到 `dist/`。
- `index/FhlInfoOb.es2023.js`（典藏）是更早就從 React 改寫的 ES module 版本，註解裡的「react props / state」指的是原本的對照。

## 9. 開發與驗證方式

- `npm run dev` → `http://127.0.0.1:5173/`
- `npm run build` → `dist/`
- `npm run preview` → `http://127.0.0.1:5175/`（測打包版一定要用這個，dev 模式沒有 legacy 串接和 ijnjs 預載）
- 部署：把 `dist/` 整個上傳。作者的習慣是先上傳到測試路徑實際使用，確認後才繼續下一步。
- 驗證畫面不變的做法：
  - 在同一個 origin，先存下改動前的 computed style 或 innerHTML（存在 `sessionStorage` / `localStorage`），改完後再比對。
  - 注意：不同 port 是不同 origin，localStorage 裡記的經節與分頁也不同，內容自然不一樣。
- 量請求數：`performance.getEntriesByType('resource')`。

## 10. 還沒做、可以考慮的

- `index/queryReferenceAndShowAtDialogAsync.es2023.js` 所在的 chunk（約 103KB）開頁就會載入。它被 6 個模組靜態 import，而且和經文區、註釋、網址初始化綁得很緊，改成延遲載入的風險中等。
- `github-markdown.min.css`（約 5KB）只作用在 `<head>` 裡那個空的 `div.markdown-body`，可以拿掉，但要先做 computed style 比對。
- `static/` 的舊元件仍是全域變數加 jQuery。若要改成 ES module，要先處理它們與 `index/*.es2023.js` 之間透過 `window` 的互相呼叫。
- 已知但未修的既有 bug：`ParsingPopUp` 的 `parseRef` 與 `FHL.ParsingReferenceToAddresses` 裡的 `BibleBookNames` 未定義。
