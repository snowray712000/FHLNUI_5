## 1. 功能概述

「同源字」是 Strong's Number (SN，聖經原文編碼系統) 字典系統的延伸功能：**同一個希臘文/希伯來文字根衍生出的不同 SN，彼此稱為「同源字」**。例如 SN=1000 的同源字包含 292b、293、306... 等數十個 SN。

這個功能在原文聖經閱讀介面中扮演兩種角色：

1. **視覺提示**：滑鼠移到經文中某個帶 SN 的字時，畫面上所有與它同源的字（可能出現在同一節、同一頁的其他地方）會被標成同一種顏色，幫助讀者一眼看出「這些字是同一字根衍生的」。
2. **明細查詢**：同時（或點擊時）彈出一個對話框，列出該 SN 的完整同源字清單，包含每個同源字的簡義與在全本聖經中的出現次數，方便讀者深入查考字義關聯。

命名由來（原始碼註解）：
> `sd`：因為 API、sd 是 sn dictionary 的縮寫，所以才這樣命名。（見 `index/Sd_same_json.es2023.js:5`）

## 2. API 規格：`sd.php`

### 2.1 Endpoint

```
GET /json/sd.php?k={sn}&N={N}&gb=0
```

- 正式站主機：`http://bible.fhl.net`（程式中組 URL 時，正式環境省略 host，直接用相對路徑 `/json/sd.php...`，交由部署環境的網域處理）
- 本機開發環境（判斷式 `isRDLocation()` 為真時）改走 `http://127.0.0.1:5600` 這個本機 Python Flask proxy，用來規避瀏覽器 CORS 限制（正式站 API 不允許本機開發網域直接呼叫）

### 2.2 參數

| 參數 | 說明 | 範例 |
|---|---|---|
| `k` | Strong's Number（原文字），字串，可能含前導 0 | `2424`、`0128` |
| `N` | 新舊約別。`0` = 新約（希臘文 Greek），`1` = 舊約（希伯來文 Hebrew） | `0` |
| `gb` | 固定傳 `0`（簡繁碼相關參數，本功能固定值，非重點） | `0` |

範例請求：`GET http://127.0.0.1:5600/json/sd.php?N=0&k=2424&gb=0`

### 2.3 回傳結構

```jsonc
{
  "status": "success",        // 失敗時非 "success"，前端視為查無資料
  "record": [
    {
      "dic_text": "...",      // 中文字典本文（HTML片段），非同源字功能重點
      "edic_text": "...",     // 英文字典本文，非同源字功能重點
      "same": [                // ← 同源字明細陣列，本功能核心資料
        {
          "csn": "1234",       // 同源字的 Strong's Number（可能含前導0，使用前需去除）
          "cexp": "簡要字義說明（可能包含交互參照文字，如「太1:1」）",
          "ccnt": 142,          // 該同源字在全本聖經中出現的次數
          "word": "原文字形"
        }
        // ... 陣列中通常也會包含「自己」這一筆（csn == 查詢的 sn），使用時需過濾掉
      ]
    }
  ]
}
```

**注意**：`sd.php` 回傳的字串本身已經是合法 JSON 物件字面量，**不應該再對它呼叫 `JSON.parse`**。原始碼中特別以註解提醒這點：

> `res(reStr) // sd.php 回傳本來就是一個 json 物件，所以不要再用 JSON.parse`
> （`index/SnDictOfCbol.es2023.js:32`）

（但舊版 `ijnjs/SnDictOfTwcb.es6.js` 仍誤用 `JSON.parse`，屬已知技術債，見第7節）

### 2.4 呼叫方失敗處理

- 若本機開發時 `127.0.0.1:5600` 代理連不上（timeout 1000ms），會 fallback 讀取本機靜態假資料檔 `index/sd_virtual_new.json` / `index/sd_virtual_old.json`（依新舊約分開），模擬 API 回應格式，讓開發環境在無網路/無 CORS 權限時仍可運作。
- 若 `status != "success"` 或 `record.length == 0`，前端視為「找不到資料」，不拋錯，而是 resolve 一個錯誤字串（見 4.1 節程式碼）。

## 3. 靜態資料檔規格

除了即時 API 呼叫外，App 啟動時會**預先下載**兩份壓縮 JSON（`.json.gz`，以 pako 解壓），用於畫面上的「同色高亮」與「次數顯示」，兩者都**不含**同源字的簡義文字（那只在即時 API 回傳的 `same[].cexp` 裡才有）。

### 3.1 `sd_same.json` / `sd_same.json.gz`（同源字對照表）

**Schema**：
```jsonc
{
  "hebrew": {},   // 希伯來文（舊約）目前恆為空物件 —— 尚無同源字資料
  "greek": {
    // key: 去除前導0的 SN 字串；value: 與它同源的所有 SN 字串陣列（含自己本身）
    "1000": ["292b", "293", "306", "311", "474", "577", "579", "580", "906",
              "955a", "956", "992", "1001", "1225", "1228", "1544", "1546",
              "1685", "1911", "1915", "2598", "2602", "3036", "3328", "3846",
              "3851", "3850", "3924a", "3925", "4016", "4018", "4261", "4820",
              "5146", "5234", "5235", "5236", "5260"],
    "1003": ["1003"],          // 沒有其他同源字時，陣列僅含自己
    "1006": ["1008"],
    "1008": ["1006"]           // 關係是對稱的：1006↔1008 互為同源
  }
}
```

- 檔案來源：由 Python 腳本產生（非即時 API 動態生成），若正式 API (`sd.php`) 更新，需要重新手動產生此檔並替換。
- 檔案大小約 564 KB（未壓縮 `.json`），改用 `.gz` 版本以提升載入效率。
- 類別封裝：`index/Sd_same_json.es2023.js`，繼承共用的 `BaseJson`（`get path_json()` 回傳 `"./index/sd_same.json.gz"`，`filecontent` getter 取得解壓後內容）。

### 3.2 `sd_cnt.json` / `sd_cnt.json.gz`（SN 出現次數表）

**Schema**：
```jsonc
{
  "hebrew": { /* ... */ },
  "greek": {
    "1": 3, "10": 2, "100": 1, "1000": 1, "1001": 2, "1003": 2,
    "1004": 1, "1005": 2, "1006": 9, "1007": 1
    // key: 去除前導0的 SN；value: 該 SN 在全本聖經（該約）出現的總次數（number）
  }
}
```

- 檔案大小約 158 KB。
- 類別封裝：`index/Sd_cnt_json.es2023.js`（結構與 `Sd_same_json` 對稱，`path_json` 為 `"./index/sd_cnt.json.gz"`）。

### 3.3 載入時機

兩者都在 App 啟動階段由 `index/load_json_gz_Async.es2023.js` 平行載入（與其他靜態資料一起 `Promise.all`），並掛到全域 `window.Sd_same_json`，供尚未模組化的舊程式碼存取。載入完成前，`filecontent` 為 `null`，呼叫方需自行判斷 `!= null` 才能使用（見 4.2 節 `act_add`）。

```js
function get_dict_async(one) {
    let result_from_cache = SnDictCache.try_get_clone(one)
    if (result_from_cache != undefined) { /* 命中快取，直接回傳 */ }

    let sn = one.sn
    let tp = one.tp
    let N = tp == 'G' ? 0 : 1
    let endpoint = `/json/sd.php?k=${sn}&N=${N}&gb=0`
    let host = isRDLocation() ? 'http://127.0.0.1:5600' : ''
    let url = host + endpoint

    return new Promise((res, rej) => {
        $.ajax({
            url,
            success: a1 => {
                if (a1.status == "success" && a1.record.length > 0) {
                    SnDictCache.add(one, a1)
                    a1.one = one
                    a1.src = "cbol"
                    a1.isOld = tp == 'H' ? 1 : 0
                    res(a1)
                } else {
                    res("找不到資料 get_dict_async a")
                }
            },
            error: er => res("找不到資料 get_dict_async b")
        });
    })
}
```

### (B) 顏色高亮：同源字同色標記

**`act_add(sn, tp)`** — `index/SN_Act_Color.es2023.js:31-62`

```js
act_add(sn, tp){
    // 本體標記 .snAct（紅色）
    let cod1 = `[sn=${sn}][tp=${tp}]`
    let needAddClassSnAct = $(this.ids()).find(`.sn${cod1}, .sn-text${cod1}`)
    needAddClassSnAct.addClass('snAct')
```

## 6. 邊界情況與已知坑（建議直接轉為 TDD 測試案例）

1. **舊約無同源字資料**：`tp == 'H'` 時，(A) 彈窗固定顯示「舊約無資料」，不呼叫/不依賴 `same[]`；(B) 靜態表 `sd_same.json.hebrew` 恆為 `{}`，故 `act_add(sn, 'H')` 永遠不會加上 `snAct2`。
   → 測試案例：`tp='H'` 時，不論 `sn` 為何，同源字清單應為空／顯示「舊約無資料」。

2. **前導零處理**：
   - API 回傳的 `same[].csn` 可能含前導0，使用（比對/顯示）前必須 `replace(/^0*/, '') || "0"` 去除（注意 `"00000"` 這種全零字串要保留一個 `"0"`，不能變成空字串）。
   - 靜態表 `sd_same.json` 的 key 與 value 都是「已去除前導0」的字串，呼叫 `act_add` 前呼叫方需自行確保 `sn` 已正規化。
   → 測試案例：`"0128"` 應正規化為 `"128"`；`"00000"` 應正規化為 `"0"` 而非 `""`。

3. **需過濾自身**：
   - (A) 中 `same` 陣列通常包含查詢對象自己（`csn == sn`），渲染前需 `filter(a1 => a1.csn != sn)`。若過濾後只剩 0 筆（原陣列長度 `< 2`），顯示「無」。
   - (B) 中 `sd_same.json` 的 value 陣列同樣包含自己，`act_add` 內用 `same.filter(a1 => a1 != sn)` 過濾。
   → 測試案例：`same` 陣列長度為 1（僅含自己）時應顯示「無」；長度 ≥ 2 時過濾掉自身後才渲染。

4. **排序規則**：(A) 彈窗中的同源字清單依 `ccnt`（出現次數）由高到低排序（`same.sort((a,b) => b.ccnt - a.ccnt)`）。
   → 測試案例：給定亂序輸入，輸出應依 `ccnt` 遞減排列。

5. **已知 bug（來自版本紀錄，設計時應留意但非強制修復）**：「恩典」一詞因為 SN=3588（冠詞「的」）的存在，導致同原文/同源字比對失效，滑鼠移過去不會觸發高亮。原因推測與資料切分（token 邊界）有關，非本文件涵蓋的解析邏輯範圍，但另一專案實作時若有類似「相鄰虛詞干擾字根比對」的情境，應留意此已知案例。

6. **靜態表尚未載入完成時的行為**：App 啟動瞬間 `Sd_same_json.s.filecontent` 為 `null`，此時呼叫 `act_add` 應該只做本體高亮 (`snAct`)，同源字高亮 (`snAct2`) 靜默略過、不拋錯。
   → 測試案例：`filecontent === null` 時呼叫 `act_add`，不應 throw，且不應加上 `snAct2`。

7. **API 查無資料**：`status != "success"` 或 `record.length == 0` 時，不應拋出例外，應回傳一個表示「找不到資料」的可辨識值（原專案用字串），由呼叫端判斷。

8. **不要對 API 回傳值做多餘的 `JSON.parse`**（見 2.3 節）——這是新版特別修正的技術債，另一專案若用 `fetch`/`axios` 等原生方式取 JSON，通常已自動解析，需確認不要重複解析一次。

## 7. 新舊版本差異對照表

| 面向 | 舊版（`ijnjs/SnDictOfTwcb.es6.js`、`index/DialogTemplate/OrigDict.js`） | 新版（`index/*.es2023.js`） |
|---|---|---|
| 模組系統 | 純函式包裝（`XxxEs6Js()`），掛在全域/自執行函式 | ES2023 `class` + `import`/`export` |
| 呼叫方式 | `OrigDict.js` 使用同步 `$.ajax({async:false})`；`ijnjs` 版為一般 async | 一律使用 Promise-based async |

## 8. 建議的 TDD 測試案例清單

依上述規格整理，可作為另一專案測試案例的起點（依測試對象分組）：

### 8.1 SN 正規化（前導零處理）
- `normalizeSn("0128")` → `"128"`
- `normalizeSn("00000")` → `"0"`（不可為空字串）
- `normalizeSn("1000")` → `"1000"`（本來就無前導零，不變）

### 8.2 同源字明細查詢與渲染（對應第4節 (A)）
- 給定 `tp='H'`（舊約），不論 `sn` 為何 → 回傳/顯示「舊約無資料」，不嘗試讀取 `same[]`
- 給定 `tp='G'` 且 `same` 陣列只有 1 筆（自己）→ 顯示「無」
- 給定 `tp='G'` 且 `same` 陣列有多筆 → 過濾掉 `csn == sn` 的自身那筆
- 給定亂序 `ccnt` 的 `same` 陣列 → 排序後應由高到低
- 給定 `same[].csn` 含前導零 → 渲染前應正規化
- API 回傳 `status != "success"` 或 `record` 為空陣列 → 回傳「找不到資料」，不拋例外

### 8.3 同色高亮（對應第4節 (B)）
- `sd_same.json.hebrew` 恆為 `{}` → `tp='H'` 時 `act_add` 不應加上同源字高亮 class
- 給定 `sn` 在同源表中查無對應 key（`undefined`）→ 不應拋錯，僅略過同源字高亮
- 給定同源表 value 陣列含自身 → 高亮時應過濾掉自身
- 靜態表尚未載入完成（`filecontent === null`）→ 呼叫高亮函式不應拋錯，且不產生同源字高亮效果，但本體高亮仍正常運作
- 高亮與清除高亮應為對稱操作（先 add 後 remove，DOM 狀態應完全還原）

### 8.4 次數統計（對應第4節 (C)）
- 次數表尚未載入（`filecontent === null`）→ 回傳 `-2`
- 查無此 SN → 回傳 `-1`
- 查有此 SN → 回傳正確次數（number）

### 8.5 API 呼叫本身（若另一專案也需重建 API client）
- 正確組出 `endpoint`：`N=0` 對應 `tp='G'`，`N=1` 對應 `tp='H'`
- 本機開發環境應改走 proxy host，正式環境使用相對路徑
- 回傳字串**不應**再被 `JSON.parse`（若使用的 HTTP client 本身已自動解析 JSON，需確認未重複解析）
