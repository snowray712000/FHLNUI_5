# 平板：灰框可按範圍加寬；拖圓點到邊緣自動捲動

7.0.12 (2026-10-02)。接續 `docs/z261002a` 第一節「未做」與 `docs/z261001a` (sticky、圓點 `.lct-knob`)。數字是與使用者確認過的建議值。

## 一、灰框 (D1)

### 做法

`index/fhl.css`，全部在 `@media (pointer: coarse)` 裡，電腦版外觀與拖曳不變：

- `.leftWindow > .ui-resizable-handle::before`、`#fhlInfo .ui-resizable-handle::before`：透明、`position: absolute`，`left: -10px; right: -10px` → 可按 32px，看起來仍是 12px
- `#fhlLeftWindow .leftWindowInside > div > .ui-resizable-handle::before`：上下各延伸 10px (目前沒有地方建立這種 resizable，留著無害)
- jQuery UI `resizable` 的 `_mouseCapture` 看 `event.target` 是不是 handle (或在 handle 裡)；偽元素的 hit test 算在 handle 上，所以 touch-punch 照常接手

### 坑：左灰框往右延伸的部分按不到

`#fhlLeftWindow`、`#fhlMidWindow`、`#fhlInfo` 都是 `z-index: 0`，DOM 順序是 左 → 中 → 右。同一層時後面的蓋前面：

- 左灰框是 `#fhlLeftWindow` 的子元素，往右延伸進經文區的那 10px 被 `#fhlMidWindow` 蓋住，按到的是 ❮ (`.chapBack`)
- 右灰框是 `#fhlInfo` 的子元素，`#fhlInfo` 在最後，往左延伸進經文區沒問題

修正：觸控時 `#fhlLeftWindow { z-index: 1; }`。左側欄與經文區本來不重疊，只有灰框延伸的部分受影響。

除錯方法：暫時給 `::before` 一個半透明紅底，看得到範圍 (畫得出來不代表按得到，被蓋住時紅色仍會透過透明的 `.chapBack` 露出來)。

### 代價

經文區最靠左右邊的約 10px，觸控時按下去是拖灰框，不是捲動 / 選字。`#lecMain` 左右各有 50px 留白 (❮ ❯ 箭頭區)，不會蓋到經文。

## 二、拖圓點自動捲動 (D2)

`index/LecCopyTable.es2023.js`。

### 參數

| 參數 | 值 | 說明 |
|------|----|------|
| `LecCopyTable.AUTO_EDGE` | 48 | 手指離捲動容器可見範圍上下緣多近 (px) 開始捲；手指拖到容器外面也算 (圓點有 pointer capture) |
| `LecCopyTable.AUTO_MAX` | 20 | 最快每格 (frame) 幾 px；速度 = 2 + 18 × 深入比例，到邊緣或超出邊緣為 20 (約 1200px/秒) |

不做左右捲：經文區、搜尋結果、交互參照的 grid 欄寬都是 `minmax(0, …)`，不會橫向溢出。

### 流程

- `#knobDown`：記下對角那格 (`fixed`)、被拖的圓點 (`knob`)、範圍的捲動容器 (`scroller`)
- `scrollerOf(el)`：自己或往上第一個 `overflow-y` 為 auto / scroll 且捲得動的元素。`#lecMain`、`.sd-results` 是自己；`.ref-dlg` 是外層 jQuery UI 的 `.ui-dialog-content`。都找不到 → `document.scrollingElement` (捲不動就馬上停)
- `#knobMove`：記下手指位置 `#knobPt`，`#knobPick()` 重算矩形，`#autoScroll()` 啟動 rAF 迴圈
- `#knobPick()`：手指座標先夾回容器可見範圍內側 4px 再 `elementsFromPoint`，手指在範圍外 (表頭、工具列上) 也找得到格
- rAF 迴圈：手指在邊緣區 → `scrollTop += v` → `#knobPick()`；離開邊緣區、捲到頂 / 底 (`scrollTop` 沒變)、放開 (`#knobEnd`) 就停。手指停著不動 iOS 不送 pointermove，所以靠 rAF 持續捲

### 順手修

- **被拖的圓點不藏**：`#placeKnobs` 原本把超出範圍的圓點設 `hidden` (display:none)，被拖的那顆一旦被藏，pointer capture 就斷、拖曳中止。現在拖曳中被拖的圓點直接放在手指位置、不藏
- **矩形翻轉**：拖過對角時 (例如左上那顆拖到對角格下面)，另一顆留在對角那格的角上，不會跑到手指旁邊

## 三、驗證 (iPad Pro 13-inch 模擬器，西 2，unv / tcv2019)

- 從灰框外側 (經文區內約 7px) 拖：左、右灰框都能調寬；12px 本體照常可拖
- 西 2:15 兩欄 sticky → 左上圓點拖到 `#lecMain` 上緣停住：捲到頂，矩形變 1–15 節
- 同一顆往下拖過 15 節到下緣停住：矩形翻轉為 15 起，捲到底 (`scrollTop` 1602/1602)，矩形 15–23 節
- 手指離下緣約 24px 時速度約 11px/格；推到邊緣才全速
- 搜尋結果、交互參照對話框沒在模擬器上實際拖過，只確認了捲動容器 (`.sd-results` 為 `overflow-y: auto`、`.ui-dialog-content` 為 `overflow: auto`)
