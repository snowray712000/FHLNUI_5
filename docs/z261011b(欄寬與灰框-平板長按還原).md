# 7.5.12.1 欄寬與灰框：平板改為長按還原

## 問題
欄寬分隔線 (拖曳調整) 可以「雙擊」恢復預設 / 自動，但平板沒辦法連擊 (第一下就開始拖，第二下對不準細線)。

## 做法
- 滑鼠：雙擊不變。
- 觸控 / 筆：在把手上按住不動 `LONG_PRESS_MS` (600ms) 就還原；手指移動超過 `LONG_PRESS_MOVE` (8px) 算拖曳，不算長按。觸發時 `navigator.vibrate(30)`。
- 共用實作在 `index/ColWidth.es2023.js`：
  - `resetGesture(h, onReset)`：一個把手一個，掛 dblclick + contextmenu(擋掉) + pointerdown；回傳 `{ fired }`。
  - `startLongPress(e, h, onReset)`：在 pointerdown 裡呼叫，給事件委派的把手用 (典藏表頭會重畫，沒辦法一個個掛)。
- 拖曳的 `move` / `up` 都要看 `gesture.fired`：長按已還原就不再改寬度、不存回去 (否則放開手指時，前 8px 內的微小位移會被存成自訂值)。
- 長按觸發時 `ColWidth.apply()` 會重建把手，被 capture 的 pointer 不會再收到 pointerup，所以 `startLongPress` 自己拿掉 body 的 `lec-col-resizing`。

## 套用處
| 地方 | 檔案 |
|------|------|
| 經文閱讀 / 搜尋結果 / 交互參照的譯本欄寬 | `ColWidth.es2023.js` `#createHandle` |
| 搜尋結果 / 交互參照的出處欄寬 | `VerseGrid.es2023.js` `addLabelHandle` |
| 原文解析上下灰框 | `parsing_render_async_es2023.js` `setupSplit` |
| 典藏表格欄寬 | `FhlInfoOb.es2023.js` `.ob_colgrip` |

## css
`.lec-col-handle`、`#parsingSplit` 加 `-webkit-touch-callout: none` 與 `user-select: none`，避免 iOS 長按跳選單 (`touch-action: none` 原本就有)。

## 沒做 / 注意
- 左右側面板的灰框沒有「還原」功能，所以不在範圍。
- 還沒在實機 iPad 上驗證，只過了語法檢查與 vitest。
