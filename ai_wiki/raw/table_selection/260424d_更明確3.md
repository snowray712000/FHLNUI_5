複製動作的觸發方式要不要明定。是只支援使用者按 Ctrl/Cmd+C，還是拖曳結束後也允許 UI 上有「複製」按鈕，或右鍵選單之後才 copy。這會影響 clipboard API 的接法與瀏覽器權限限制。

- ctrl/cmd + c 一定是要有
- 但也允許有其它按鈕或右鍵選單支援
  - 因為平板沒鍵盤

---

進入「選取模式」的門檻要不要定義。像 pointerdown 後移動幾個 px 才算拖曳，不然很容易把正常點擊誤判成選取。桌機和平板通常門檻值不一樣。

- pointerdown 後，若 pointermove 超過裝置門檻距離，則進入 cell selection mode；桌機預設 4 px，平板預設 10 px。未超過門檻前不改變 selection 狀態，且視為一般點擊。

---

平板上的長按是否要介入。你現在定了單點、拖曳，但還沒明講長按要不要進選取模式，或完全交給瀏覽器原生行為。這會直接影響 iPad / Android 上原生 callout、放大鏡、文字 handles。

- 思考ing
  - 先了解不太明白的字眼
    - callout
      - 「按住跳出功能選單」
      - iPad Safari 常見
    - 原生文字選取 handles: 也就是出現兩個拖曳把手，用來調整選取範圍
    - context menu: 有些瀏覽器會把長按當成右鍵語意，打開選單
    - pointercancel / 原生手勢接管: 瀏覽器判定這次觸控要交給系統做捲動、縮放、選字時，會中止你原本的 pointer 流程
- 平板長按不新增獨立 gesture
- 若長按發生在 table selection 區域，且該互動已被判定為 cell selection，則壓掉瀏覽器原生 callout 與文字 selection
- 若互動仍屬於單一 cell 的原生文字選取情境，則保留瀏覽器預設行為
- 長按是否能啟動選取，不作為第一版必要功能

copy 時機與選取完成狀態要不要分開。現在比較像「先選，再由使用者 copy」，但要不要支援「選完自動寫入 clipboard」？如果不要，建議明寫，避免之後有人期待像截圖工具那樣自動複製。

- 分開。反白，不一定會要 copy。

HTML 複製時，連結要保留樣式還是也保留可點擊 href。你已經說超連結格式保留，但工程上還要再決定複製出去的是純樣式文字，還是真的含 a 標籤。

- 純樣式文字時，就只 copy a.innerText 了

多欄 table 複製成純文字時的欄位順序要不要固定成「row-major」。你目前例子看起來是 row-major，但我會把它寫死，不要只靠範例暗示。

- 作成開放設定值好了，預設 row-major，也可以 column-major。

---

空 cell 的輸出規則要不要定義。table 複製時若某格沒內容，是輸出空 td、空字串、還是 nbsp；純文字版是否要保留空欄位置。這會影響貼到試算表或文件時欄位是否對齊。

- 也要有空的 td，這樣才能對齊

---

選取期間資料若局部重繪怎麼辦。你有定義換章換版本清除，但如果只是同一畫面某個 cell 因為 lazy render、註腳展開、字體切換而重繪，是否也要取消選取。

- lazy render 存在，是可能的。
  - 例如，取得註腳是非同步。
- 若是上述幾種，不取消選取。

---

捲動容器的定義要不要固定。自動滾動是滾整個 window，還是最近的 scroll container。這個如果不先定，實作時常常會和彈窗、內嵌捲動區打架。

- 自動滾動目標為「當前選取所在 table 的最近可捲動祖先容器」。
- 若沒有可捲動祖先容器，才退回捲動 window。
- 只捲動一個容器，不要同時捲多層，避免速度疊加與行為難預期。
- 若 table 位於彈窗內，優先捲彈窗自身的 scroll area，而不是背景頁面。
- 若容器已到頂或到底，才考慮把滾動交給外層，否則不要穿透。
- 以「pointer 所在 table 當下的 scroll ancestor」為準，不要在拖曳過程中頻繁重新改變目標容器。
- 自動滾動的熱區與速度計算，都只對這個固定目標容器生效。
