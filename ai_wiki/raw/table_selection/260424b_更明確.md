# 更明確定義

## 

「複製結果的判定規則」要更精確。現在寫了「跨 column 時複製 table、非跨 column 時複製純文字」，但還沒明確定義：

### 什麼叫「跨 column」：只要起訖點不同欄就算，還是只要選取範圍覆蓋多欄就算？

- 事件: mouse press -> move -> release
- (row, col)_start (row, col)_end
  - (row, col)_end mouse move / release 都會 update
  - (row, col)_start mouse press 時 update
- 起訖點不同欄，就是跨 column

### 只選到同一個 cell 的一小段文字時，算 text 還是 table？

- 算是 text

### 如果選取範圍橫跨多列但只在同一欄，是否永遠輸出純文字？

- 是。

### 選取範圍包含空白欄、合併欄位、或某些欄位為非經文內容時怎麼處理？

- 經文顯示，應該不會出現，「合併欄」，但可能出現「合併列」
- 例若以後其它的功能，例如 table 用在 「註釋顯示」。可能會有，但目前沒有。
- 若真的有合併欄，就視作跨欄，也就是要 copy 成 table。

## 

「選取視覺效果」和「實際複製內容」的關係。你有提到平板在同欄時要整格反白，但 copy 仍然是 text，而不是 table，這很好，但還需要定義：

### 反白的單位是 cell 邊界、文字範圍，還是整個 row/column？

- 平板操作時，是 cell 為單位，而非整個 column。(如 圖1)

![alt text](260424a/image-3.png)

### 視覺上反白和 clipboard 內容是否一定一致，還是可以分離？

- 不會分離。當某個 cell 是反白，表示這個 cell 中的文字全部被複製了

### 如果使用者從同欄拖曳到同欄，但實際選到跨列，是否仍然只顯示整格反白？

- 假設從 row 0 到 row 1，並且都是 col 0。
- 平板模式
  - 2 個 cell 整個會被反白
- 電腦模式
  - 在同欄，所以不會切成 cell 反白模式，就是文字反白。第幾個字元開始，到下一格第幾個字元

## 

第三個要釐清的是「輸入裝置與操作模型」。你現在同時提到滑鼠、平板，但還沒定義：

### 平板是指觸控事件，還是含觸控筆？

- 對瀏覽器來說，都是用 Pointer 相關的事件，沒有分。
- 所以 touch 都是同樣作法。

### 要不要支援桌機上的 Shift+click、拖曳選取、雙擊、長按？

- 雙擊、三擊
  - 在同個位置上，連點雙擊，本來就會自動選一個「字」要保留這個
  - 若連點三擊，會自動選一整個句話，也似乎是常見的預設行為。
- 平板
  - 不會有 shift 鍵 + click。
  - 平板沒有鍵盤

### start cell 和 end cell 的判定基準是 pointerdown/pointerup 的落點，還是以最近可命中的 cell 為準？

- 如果 up 是在 table 可命中範圍內，就都會一樣
- 當 down 在 table 中，但 up 在 document 或 header 這些不可命中的地方時
  - 在 mouse move 最後可命中範圍內那個
  - 即，在不可命中範圍時，都是不更新 end cell。

### 如果使用者在 cell 邊界外放開，算哪個 cell？

- 同 [上](#start-cell-和-end-cell-的判定基準是-pointerdownpointerup-的落點還是以最近可命中的-cell-為準)

##

第四個是「輸出格式」本身還不夠具體。既然一種情況要輸出 table，另一種要輸出 text，工程上需要明確知道：

### table 的格式是 HTML table、Markdown table，還是 TSV？

- 目前是
  - html table
- Markdown table
  - 未來可能會用到，但目前還不用
- TSV (Tab-Separated Values)
  - 應該不會用到

### 純文字的分隔符號是換行、tab、空白，還是依顯示格式而定？

- 思考ing
  - 純文字，是同譯本複製時
  - 因此，通常我是連起來，沒有分隔符號
  - 但是，也的確會有人喜歡「一節一行」
  - 所以，將會有一個開放設定參數「連接符號」選項有『無』『空白』『換行』
- 決策
  - 每個 table 會有一個參數
  - 並且這參數還提供 setter getter 可以改

### 是否保留原本的格式，例如經文編號、註腳、連結、粗體？

- 思考ing
  - 最直覺的就是看到什麼就是複製什麼最好。
    - 例如: 目前經文編號 是藍色，
    - 註腳是粉紅色
    - 有些譯本耶穌說的話是紅色
    - 交互參照超連結，通常是藍色 (但連結通常看不到)
  - 這樣說起來，其實不是純文字，而是有格式的文字
  - 然而，純文字的確是「不是有格式的」
    - 的確，有些時候，有些人會需要這樣的
    - 但是，有格式的文字是比較複雜要產生的，軟體貼上時，可選擇「純文字貼上」
- 決策
  - 純文字，應該是「有格式的文字」不是表格。
  - 若使用者需要純文字，可以用貼上的軟體中的功能「貼上純文字」或「合併格式」之類的，而不用再從 copy 過程處理

### 複製時要不要包含版本名、章節標題、引用範圍？

- 思考ing
  - 原則還是「看到什麼，複製什麼」
  - table 就是 cell 是什麼就是什麼
  - 非table，或許也是選到什麼是什麼
  - 但考慮到方便性，若每次都要手動輸入 (FHL和合本) 或 (#太2:3-4,7-9|,FHL和合本)這樣的字眼也挺累
- 決策
  - class 可以提供設定，預設是什麼都不加
  - 設定是一個文字，可以 hard code，但也可以變數，例如
    - `{{譯本名稱}},{{引用範圍}}`  或 `{{譯本名稱}},{{引用範圍_書卷全名}}`
    - 使用者自訂 `{{引用範圍}} 和合本`，可能使用者稱呼此譯本的習慣不同
    - 變數目前想到
      - 譯本名稱 ... 例如「FHL和合本」
      - 譯本名稱_代碼 ... 例如 「kjv」「unv」
      - 引用範圍 ... 例如「#太 2:3-4,7-9|」
      - 引用範圍_書卷全名 ... 例如 「#馬太福音 2:3-4,7-9|」
    - 繁體與簡體 Big5 and GB
      - 若是簡體，輸出則是簡體

##

第五個是「選取範圍的起點/終點排序與方向」。現在只描述 start/end cell，但實作上還要定義：

### 從左到右、右到左拖曳，結果是否相同？

- 視為一樣

### 從上到下、下到上拖曳時，輸出順序怎麼排列？

- 視為一樣，都是從上到下

### 當起點比終點更後面時，要自動正規化為閱讀順序嗎？

- 思考ing
  - 若表格用在交互參照的顯示時，原本經文的順序可能不是按順序，而是作者刻意的安排，應該保持
  - 例子，太1章
    - row 0 是第1節 row 1 是第2節 ...
    - 當 起點是 row 1 終點是 row 0 時，copy 起來與 兩個互換是一樣的。

##

還有幾個經常會被忽略但很重要的邊界：

### 如果選到表格外部元素，例如標題、註解、按鈕，是否要取消選取？

- 不會，當已經在 table 的 pointerdown 觸發時，在還沒 pointerup 前，若跑到外面，仍然運作 (甚至其它的動作要暫時失效，直到 pointup)
  - 這時想到，若是 非作用區 up，也要能取消，而非只有 table pointerup 才取消

### 如果使用者正在拖曳時頁面捲動，選取是否仍然有效？

- 當 pointdown 之後，此時同時 wheel 事件觸發，的確還要有效。
- 平板似乎無法作到，平板只能靠著，當 pointer 很接近底部時，自動的向下滾 ... 不知道是內建就會還是是開發出來的效果？

### 手機/平板上如果只是點一下，不拖曳，應該視為單 cell 選取還是純點擊？

- 純點擊
- 正如上面 [](#要不要支援桌機上的-shiftclick拖曳選取雙擊長按) 中提到的，雙連擊、三連擊時的設計

### 當資料更新、換版本、換章時，選取狀態是否要保留或清除？

- 是的，清除，因為畫面不同了。

### 目前是否需要支援跨多個 table 區塊的選取，還是限制在單一 table 內？

- 不跨 table。
- 的確，這個我當時沒想到，若畫面同時有 2 個 table 時。當在其中一個 pointerdown 時，在 up 之前，應該都是要在那一個
